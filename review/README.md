# 설화 제작 검수 작업대

2026-10-14 구현. 설화 입력부터 **설화별 자료·에셋·연결한 게임 공간을 대조하고 승인·반려·보류를 저장하는 로컬 개발 도구**다. 기존 HTML 목업과 별도이며, 전체 게임 자동 제작 에이전트의 완성본은 아니다.

## 실행

저장소 루트에서 실행한다.

```sh
npm run review
```

[검수 작업대 열기](http://127.0.0.1:5180/review/)

기존 5173·5174 게임 개발 서버와 분리된 5180 포트다. 이미 사용 중이면 자동으로 다른 포트로 옮기지 않고 실패한다. 서버는 이 컴퓨터에서만 접속할 수 있다. 페이지를 파일로 더블클릭하거나 정적 배포본으로 열면 저장 API가 동작하지 않는다.

## 처음 사용하는 순서

1. **설화와 기획:** MD·TXT(UTF-8, 원문 400,000바이트 이하)를 가져오거나 텍스트를 붙여넣는다. `나주 기존 자료로 채우기`는 사실 계약서·시놉시스·Scene 구성표와 기존 구현 공간을 연결한다. 이 입력은 원전 전문이 아니며, LLM 분석이나 자동 에셋 선정은 실행되지 않는다.
2. **검수 자료 저장·시작:** 원문, 시놉시스, 씬 계획, 연결 공간과 버전을 저장한다. 기존 기록은 개별 에셋 검수 방식을 유지한다. 기존 나주 기록을 구역 중심으로 검수하려면 공간 화면에서 `공간에서 확인 · 구역별 배치 판정`으로 바꾸고 저장한다.
3. **공간·에셋 검수:** `배치된 공간 둘러보기`로 실제 게임을 열고, 구역 이동 버튼·드래그 회전·오른쪽 드래그 이동·휠 확대를 사용한다. 물체를 짧게 클릭하면 이름·위치·식별 범위가 표시된다. 이름이 없거나 묶음만 식별되면 그대로 표시한다.
4. **문제 물체만 기록:** 선택한 물체에 검수자와 사유를 적고 `수정 요청 저장` 또는 `물체 반려`를 누른다. 이 기록은 실제 모델이나 배치를 바꾸지 않는다. 이번 회차의 미처리 요청은 외형·공간 승인을 막는다. 수정 작업 후 새 검수 회차를 열어 재확인한다.
5. **구역 사진 비교:** 실제 게임에서 4구역×대표 시점 2장을 순차 촬영한다. 각 구역의 사진을 확대하고 배치 적합·수정 필요·보류를 기록한다. 사진은 게임 버전·실행 구성·검수 회차에 묶인다. 재촬영 후에는 새 사진을 판정해야 한다. 4구역은 서사 5씬이 공유하는 물리 공간이며, 씬 진행 상태별 장면을 모두 검증한 것은 아니다.
6. **배치·에셋 판정:** 같은 공간 화면의 판정란에서 `배치·에셋 판정`을 선택한다. 구역 중심 방식은 구역별 사진·사람 판정과 추가 선택 항목의 검수를 확인한다. 라이브러리 목록 전체를 개별 검수할 필요는 없다. `개별 에셋 상세 도구`에서 체크한 항목은 추가 검수 대상이므로 GLB 로드 또는 팔레트 관찰 기록이 필요하다.
7. **동선·충돌 판정:** `직접 걸으며 동선·충돌 검수`를 실행하고 화면 클릭 → T → WASD·마우스로 탐색한다. Esc로 조작을 해제하고 같은 화면의 동선·충돌 판정으로 돌아온다. 둘러보기·사진용 진단 세션은 직접 이동 검수의 승인 근거를 대신하지 않는다.
8. **수정과 재검수:** 수정 내용을 저장하거나 `현재 자료로 재검수 회차 열기`를 누른다. 이전 원문·의견·판정·사진과 참조 해시는 이력에 남고 새 버전에서 다시 확인한다. 사진이나 물체 요청이 바뀌면 이미 기록한 외형·공간 판정도 재확인이 필요하다.
9. **내보내기:** 판정·관찰 이력에서 JSON을 내려받는다. 입력 원문, 이전 버전, 판정자, 선택 에셋·게임 버전, 구역 사진·판정·물체 요청이 함께 담긴다.

### 수량과 자동화 범위

- 기존 자료 목록 120개는 GLB 47개와 코드 팔레트 73개의 합이었다. 현재 배치 수나 설화에 자동 선정된 에셋 수가 아니다. 파일 상태에 따라 수량은 달라진다.
- 공개 교체 구성의 92개는 근경·원경 등을 포함한 활성 GLB 파일 수다. 화면의 물체 인스턴스 수와 다르며, 기존 자료 목록과도 별개다.
- **설화 → 에셋 자동 선정 → 새 공간 자동 배치는 아직 미연결**이다. 현재 기능은 이미 구현된 공간에서 실제 물체와 배치를 확인하는 검수 도구다.
- 실제 물체 선택 기록은 브라우저가 보고한 식별 정보다. 서버가 모델 이름이나 실물 동일성을 자동 인증한 것이 아니다. 묶음 단위 식별이면 위치와 함께 수정 요청을 남긴다.

## 다른 설화와 게임 공간 연결

- 설화 제목·관리 코드·본문은 자유롭게 입력한다. 새 검수는 특정 게임과 자동 연결되지 않는다.
- `연결할 구현 공간`에서 저장소에 등록된 게임을 고른다. 현재 등록된 공간은 나주 앙암바위다. 입력 본문만 바꾼다고 게임 공간이 새로 생성되지는 않는다.
- 수동 연결의 기본값은 `참고용 공간`이다. 참고용으로 나주를 실행해 볼 수 있지만, 다른 설화의 공간 승인이나 게임 팔레트 확인 근거로 사용하지 않는다.
- 실제로 해당 설화를 구현한 공간을 검수할 때만 `이 설화의 검수 대상 공간`을 선택한다. 나주 기존 자료 불러오기는 이 연결까지 채운다.
- 공간이 없어도 설화·시놉시스와 실제 GLB 파일에 대한 검수·판정을 진행할 수 있다. 공간·플레이 승인은 연결 전까지 차단된다.
- 연결 변경도 검수 자료의 새 버전이다. 이전 판정과 기록은 보존하고 다시 확인한다. 기존 나주 검수 기록은 나주 검수 대상 연결로 호환한다.
- 게임 종료·공간 밖 단계 이동·프로젝트 변경 전에는 대기 중인 관찰 전송이 끝난 응답을 확인하고 삽입 게임을 닫는다. 실패하면 게임을 유지하고 재시도하거나 미전송 기록 유실을 확인한 뒤 강제 종료할 수 있다. 재개할 때 새 세션을 시작한다.

### 나주 최신 화면과의 일치 (2026-10-14)

사용자가 확인한 기준 주소는 `http://localhost:5174/?aihub&src=sf&r=15`다. 검수 서버는 같은 소스와 같은 `public/`를 사용하며, 공개 에셋 교체 자료가 있을 때 이 실행 옵션을 `/naju01/`에 적용한다. `src=sf`는 공개 Sketchfab·KCISA·KHS 자료 폴더 `_sf_local`만 선택한다. AI허브 자료 폴더 `_aihub_local`로 넘어가지 않는다. `r=15`는 현재 게임 코드가 읽는 연출 설정이 아니다(`naju01/src/review/reviewPolicy.ts`의 TODO 참고).

- 화면 상단에 적용한 구성을 표시하고, 해당 구성과 교체 로더·자료의 해시를 검수 버전에 포함한다. `_sf_local`에서는 현재 목록이 참조하는 파일만 비교하며, 사용하지 않는 화풍 실험본의 생성은 검수 버전을 바꾸지 않는다. 기존 기본 조형으로 확인한 기록은 변경된 구성의 승인 근거로 재사용하지 않는다.
- 공개 교체 구성은 교체 모델 로딩과 후속 실제 프레임을 확인한 뒤 준비 상태로 바뀐다. 실패하면 오류를 표시한다. 이 확인은 형태·고증·라이선스의 사람 검수를 대신하지 않는다.
- 구역별 초점·안개는 기본 켬이다. 첫 구역 진입 카메라 연출은 **게임 화면을 클릭한 뒤 T로 탐색을 시작해야** 재생된다. 시작 전 정지 화면만으로 연출 동작을 판단하지 않는다.
- 현재 최적화는 거리 밖의 그리기 제한과 안개·원근 표현이다. 씬별 파일을 독립적으로 불러오고 해제하는 스트리밍 구현과는 구분한다.
- 실제 퍼즐 진행은 아직 연결되지 않았다. 일반 검수에서는 개발용 씬 강제 완료를 막으며, 이후 씬 연출을 개발 단축키로 살펴보는 작업은 진단 실행에 해당한다.
- 일반 검수는 Alt+클릭으로 교체 바위를 숨기는 편집을 막고, 개인 브라우저에 저장한 숨김 목록을 적용하지 않는다. 5174의 개인 설정을 5180으로 자동 복사하지 않는다.

입력 양식은 [설화입력_양식.md](설화입력_양식.md)를 참고한다. 양식을 강제하지 않으며 일반 텍스트도 보존한다.

## 기록과 판정의 의미

- 기록은 `.local/review/projects.json`에 저장된다. Git 제외, Vite 직접 파일 접근 차단, 원자적 파일 교체와 프로세스 내 직렬 쓰기를 사용한다. 서버를 껐다 켜도 남는다. 운영 DB·서버 인증을 대신하지 않는다. 같은 저장 경로를 쓰는 서버를 두 개 실행하지 않는다.
- 검수 자료 버전과 게임/참조 파일 해시를 확인한다. 오래된 창의 저장은 거절하고 초안을 보존한다. 게임 변경 뒤에는 이전 관측을 새 버전 승인에 쓰지 못한다.
- 검수 게임은 코드 기본 설정과 저장된 배치 파일을 사용한다. 기존 브라우저의 Leva 개인 설정을 덮어쓰지 않는다. 따라서 평소 개인 설정을 적용한 화면과 다를 수 있다.
- 첫 프레임 관측은 **모든 비동기 모델 로드 성공이나 공간 품질 보증이 아니다.** 화면에서 확인한 사람의 의견이 필요하다. 관측 FPS는 현재 기기의 값이며 최소 사양 통과 결과가 아니다.
- 게임 관찰은 개발 도구의 클라이언트 보고다. 로컬 개발자가 요청을 조작할 수 없는 보안 증명이나 운영용 감사 로그가 아니다. 판정 조건은 서버에서도 검증한다.
- AI허브 원본·가공본은 목록·자료에 넣지 않는다. 현재 승인도 에셋 이용 권한이나 외부 배포 허가를 대신하지 않는다.
- `[동작 테스트]`로 시작하는 프로젝트와 `Codex · 동작 확인` 판정은 UI/API 연결 검증용이다. 콘텐츠 최종 품질 승인이 아니다. 실제 검수는 새 검수 기록에서 시작한다.
