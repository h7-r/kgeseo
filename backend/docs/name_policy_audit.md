# 기존 이름 정책 점검 — `scripts/audit_existing_names.py`

- 작성: 11/27. 배경: 11/27 까지 운영 배포 묶음에 `shared/` 가 빠져 백엔드가 옛 내장 목록으로 이름을 판정했다(#219 로 정상화 ·
  15:35 KST 재시작 이후 fallback 경고 0건 — PM 확인). 그 기간에 들어온 회원 닉네임 · 게임 조사관명이 지금 공유 정책에 어긋나는지 **세기만** 한다.
- 이름 변경 · 삭제 · 회원 제한 · 데이터 정리는 하지 않는다. 운영 실행은 PM 담당이다.

## 무엇을 어떻게 보나

| 대상 | 판정(실제 함수) | 비고 |
|---|---|---|
| 회원 닉네임(`app_users.nickname`) | `nickname_policy.validate_nickname` — 가입 규칙 | 한글 · 영문 · 숫자 · `_`, 2~12자, 공백 · 자모 불가 |
| 조사관명(`user_characters.display_name`) | `lobby.public_investigator_name` — 로비 표시 규칙 | 자모 · 낱말 사이 한 칸 공백 허용, 언더바만으로 된 이름 불가 |

- 두 규칙은 일부러 다르다 — 점검이 통일하지 않는다.
- 제외: 탈퇴 회원(`deleted_at` 있음 — 닉네임이 비식별 값 `탈퇴#…`). 관리자 · 테스트 계정은 포함하되 따로 센다.
- 위반 이유(형식 · 길이 · 예약어 · 금칙어 · 제어 문자)는 한 이름에 여럿일 수 있다 — 이유별 숫자를 더해도 `Invalid` 가 되지 않는다.
- 「옛 내장 목록이면 허용, 지금은 위반」은 배포 누락과 관련 있을 수 있는 **후보**다. 실제로 그 기간에 가입했는지 · 그 때문에 통과했는지는
  이 점검으로 단정하지 않는다.
- 로비 영향: 조사관명이 지금 규칙에 어긋나면 로비 머리 위 이름이 **계정 닉네임으로 바뀌어 보인다**(입장은 막지 않는다). 계정 닉네임은 로비에서
  다시 검사하지 않으므로, 닉네임도 위반이면 그 닉네임이 그대로 보인다 — 그 수를 따로 센다.

## 안전 장치

- 시작 전에 공유 정책을 확인한다: 파일이 있음 · JSON 으로 읽힘 · 로더가 내장 목록을 돌려주지 않음 · **돌고 있는 판정기가 그 파일로 만든 것과 같음**.
  하나라도 아니면 DB 를 열지 않고 종료 코드 3(`Completed: FAIL`). 내장 목록 기준으로는 점검 완료를 내지 않는다.
- DB: 하나의 읽기 전용 트랜잭션(`SET TRANSACTION READ ONLY`)에서 SELECT 만, 회원 id 순으로 묶음(기본 500, 1~5000) 조회. 한 트랜잭션이라 모든 묶음이
  첫 조회 시점의 스냅숏을 본다(점검 중 가입 · 이름 변경은 들어가지 않는다). 끝나면 rollback.
- 출력은 건수뿐이다. 이름 · 이메일 · 회원 id · 해시 · 서버 경로는 내지 않는다. 개별 대상을 보는 옵션은 없다(필요하면 PM 승인 뒤 별도로).

## 운영 실행(PM, root)

```bash
systemd-run --wait --pipe --quiet \
  -p User=waegok \
  -p EnvironmentFile=/srv/waegok/.env \
  -p WorkingDirectory=/srv/waegok/current/backend \
  /srv/waegok/current/venv/bin/python -m scripts.audit_existing_names
echo "exit=$?"
```

- `.env` 를 셸에서 `source` 하지 않는다(`CORS_ORIGINS` JSON 이 깨질 수 있다) — 위처럼 systemd 의 `EnvironmentFile=` 로 읽는다.
- 읽기 전용 DB 계정이 있으면 그 계정으로 돌리는 것이 더 안전하다(앱 계정은 쓰기 권한이 있다 — 점검 자체는 읽기 전용 트랜잭션으로 쓰기를 막는다).

## 결과 읽기

| 종료 코드 | 뜻 |
|---|---|
| 0 | 점검 완료. 위반이 있어도 0 — `Violations found: yes/no` 로 본다 |
| 2 | 잘못된 옵션 |
| 3 | 공유 정책을 쓸 수 없음(파일 없음 · 깨짐 · 내장 목록으로 돌고 있음) — 조회하지 않았다. 배포 · 파일부터 확인 |
| 4 | DB 오류 — 집계 없음(오류 종류 이름만 출력) |

- `[Shared Policy] Source:` 줄의 sha256 앞 12자리 · 항목 수로 어떤 정책 파일로 판정했는지 남긴다.
- `unexplained` 는 0 이어야 한다(실제 함수의 판정과 이유 분류가 어긋난 수).
- `Withdrawn accounts that still have a character row` 는 0 이어야 한다(탈퇴가 캐릭터를 지운다).
- 숫자를 그대로 회신한다. 위반 건수의 후속 처리(안내 · 이름 변경 요청 등)는 PM 이 정한다.
