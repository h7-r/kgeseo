## 1. 복도는 어디에 있나

| 값 | 내용 |
|---|---|
| x 범위 | `CD.바깥x`(-31) ~ `MIN_X`(-20) → 폭 11 |
| z 범위 | `CD.z시작`(-60) ~ `CD.z끝`(25.5) → 길이 85.5 |
| 높이 | `CD.높이` = 8 |
| 방(로비)과의 연결 | `CD.문z`(+4) 자리에 뚫린 구멍 하나 |
| 플레이어 시작 자리 | `(-25.5, EYE, 0)` — App.jsx 13347 근처 |

**퍼즐이 있는 쪽은 z ≈ +15 (z비율 0.88) 한 군데뿐**이고, z = -60 ~ +5 의 약 65유닛은
측면문·등·잡동사니 말고는 비어 있다. 새 퍼즐은 **반대쪽 끝(z시작 = -60 쪽)** 에 놓는다.

## 3. 밝기 규칙 — **여기를 건드리면 복도 전체가 바뀐다**

```
복도밝기(z)  =  복도깊이밝기(z, 깊이규칙)      // App.jsx 10635, useMemo
깊이규칙     =  { 문z, 감쇠, 어둠, 최소밝기, 끝어둠, 끝기울기, z0 }   // 10620 근처
```

- 이 값은 **조명이 아니라 정점색**이다. 벽·바닥·배관 지오메트리의 `color` 속성에 구워
  넣고 `vertexColors` 로 재질 색에 곱한다. 그래서 **광원을 늘리지 않고도** 멀수록
  어두워진다(툰 셰이딩 단계도 안 깨진다).
- 소품(벽함·측면문·끝문·자물쇠)은 `밝기={복도밝기(zz) * 배수}` 를 prop 으로 받아
  `색밝기(색, 밝기)` 로 **색 자체를 어둡게** 만든다.
- ★ 새로 실제 광원을 얹을 때 주의: 정점색은 **이미 어둡게 구워져 있다.** 그 위에
  광원을 더하면 벽은 밝아지지만 「구워진 어둠」은 그대로라, 세기를 잘못 주면
  켜진 구간이 떠 보인다. 새 광원은 **기존 `복도등` 과 같은 세기 단위**로 맞춘다.

## 6. 되돌리기

새 퍼즐은 **새 파일에 넣고, App.jsx 는 최소한만** 건드린다. 그래서 되돌리기는
「블록 삭제」로 끝난다. 실제로 넣은 자리는 아래 목록에 계속 적는다.

### 6-1. 지우기만 하면 되는 블록 — 전부 `⟦작업등퍼즐⟧` 표시가 붙어 있다

```
grep -rn "⟦작업등퍼즐⟧" src/
```

| 파일 | 블록 | 지우는 법 |
|---|---|---|
| `src/App.jsx` | ① 수입 2줄 (`작업등퍼즐`·`손에든작업등`, `작업등들었나`·`use복도전원`) | 줄 삭제 |
| | ② Leva 폴더 `작업등 퍼즐` + `const 복도전원켜짐 = use복도전원();` | 블록 삭제 |
| | ③ 복도 안 `<작업등퍼즐 …/>` + 「차단기를 올리면 들어오는 등」 `복도등` map | 블록 삭제 |

### 6-2. 통째로 지워도 되는 새 파일
- `src/소품/작업등.js` (상태 상자 — `window.__작업등` QA 손잡이 포함)
- `src/소품/작업등.jsx` (램프·분기함·분필 자국·차단기함)

### 6-3. Leva 저장값
폴더 이름이 **「작업등 퍼즐」** 하나뿐이라, 지우고 나면 그 폴더는 그냥 안 뜬다.
기존 폴더(「비밀 복도」·「소화전 자물쇠」 등)에는 **키를 하나도 더하지 않았다.**

### 6-4. 그래도 이상하면
`docs/되돌리기/App.jsx.복도작업전` 과 지금 App.jsx 를 `diff` 해서 **내 블록만**
골라 되돌린다. 남의 작업이 같이 들어 있으므로 파일을 통째로 덮어쓰면 안 된다.

### 7-1. [E] 가 안 잡혔던 이유 (2026-09-28 수정)

`상호대상` 의 **`거리` 는 사람 자리에서 잰 진짜 3D 거리**다(상호작용.js 137줄).
처음에 넣은 값이 기하학적으로 불가능했다.

| 대상 | 처음 | 왜 안 됐나 | 고침 |
|---|---|---|---|
| 바닥 램프 | `거리 3` | 눈 4.15 · 램프 0.62 → **세로로만 3.5**. 어떻게 서도 안 닿는다 | `거리 6` (손닿는거리) |
| 분기함 A·B·C | `거리 3.2` | 함은 벽(x −20 / −31)에 붙고 사람은 폭 11 복도 한가운데를 걷는다 → 최소 5 | `거리 6` |
| 차단기함·레버 | `4.5 / 3.4` | 같은 이유로 빠듯했다 | `거리 6` |

동전 줍기가 **똑같은 함정**에 빠졌던 자리다(App.jsx 「동전줍기:캔」 주석).
새 상호대상을 만들 때는 **`거리` 를 손닿는거리(6)로 두고 시작**하는 편이 안전하다.

확인 방법(렌더·포인터 잠금 없이):
```js
const cam = window.__카메라.clone();
cam.position.set(-25.2, 4.15, -54.6);
cam.lookAt(-25.2, 0.62, -56.5);
cam.updateMatrixWorld(true);
window.__로비.겨냥갱신(cam, true);
window.__로비.겨냥.라벨();   // "[E] 작업등 집기" 가 나와야 한다
```

## 8. 3인칭 시점 손보기 (2026-09-28)

### 8-1. 무엇이 문제였나

`공용.jsx` 의 `삼인칭자리()` / `붐거리()` 에 두 가지 결함이 있었다.

1. **붐이 굵기 없는 선이었다.** 카메라 *중심*만 벽 앞에 세우니, 화면의
   **근평면 모서리**(near 0.25 · fov 60 · 16:9 → 중심에서 옆으로 0.257 유닛)는
   그대로 벽 안으로 들어갔다. 그게 「벽 통과해서 옆이 보이는」 증상의 정체다.
2. **`갇힘` 처리가 통째로 검사를 건너뛰었다.** 사람이 '못 있을 칸'에 서면
   `return 최대` 로 **붐을 검사 없이 끝까지 폈다.** 접속 직후뿐 아니라
   문턱·가구 곁·호스 줄이 팽팽할 때(`막힘` 이 true)도 이 갈래에 걸렸다.

### 8-2. 실측 (실제 콜라이더 `window.__막힘` 으로, 열린 자리 688 표본)

|---|---|---|
| 옛 규칙 | **1.45 %** (10/688) | 8.96 유닛 |
| 새 규칙 | **0 %** (0/688) | 6.37 유닛 |
