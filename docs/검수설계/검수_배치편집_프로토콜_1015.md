# 검수 배치 편집 — 메시지·기록 규약 (10/15)

> 미르 요구(10/15): ① 씬별 탭 — 그 씬 안에서만 탐색·검수 ② 선택한 에셋: 반려 / 반려+새로 생성 요청 / 수정 요청
> ③ 빈 자리 선택(좌표 기억) → 라이브러리에서 골라 배치 ④ 라이브러리: 카테고리별 썸네일+한글명, 한글 검색(의미 유사도)
> ⑤ 배치한 에셋은 회전·세밀 이동(높낮이 포함) 후 확정. 확정 = **변경안 기록**, 공간 승인 때 코드가 게임 데이터에 반영(미르 결정).
> 한글 검색 = 로컬 임베딩 모델 + 자모 유사도(미르 결정). 외부 유료 API 없음.

단위: 좌표는 모두 **미터**(게임 장면 단위 아님, `METERS_PER_UNIT` 로 변환). 회전 `rotationY` 는 **도**. `scale` 은 배율(1 = 라이브러리 기준 크기).

## 1. 부모(작업대) → 게임(iframe) — 진단 실행에서만
기존 봉투 그대로: `{ type, projectId, sessionId, requestId, ...추가 키 }` (reviewPolicy.readVisualRequest 와 같은 출처·세션 검사, 허용 키 목록 검사).

| type | 추가 키 | 게임 동작 | 답장 type |
|---|---|---|---|
| `kgeseo-review-scene` | `scene: 1..5` | 씬 상태 맞춤(그 씬 이전 차단물 치움·씬안개 단계), 그 씬의 구역 시작 시점으로 카메라 이동, **둘러보기 카메라를 그 씬 구역 경계(+여유 8 m) 안으로 묶음**. `scene: 0` = 묶음 해제(전체) | `kgeseo-review-scene-changed` `{ ok, scene, zoneIds, bounds:{x:[a,b],z:[a,b]}, error? }` |
| `kgeseo-review-place-start` | `asset: { id, url, nameKo, source, sha256? }`, `at: {x,y,z}`, `rotationY?`, `scale?` | GLB 로드(공용 `loaders/compressedGlb`), 땅 높이에 맞춰 at 에 세움, 이동(X·Y·Z)·회전(Y) 손잡이 표시. 진행 중 초안은 하나뿐 | `kgeseo-review-place-changed` `{ ok, draft, error? }` — 손잡이로 바꿀 때마다(최대 10회/초) 다시 보냄 |
| `kgeseo-review-place-adjust` | `position?: {x,y,z}`, `rotationY?`, `scale?`, `mode?: "move"|"rotate"` | 초안 값 직접 설정(패널 숫자 입력·화살표 미세 조정) | `kgeseo-review-place-changed` |
| `kgeseo-review-place-cancel` | — | 초안 제거 | `kgeseo-review-place-changed` `{ ok, draft: null }` |
| `kgeseo-review-place-commit` | — | 초안을 굳혀 「확정 대기」 미리보기로 바꿈(손잡이 제거) | `kgeseo-review-place-committed` `{ ok, draft }` |
| `kgeseo-review-proposals` | `proposals: Proposal[]` | 저장된 변경안을 미리보기 층으로 그림(반투명 아님, 테두리 강조). 목록 전체 교체 | (없음) |

`draft` = `{ assetId, url, nameKo, position:{x,y,z}, rotationY, scale, zoneId, groundY }`

## 2. 게임 → 부모
- 기존 `kgeseo-review-object-selected` 유지.
- 새 `kgeseo-review-point-selected` `{ point:{x,y,z}, zoneId, surface }` — 짧은 클릭이 **식별 가능한 물체가 아닌 땅·길·물**에 맞았을 때(또는 Alt+클릭이면 물체 위라도 맞은 표면 좌표). surface = 맞은 메시 이름 계열(ground/path/river/cliff …).
- 씬 탭으로 묶인 동안 경계 밖 클릭 지점은 `point-selected` 를 보내지 않는다.

## 3. 서버 기록 (`tools/review/server.mjs`, `.local/review/projects.json`)
- `objectIssues.disposition` ∈ `rejected | change_requested | regenerate` — `regenerate` = 반려 + 새로 생성 요청. 생성 공정 미연결이라 **요청 기록만** 남긴다(`regenerationRequests` 로도 조회 가능하게 export).
- `placements[]` 새 컬렉션: `{ id, at, reviewer, note, projectRevision, gameRevision, runtimeId, sceneNo, zoneId, asset:{ id, source, url, nameKo, sha256 }, position:{x,y,z}, rotationY, scale, status: "proposed"|"withdrawn"|"applied", appliedAt?, manifestEntryId? }`
  - `POST /__review/projects/:id/placements` · `POST /__review/projects/:id/placements/:pid/withdraw`
  - 이번 회차의 `proposed` 변경안이 있으면 **배치·에셋 판정(assets) 승인 조건에 「변경안 확인」 체크 필요**, 공간 승인 시 코드가 `public/_sf_local/manifest.json` 의 `놓기` 에 `{ files:[상대경로], 자리:[[x,z,y]], 회전:[deg], 크기, 출처:"review:<id>" }` 형식(기존 놓기 항목 형식을 읽어 맞춤)으로 덧붙이고 `status: applied`. 쓰기 전 manifest 백업(`.local/review/manifest_bak_<시각>.json`).
- `GET /__review/library` · `GET /__review/library/search?q=` — 라이브러리 색인(아래 4).

## 4. 라이브러리 색인 (`tools/review/library.mjs`)
항목 `{ id, nameKo, nameEn, category, categoryKo, source: "public"|"khs"|"palette"|"catalog", url|null, placeable, sha256?, tags[], thumbnail|null }`
- public = `_sf_local/manifest.json` 이 참조하는 GLB(경량본) / khs = `_sf_local/khs/*.glb` / palette = 게임 `placement/assetCatalog.ts` 의 코드 모형(배치 불가·참고) / catalog = 720 생성 준비 목록(`docs/에셋라이브러리/생성준비_v1/catalog.json`, 3D 미생성 → `placeable:false`, 「생성 요청」만 가능)
- 검색: 정확·부분 일치 > 자모 n-gram 유사도 > 임베딩 코사인(multilingual-e5-small, 로컬). 모델이 없으면 앞 두 가지만, 응답에 `semantic:false` 표시.

### 5-1. 카메라 미세 조정
| 방향 | type | 키 | 내용 |
|---|---|---|---|
| 부모→게임 | `kgeseo-review-camera` | `position?:{x,y,z}`(m) · `yaw?`(도, 0=+X, 반시계) · `pitch?`(도, -85~85) · `fov?`(도, 20~100) · `nudge?:{yaw?,pitch?,forward?,right?,up?,fov?}`(도·m 상대값) · `sensitivity?`(0.2~3, 끌기 회전 배율) · `moveSpeed?`(0.2~5, WASD·휠 배율) | 값 직접 지정 또는 상대 이동. 씬 경계 묶음은 그대로 적용 |
| 게임→부모 | `kgeseo-review-camera-changed` | `{ position, yaw, pitch, fov, sensitivity, moveSpeed }` | 카메라가 바뀔 때마다(최대 10회/초), requestId 는 요청 답이면 그 값, 아니면 null |
- 게임 안 키(둘러보기 중, HUD 입력칸 밖): **J/L 좌우 회전 1°(Shift 10°) · I/K 위아래 1°(Shift 10°) · `-`/`=` 화각 −/+1°(Shift 5°) · `0` 화각 기본값(게임 기본 FOV)**. 초안이 있을 때도 카메라 키는 그대로 카메라를 움직인다(초안 키와 겹치지 않음).

### 5-2. 에셋 추가 — 자리 먼저 / 에셋 먼저 둘 다
- `kgeseo-review-place-start` 의 `at` 을 **생략 가능**: 생략하면 게임이 화면 가운데에서 땅으로 쏜 지점(못 맞으면 카메라 앞 6 m 땅)에 세운다. 씬 경계 밖이면 경계 안 가장 가까운 점.
- 작업대에는 게임 위 도구줄에 늘 보이는 **「＋ 에셋 추가」** 버튼(라이브러리 서랍 열기). 자리를 골라 둔 상태면 그 자리, 아니면 화면 가운데.

### 5-3. 기존(선택한) 에셋의 위치·회전·크기 조정 = 「조정 변경안」
| 방향 | type | 키 |
|---|---|---|
| 부모→게임 | `kgeseo-review-adjust-start` | `target: { objectId }` (직전 `object-selected` 로 받은 objectId) |
- 게임: 그 인스턴스(또는 메시)를 복제해 초안으로 만들고 **원래 인스턴스는 숨긴다**. 이후 `place-adjust / place-cancel / place-commit / place-changed / place-committed` 를 **그대로 공유**하며, `draft.kind = "adjust"`, `draft.target = { objectId, groupId, instanceId, meshName, original:{position, rotationY, scale} }`. 취소하면 원래 인스턴스를 되살린다.
- 배치 초안(추가)은 `draft.kind = "add"`.
- `kgeseo-review-proposals` 의 항목에 `kind`·`target` 추가 — `adjust` 는 원래 인스턴스를 숨기고 옮긴 사본을 그린다. `withdrawn` 이면 원래대로.
- 서버 `placements[].kind ∈ add | adjust`, `adjust` 는 `target` 필수. 승인 반영: `add` → manifest 놓기(기존 그대로), `adjust` → 게임 손 배치 파일(`naju01/assets/edits.json`, 형식은 `naju01/src/placement/editFile.ts`)에 그 무리·번호의 이동/회전/크기 덮어쓰기. 공개 에셋 교체본(`AI허브:` 메시)이나 손 배치 경로가 없는 물체는 서버가 422 「이 물체는 위치 조정을 반영할 경로가 없습니다 — 수정 요청으로 남겨 주세요」.

## 6. 추가 (10/15 — AI 공간 배치 초안 가져오기 · 변경안 고치기)

### 6-1. 가져오기 — `POST /__review/projects/:id/placements/import`
- 본문 `{ origin: "ai-draft", trialId, reviewer, items: Item[], expectedRevision? }` — `expectedRevision` 은 생략 가능(바깥 생성 공정용), 주면 현재 회차와 같아야 한다(409).
- `Item = { assetId | url, source?, position:{x, z, y?}, rotationY?, scale?, sceneNo, zoneId?, reqId?, reason?, groundSnap? }`
  - `assetId` = 라이브러리 ID(`public:<_sf_local 상대경로>` · `khs:<파일>`). 색인에 있으면 이름·주소·출처를 거기서 가져오고, 없으면 ID 앞머리로 `/_sf_local/…` 주소를 만든다. `url` 만 줘도 된다.
  - **세션 없이** 받는다(일괄 가져오기). 대신 연결 게임이 검수 대상(`runtimeUse: target`)이고 현재 게임 버전이어야 한다.
  - 항목마다 일반 배치와 **같은 에셋 확인**: public/khs 출처 · `/_sf_local/` 아래 `.glb` · AI허브 금지 · 심볼릭 링크 금지 · sha256 은 실제 파일에서(주면 대조) · GLB 머리에서 높이(못 읽으면 거절).
  - **경계 확인**(게임 도면 `naju01/src/plan/sitePlan.ts` 의 ZONES·CORE 를 글자로 읽음 — 표를 고치면 따라 바뀜): `zoneId` 가 있으면 그 구역(+8 m) 안 · 그 구역이 `sceneNo` 씬에 속해야 함. 없으면 씬 경계(그 씬 구역 합 +8 m, 게임 씬 탭과 같은 계산) 안, 씬 0/없음 = CORE(0~80 × 0~50 m) 안. `zoneId` 가 없으면 서버가 가장 가까운 구역(8 m 안)을 적는다.
  - `y` 가 없으면 `groundSnap: true`, `position.y = null` — 게임이 그 자리 땅 높이에 세운다(6-3). 승인 반영 때 `묻힘m` 0.
  - 같은 시행·요구·자리·에셋의 제안이 이미 있으면 `placement_duplicate` 로 거절. 보존 한도(300건)를 넘는 항목은 `placement_limit` 로 거절.
- 한 번에 300개 초과면 413(`import_too_many`). 통과한 항목은 `placements[]` 에 `{ …§3 필드, sessionId: null, status: "proposed", origin: "ai-draft", trialId, reqId, reason, groundSnap }` 로 쌓인다.
- 답: `200 { project, accepted: [id…], rejected: [{ index, reqId, assetId, url, code, reason }] }`. 하나도 못 넣으면 `422 import_all_rejected` + 같은 `accepted/rejected`. 이력 `placements-imported`, 배치·에셋 이후 판정은 `placements_imported` 로 다시 확인.
- 조회: `GET /__review/projects/:id/placements?origin=ai-draft|human&trialId=…&current=1` → `{ placements, currentPlacementIds, revision, gameRevision }`. 예전 기록(origin 없음)은 `human` 으로 본다. 사람이 작업대에서 놓은 배치는 `origin: "human"`.
- 작업대: 「배치 변경안」 아래 접힌 칸 **「AI 배치 초안 가져오기 · 개발용」**(Vite 개발 서버에서만) — JSON 붙여넣기/파일 열기, 시행 ID, 거절 항목 목록.

### 6-2. 변경안 고치기(출처 무관)
| 방향 | type | 키 | 게임 동작 | 답장 |
|---|---|---|---|---|
| 부모→게임 | `kgeseo-review-proposal-edit-start` | `proposalId`(서버 placements[].id) | 마지막 `kgeseo-review-proposals` 목록에서 그 변경안을 찾아(제안 상태만) 같은 에셋·자리·회전·크기로 초안을 만들고 **그 미리보기를 숨긴다**. 씬 탭 경계 밖이면 거절 | `kgeseo-review-place-changed` `{ ok, draft, error? }` |
- 이후 `place-adjust / place-cancel / place-commit`, 키(G·R·화살표·[ ]·, .·Enter·Esc)·손잡이는 배치 초안과 **그대로 같다**. `draft.kind = "add"`, `draft.replaces = proposalId`(새 배치면 `null`).
- 취소(버튼·Esc, 또는 확정 뒤 저장 실패로 작업대가 보내는 `place-cancel`)하면 숨긴 미리보기를 되살린다. 확정 뒤에는 새 목록에서 그 변경안이 제안 상태가 아니게 될 때까지 숨겨 둔다.
- 작업대는 확정 때 `POST /placements` 에 `replaces: <옛 id>` 를 붙인다. 서버는 **같은 줄 세운 쓰기 한 번**에 새 변경안(`origin: "human"`, `replaces`, `editedFrom`, 옛 것의 `trialId·reqId·reason` 이어받음, `groundSnap: false`, 실제 y)을 넣고 옛 변경안을 `status: "withdrawn"`, `withdrawnBy`, `replacedBy: <새 id>` 로 바꾼다. 옛 것이 이미 제안 상태가 아니면 409, 없으면 404, 지난 회차면 409. 같은 요청 재전송은 새로 쌓지 않는다.
- 게임에서 변경안 미리보기를 클릭하면 기존처럼 `object-selected` 의 `objectId = "review-proposal:<id>"` — 작업대는 그때 물체 판정 칸 대신 「선택한 배치 변경안」 카드(위치·회전 조정 / 철회)를 보인다. `pending-N`(확정 대기)은 고칠 수 없다.

### 6-3. `kgeseo-review-proposals` 항목 추가 키
- `groundSnap?: boolean` — 참이면 `position` 은 `{x, z}`(y 없음·null 허용). 게임은 `terrain.groundAt(x,z).y` 에 세운다. 고치기 시작 때도 그 높이로 초안을 만들고, 확정하면 실제 y 가 저장된다.
- `origin? · trialId? · reqId? · replaces?` — 표시·추적용 문자열(200자 이하). 게임은 쓰지 않는다. 이 밖의 키는 여전히 거절.
