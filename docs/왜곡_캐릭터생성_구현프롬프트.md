## 복사해서 사용할 구현 프롬프트

당신은 React·Three.js 기반 웹 3D 게임의 UI/UX와 캐릭터 시스템을 구현하는 개발자다. 현재 저장소의 게임 「왜곡」에 **독립적으로 실행·확인할 수 있는 캐릭터 생성 화면 컴포넌트**를 구현하라. 현재 사용 중인 캐릭터·모션·렌더링을 재사용하고, 실제 3D 외형을 조절한 결과를 외부에 전달하는 화면을 만들어라. 회원가입, 서버 연결, 오프닝, 튜토리얼과 전체 화면 이동은 다른 프론트 담당자가 구현한다.

### 1. 가장 우선하는 요구와 작업 범위

전체 서비스에서 이 화면이 놓이는 위치는 다음과 같다. 앞뒤 흐름은 배경 설명이며 이번 구현 범위가 아니다.

메인·로그인 → 회원가입 → **[이번 범위: 외형 설정 → 캐릭터명 입력·확인 UI → 완료 데이터 전달]** → 외부 저장·오프닝 → 튜토리얼.

- 캐릭터 성별은 남성·여성 중 선택한다. 현재 모델의 `masculine`·`feminine` 값에 대응한다. 실제 계정 개인정보의 성별을 수집하는 항목과 혼동하지 않는다.
- 처음 생성 화면에 들어오면 기본 속옷·맨발 상태다. 이후 준비된 옷과 신발을 선택할 수 있다. 기본 속옷은 캐릭터의 기본 외형으로 유지한다.
- 의상은 현재 성별별 한 벌이다. 이후 의상 추가를 지원하도록 구성한다. 현재 없는 옷이나 얼굴 옵션을 만들어진 선택지처럼 표시하지 않는다.
- 키, 머리 크기, 손 크기, 발 크기는 반드시 실제 3D 모델에 반영한다. 어깨·골반·팔 길이·팔과 다리 두께 등 현재 지원하는 세부 조절도 함께 제공한다.
- 외형을 정한 다음 이름을 입력한다. 중복확인 버튼과 결과·오류 상태는 화면 내부에 구현하고, 실제 검사는 외부에서 전달받은 함수로 요청한다. 완료 시 선택한 외형과 이름을 외부 콜백에 전달한다.
- 기존 문서의 ‘슬롯별 4개 옵션’과 충돌하면 이번 요구를 우선한다. 기존 모델 공급자 변경이나 신규 캐릭터 대량 제작을 이번 화면 작업의 선행 조건으로 삼지 않는다.
- 구현 범위는 **화면, 3D 미리보기, 편집 상태, 이름 입력·확인 UI, 외부 연동용 props/콜백, 독립 미리보기**다.
- **회원가입·로그인 수정, 전역 라우팅, 인증, 실제 API 호출·백엔드·DB, 계정별 영구 저장, 오프닝 플레이어, 튜토리얼, 재로그인·온보딩 분기**는 다른 담당자의 범위다. 이번에는 해당 파일·기능을 구현하거나 연결하지 않는다.

### 2. 구현 전에 확인할 현재 프로젝트

먼저 공통 스타일, 외형 설정, 캐릭터 렌더러와 에셋을 읽고 화면에서 재사용할 방법을 결정하라. 아래 경로는 저장소 루트 기준이다.

| 확인 대상 | 파일·디렉터리 | 확인 이유 |
|---|---|---|
| 기존 디자인 | `시작페이지/src/구간/인증폼.jsx`, `시작페이지/src/공통.js` | 색상·글꼴·버튼 스타일 참고, 인증 기능 수정 제외 |
| 외형 선택지·기본값 | `naju01/src/메시외형옵션.js` | 이미 있는 설정·보정·선택지 재사용 |
| 캐릭터 렌더러 | `naju01/src/치비게임아바타.jsx`, `naju01/src/모션보정.js` | 기존 Meshy 모델·모프·뼈·모션 보정 재사용 |
| 실제 모델 | `public/models/meshy-*.glb`, `public/models/shoes-*.glb` | 지원 형태·착장별 호환성 확인 |
| 기획 참고 | `프로젝트파일/PRD/왜곡_PRD_v2_1_1.xlsx` | 화면 용어·이름 규칙 참고, 원본 수정 제외 |

현재 React·React Three Fiber·Drei·Three.js·Vite를 활용한다. 라이브러리 버전은 실제 package.json을 따른다. 생성 화면 내부 단계는 컴포넌트 상태로 관리하고 특정 라우터·인증 전역 상태에 종속시키지 않는다.

재사용과 수정 범위:

- 기존 외형 설정과 렌더러를 가져와 전용 프리뷰 어댑터로 사용한다. 생성 화면에 필요한 최소 보정만 적용하고, 전체 게임의 캐릭터 파이프라인을 재설계하지 않는다.
- 공용 렌더러의 수정이 꼭 필요하면 기존 기본 동작을 유지하는 선택적 프리뷰 설정 등 최소 변경으로 한정한다. 게임의 이동·판정·씬 전환은 수정하지 않는다.
- 시작페이지와 본편 앱의 통합, 기존 가입폼의 닉네임 이동, `src/_보류/앱셸.jsx` 활성화는 다른 프론트 담당자에게 맡긴다.
- 현재 `src/서버/api.js`는 모의 서버다. 생성 화면은 이 모듈에 직접 결합하지 않고 외부에서 전달받은 이름 확인·완료 콜백만 사용한다.
- 실제 API가 없어도 독립 개발용 미리보기에서 가짜 응답을 주입하여 화면을 확인할 수 있게 한다. 가짜 응답은 미리보기 진입점에만 두고 실제 컴포넌트에 ‘무조건 사용 가능’ 응답을 내장하지 않는다.

### 3. 화면 구성과 시각적 방향

기존 메인·로그인 화면의 로고, 짙은 배경, 파란 강조색, 한글 글꼴을 이어받는다. 캐릭터는 현재 게임의 스타일라이즈드 3D 외형을 유지한다. ‘왜곡을 조사할 조사관을 등록한다’는 분위기를 가볍게 담되, 외형을 관찰하기 쉽게 만든다.

기본 제목은 **캐릭터 생성**, 보조 문구는 **왜곡을 조사할 당신의 모습을 만들어 주세요.** 로 한다. 실제 기존 용어가 확정돼 있다면 일관되게 맞춘다.

데스크톱 화면 구성:

```text
┌─────────────────────────────────────────────────────────────┐
│ 왜곡 로고       캐릭터 생성       ① 외형 설정  ② 이름·최종 확인 │
├─────────┬────────────────────────────┬──────────────────────┤
│ 기본    │                            │ 선택한 항목의 옵션    │
│ 체형    │     큰 3D 캐릭터 미리보기   │                      │
│ 헤어    │                            │ 성별 / 슬라이더 /     │
│ 의상    │     바닥·부드러운 그림자    │ 실제 의상 썸네일      │
│         │                            │                      │
│         │ 전신 / 머리 / 손 / 발       │ 현재 항목 초기화      │
│         │ 회전 / 확대 / 보기 초기화   │                      │
├─────────┴────────────────────────────┴──────────────────────┤
│ 되돌리기  다시 실행  외형 초기화                이름 입력으로 → │
└─────────────────────────────────────────────────────────────┘
```

- 왼쪽은 좁은 카테고리 목록, 중앙은 가장 큰 3D 미리보기, 오른쪽은 조절 패널로 구성한다. 1920px 기준 중앙에 화면 폭의 약 55~65%를 배정하되 실제 가독성에 맞춰 조정한다.
- 오른쪽 패널만 내부 스크롤되게 하고 하단 진행 버튼은 항상 찾을 수 있게 한다. 선택 항목은 테두리·체크·텍스트로 함께 구분한다.
- 체형 조절은 기본값만으로도 넘어갈 수 있다. 모든 슬라이더를 조작하도록 요구하지 않는다.
- 넓은 화면을 통째로 축소해서 글자를 작게 만들지 않는다. 좁은 화면에서는 카테고리를 가로 탭, 조절 패널을 아래쪽 영역으로 재배치한다.
- 1280×720에서도 캐릭터, 현재 조절 항목, 진행 버튼이 겹치지 않아야 한다. 기존 지원 기기 범위에 맞춰 작은 화면도 확인한다.
- Leva, 뼈 이름, 모델 경로, 모션 공급자, 디버그 수치 등 개발 도구는 이용자 화면에 노출하지 않는다.
- 배경의 강한 번쩍임, 지속적인 화면 흔들림, 큰 블룸으로 얼굴·피부색·옷의 실루엣을 가리지 않는다.

### 4. 성별, 속옷, 헤어, 의상

**성별 변경**

- 남성·여성 선택 버튼과 현재 선택 상태를 명확히 제공한다.
- 성별마다 외형 초안을 별도로 보관한다. 남성→여성→남성으로 바꾸면 이전 남성 설정이 복원된다.
- 다른 성별에 사용할 수 없는 의상·헤어는 호환되는 기본값으로 대체하고 짧게 안내한다. 이름 입력 초안은 유지한다.
- 성별 선택 결과는 외형 데이터로 전달한다. 게임 능력치 설정을 생성 화면에서 추가하지 않는다.

**첫 진입 상태**

- 신규 초안에만 `top=-1`, `bottom=-1`, `shoes=-1`에 해당하는 기본 속옷·맨발 상태를 적용한다. 헤어는 해당 성별의 실제 기본 헤어를 사용한다.
- 이미 저장한 초안이나 생성 완료 캐릭터를 다시 불러올 때 속옷 상태로 덮어쓰지 않는다.
- ‘속옷으로 체형 보기’ 미리보기 토글을 제공할 경우, 선택한 실제 착장과 일시적인 미리보기 상태를 분리한다. 토글을 끄거나 이름 확인 단계로 가면 선택해 둔 옷으로 돌아온다.
- 의상을 입지 않았다는 이유로 임의의 완료 불가 조건을 추가하지 않는다. 기본 속옷은 항상 유지한다.

**현재 선택지와 이후 확장**

- 현재 파일에서 확인되는 의상은 티셔츠·반바지·흰 운동화 각 1종이다. 각 부위의 미착용 선택과 실제 1종만 표시한다. 헤어도 실제 선택지 목록에서 읽는다.
- 카드에 실제 모델을 반영한 썸네일, 이름, 선택 표시를 제공한다. 준비되지 않은 아이템으로 빈칸을 억지로 채우지 않는다.
- `catalog` 데이터에 안정적인 아이템 ID, 표시명, 슬롯, 호환 성별/몸체/리그, 썸네일, 렌더링 참조, 지원 색상·체형 범위 등을 둔다. 앞으로 항목을 추가하면 UI가 자동으로 늘어나게 한다.
- 저장 데이터는 배열 순번 대신 안정적인 ID를 사용한다. 현재 `0`, `-1` 같은 렌더러 값과의 대응은 어댑터에서 처리한다.
- 현재 상·하의는 각각 독립된 옷 메시를 겹치는 구조가 아니라 `base/top/bottom/both`의 **옷을 입은 전신 GLB 교체 방식**이다. 현재 방식과 옷 조합을 정확히 연결한다. 신발은 착장·성별별 별도 파일을 사용한다.
- 앞으로 전신 착장이나 진짜 분리형 의상이 추가될 수 있도록 카탈로그와 렌더링 방식을 분리한다. UI 확장이 쉬워져도 새 의상의 모델·리그·체형 대응 제작까지 자동으로 끝나는 것은 아니다. 지원하지 않는 조합은 카탈로그에서 제한한다.
- 피부·헤어·의상 색상은 현재 재질이 실제로 분리해서 지원하는 범위에서 검증한 팔레트로 제공한다. 현재 색은 원본 텍스처에 곱해지는 방식이며 흰색이 원본 유지다. 이를 실제 피부의 흰색 선택과 혼동하지 않는다. 상의·하의 개별 색을 지원하지 않으면 독립 조절처럼 표시하지 않는다.

### 5. 체형 조절 — 실제 3D에 적용

필수 조절 항목은 **키, 머리 크기, 손 크기, 발 크기**다. 추가로 현재 모델이 지원하는 어깨 너비, 골반 너비, 팔 길이, 팔 두께, 다리 두께, 체격을 제공한다.

각 항목에는 한글 라벨, 슬라이더, 현재 값, 미세 조절 버튼, 개별 초기화를 둔다. 모델의 실제 치수가 검증되지 않았다면 cm를 붙이지 말고 ‘기본 대비 비율’로 표시한다. 슬라이더가 0~100 표시라면 실제 모델 값과의 대응 및 기본값 위치를 일관되게 정의한다.

현재 코드에 있는 범위는 다음과 같다. **운영 화면에 그대로 확정할 안전 범위가 아니라 검증을 시작할 기존 값**이다.

| 항목 | 현재 키 | 현재 범위 | 현재 기본값 |
|---|---|---|---|
| 키 | heightScale | 0.70~1.30 | 1.00 |
| 머리 크기 | headScale | 0.80~1.30 | 1.00 |
| 어깨 너비 | shoulderWidth | 0.75~1.25 | 1.20 |
| 골반 너비 | hipWidth | 0.70~1.30 | 1.00 |
| 팔 길이 | armLength | 0.70~1.15 | 0.88 |
| 팔 두께 | armThickness | 0.70~1.30 | 1.00 |
| 다리 두께 | legThickness | 0.70~1.30 | 1.00 |
| 손 크기 | handScale | 0.70~1.30 | 1.00 |
| 발 크기 | footScale | 0.70~1.30 | 1.00 |
| 체격 관련 | heavy / skinny / buff | 각각 0~1 | 각각 0 |

- 조절값은 기존 모프 타깃 또는 검증한 뼈 변형에 연결한다. CSS로 캔버스를 늘리거나 카메라 줌을 바꿔 신체가 변한 것처럼 처리하지 않는다.
- 현재 키는 캐릭터 전체의 균일 배율이다. 키만 수직으로 늘려 팔다리를 찌그러뜨리지 않는다. 머리·손·발은 각각의 상대 크기를 조절한다.
- 현재 머리는 head 본 배율, 어깨·팔 길이는 본 위치 보정, 손·발·두께 등은 모프로 처리한다. 애니메이션 적용 순서와 현재 접지 보정을 유지한다.
- 초기화는 보정된 실제 기본값으로 돌아가야 한다. 어깨 1.20, 팔 길이 0.88을 임의로 1.00으로 바꾸지 않는다.
- `heavy`와 `skinny`를 동시에 최대로 겹치지 않도록 ‘마른 ↔ 기본 ↔ 두꺼운 체형’ 하나로 매핑하는 등 의미가 분명한 조작을 제공한다. 양수·음수를 각각 기존 모프에 대응하고 반대 모프는 0으로 둔다. `buff`는 실제 변화가 라벨에 맞는지 확인한 뒤 제공한다.
- ‘주먹 쥐기’, 리타게팅, 팔 벌림 보정 같은 모션·개발 설정을 영구 외형 항목으로 노출하지 않는다. 손 크기를 조절할 때는 손을 보기 쉬운 자세를 사용한다.
- 눈·코·입, 손가락 길이 등 현재 지원하지 않는 형태 조절을 작동하는 것처럼 만들지 않는다. 이번 필수 항목에 지원 누락이 있으면 에셋·렌더러 보완 사항으로 해결하거나 명확하게 보고한다.
- 남녀와 모든 현재 착장에서 기본·최소·최대 및 극단 조합을 확인한다. 옷 뚫림, 팔·몸 관통, 머리·헤어 분리, 발·신발 크기 불일치가 보이면 해당 변형을 보완하거나 공통 안전 범위를 정한다.
- 옷을 바꿨을 때 사용자의 체형값을 조용히 초기화하지 않는다. 현재 모든 옷에 적용 가능한 공통 범위를 우선하고, 향후 의상별 제한이 필요한 경우 명시적으로 안내한다.
- **현재 신발 GLB 8개에는 모프 타깃이 없다.** 몸체의 발 모프만 변하고 신발 외형은 따라가지 않는 상태다. 발 크기 조절이 맨발·신발 착용 상태 모두에서 보이도록 신발 변형 또는 적절한 별도 보정을 구현한다. 기존 발 축소·관통 억제와 접지를 함께 유지한다. 신발을 신으면 발 크기가 바뀌지 않는 상태를 완료로 인정하지 않는다.
- 출력은 외형 조절값으로 한정한다. 생성 화면 구현 중 퍼즐 상호작용 거리·충돌체·이동 속도 등 게임 로직을 변경하지 않는다.

### 6. 3D 미리보기와 편집 조작

- 캐릭터는 전신과 발끝이 보이는 정면 또는 약한 3/4 시점으로 시작한다. 안정적인 조명과 바닥 그림자로 체형을 읽기 쉽게 한다.
- 캐릭터 영역 드래그로 좌우 360도 회전, 휠/핀치로 확대·축소를 제공한다. 위아래 회전과 줌에는 관찰에 적합한 제한을 두고 카메라가 모델 속이나 바닥 아래로 들어가지 않게 한다.
- ‘전신 / 머리 / 손 / 발’ 보기, 좌우 회전 버튼, 확대·축소 버튼, 보기 초기화를 제공한다. 손은 좌우 손을 비교할 수 있는 구도로 잡는다.
- 카테고리 변경 시 부드럽게 해당 부위로 이동하되, 슬라이더를 움직일 때마다 카메라를 다시 움직이지 않는다. 이용자가 직접 잡은 시점을 존중한다.
- 키가 바뀌어도 발은 바닥에 붙고 머리는 화면 밖으로 잘리지 않아야 한다. 지나친 자동 줌으로 키 변화가 전혀 보이지 않는 문제도 피한다.
- 편집 중에는 팔을 가볍게 벌린 편안한 자세 등 신체를 가리지 않는 자세를 사용한다. 현재 팔짱·허리에 손을 얹는 대기 모션은 손·허리 편집을 가릴 수 있으므로 편집용 자세와 게임 대기를 구분한다.
- ‘기본 자세 / 대기 / 걷기 확인’을 제공할 때는 실제 사용 가능한 모션만 사용한다. 미리보기 자세는 영구 외형 데이터와 분리한다.
- 패널·이름 입력·슬라이더를 조작할 때 카메라 회전, WASD 이동, 게임 단축키가 동시에 실행되지 않게 한다. 포인터 잠금은 사용하지 않는다.
- 한 단계 되돌리기/다시 실행, 항목 초기화, 외형 전체 초기화를 제공한다. 슬라이더 한 번 드래그를 되돌리기 한 단계로 묶는다. 전체 초기화는 확인하거나 즉시 되돌릴 수 있게 한다.
- 성별·의상 교체는 새 모델이 준비된 후 전환한다. 로딩 중 마지막 정상 모델과 진행 표시를 유지하고, 실패하면 재시도를 제공한다. 이전 비동기 요청이 늦게 도착해 최신 선택을 덮어쓰지 못하게 한다.
- 프리뷰는 기존 렌더러와 외형 키를 재사용하고, 결과 데이터의 대응 관계를 문서화해 다른 프론트가 적용할 수 있게 한다. 실제 게임 화면에 외형을 적용하는 작업은 다른 담당자의 몫이다. 캐릭터 인스턴스의 골격은 안전하게 복제하고, 변경할 재질·형상은 공유 자원을 오염시키지 않게 처리한다.
- 새 의상·신발의 본 대응을 검사한다. 대응 본이 없을 때 임의로 0번 본에 붙이지 말고 호환되지 않는 에셋으로 처리해 오류를 드러낸다.
- 현재 프리뷰에 필요한 에셋부터 로드한다. DPR·그림자 품질을 조정할 수 있게 하고, 고해상도 전신 GLB를 무조건 전부 동시에 읽지 않는다. 탭 비활성 시 불필요한 렌더링을 줄인다.
- WebGL 초기화 실패·모델 로딩 실패는 명확한 오류 화면과 재시도로 처리한다. 캐릭터가 안 보이는 상태를 정상 생성 완료로 통과시키지 않는다.

### 7. 외형 확정 후 캐릭터명 입력 — 화면 내부 처리

‘이름 입력으로’ 버튼을 누르면 같은 캐릭터를 보여 주면서 오른쪽 패널을 이름·최종 확인으로 바꾼다. 선택한 성별·외형·착장과 이름을 함께 확인할 수 있게 한다. ‘외형 수정’으로 돌아가도 모두 유지한다.

- 사용자 라벨은 **캐릭터명**, 보조 문구는 **게임에서 사용할 조사관의 이름을 입력해 주세요.** 로 한다.
- 기본 길이 안내는 현재 PRD의 2~12자를 참고한다. 길이·허용 문자 등의 정책은 설정으로 전달받을 수 있게 하고 다른 프론트가 공통 규칙을 연결할 수 있게 한다. 이번 화면에서 서버 정책을 새로 확정하지 않는다.
- 한글 IME 조합 중에는 잘못된 오류·자동 제출을 발생시키지 않는다. 이름 정규화·글자 수 계산 방식은 한곳에 모아 교체할 수 있게 한다.
- 입력 옆에 ‘중복확인’, 아래에 현재 글자 수와 결과 메시지를 둔다. 상태는 입력 전 / 형식 오류 / 확인 중 / 사용 가능 / 이미 사용 중 / 허용되지 않는 이름 / 확인 실패로 구분한다.
- ‘중복확인’을 누르면 외부에서 주입받은 `checkName` 함수를 호출하고 결과를 표시한다. 실제 API 호출이나 금칙어 서버를 이 화면에 구현하지 않는다.
- 입력값이 바뀌면 이전 ‘사용 가능’ 결과를 무효화한다. 검사한 이름과 현재 정규화된 이름이 일치할 때만 확인 완료로 취급한다. 요청 번호나 취소 신호로 오래된 응답이 현재 결과를 덮지 못하게 한다.
- 이름이 확인되기 전에는 ‘캐릭터 생성 완료’를 비활성화하고 이유를 설명한다. 외부 검사 함수가 연결되지 않은 경우 ‘이름 확인 기능이 연결되지 않았습니다’로 표시하고 임의로 통과시키지 않는다. 독립 미리보기에서는 가짜 검사 함수를 명시적으로 주입한다.
- 완료 버튼을 누르면 외형·이름 데이터를 `onComplete`에 전달하고 처리 중 상태를 표시한다. 중복 클릭을 막고 외부 함수의 성공·실패 결과를 기다린다.
- 외부 함수가 이름 충돌을 돌려주면 외형을 유지하고 이름 확인 결과를 무효화해 재입력·재확인을 안내한다. 일반 실패는 초안을 유지하고 재시도할 수 있게 한다.
- 성공 결과를 받아도 이 컴포넌트가 오프닝 등으로 직접 이동하지 않는다. 부모가 화면을 교체할 때까지 중복 완료를 막고 완료 상태를 유지한다. 저장·다음 화면 이동은 외부 담당자가 처리한다.

권장 메시지:

- 사용 가능: ‘사용할 수 있는 이름입니다.’
- 중복: ‘이미 사용 중인 이름입니다. 다른 이름을 입력해 주세요.’
- 미확인: ‘이름 중복확인을 진행해 주세요.’
- 확인 실패: ‘이름을 확인하지 못했습니다. 다시 시도해 주세요.’
- 완료 요청 중: ‘처리 중입니다…’

### 8. 다른 프론트가 연결할 컴포넌트 계약

컴포넌트는 필요한 초기값과 함수를 외부에서 받고, 완성된 결과를 외부로 전달한다. 아래 이름은 제안이며 저장소 규칙에 맞춰 바꿀 수 있다. 의미와 입출력 형식은 인수인계 문서에 명확히 남긴다.

| 입력·콜백 | 역할 | 생성 화면의 책임 |
|---|---|---|
| `initialValue?` | 초기 외형·이름 또는 복구할 초안 | 유효한 값을 읽어 초기 표시. 없으면 신규 기본값 사용 |
| `catalog?` | 사용 가능한 헤어·의상·색상 목록 | 호환 선택지를 표시. 없으면 현재 실제 에셋 목록 사용 |
| `nameRules?` | 공통 이름 형식 규칙 | 입력 안내·로컬 형식 검사에 사용 |
| `checkName(name, { signal })` | 외부 이름 확인 함수 | 확인 중·가능·중복·오류 결과를 UI에 반영 |
| `onDraftChange?(draft)` | 현재 초안을 부모에 전달 | 외형·이름 변경 결과 전달. 실제 임시 저장은 부모 책임 |
| `onComplete(payload)` | 완료 결과를 전달하는 비동기 함수 | 데이터 전달·진행 표시·재시도 UI 처리 |
| `onCancel?()` | 화면 닫기·뒤로 요청 | 콜백 호출. 목적지 결정은 부모 책임 |

**확인·완료 함수의 결과 형식도 문서화한다.** 예를 들면:

```text
checkName 결과
  { status: 'available' }
  { status: 'taken' | 'invalid', message?: string }
  통신 등 예상하지 못한 실패: Promise 거절 → 화면에서 확인 실패 표시

onComplete 결과
  { ok: true }
  { ok: false, reason: 'name_taken' | 'invalid' | 'failed', message?: string }
  예상하지 못한 실패: Promise 거절 → 화면에서 재시도 안내
```

`checkName`의 사용 가능 결과는 이름 예약을 뜻하지 않는다. 외부에서 최종 제출 실패를 돌려줄 수 있다는 전제로 화면을 만든다. DB·서버의 실제 중복 판정은 외부 담당 영역이다.

완료 시 전달할 데이터의 최소 형식:

```text
CharacterCreationPayload
  schemaVersion
  displayName
  appearance
    catalogVersion, bodyAssetVersion
    gender
    bodyParameters: 키·머리·어깨·골반·팔·손·발·체격
    hairId
    equipmentIds: 상의·하의·신발 ID 또는 미착용 값
    supportedColorValues
```

- 값은 직렬화 가능한 순수 데이터로 전달한다. Three.js 객체, 카메라, 모션 재생 상태, 함수, 모델 바이너리는 넣지 않는다.
- 현재 렌더러의 외형 키와 출력 데이터 사이 매핑을 함께 제공한다. 다른 프론트가 어떤 값을 캐릭터에 적용해야 하는지 알 수 있어야 한다.
- `initialValue`는 최초 마운트에 적용하고 부모의 일반 재렌더마다 초안을 초기화하지 않는다. 다른 캐릭터로 바꾸려면 부모가 컴포넌트 key를 바꿔 다시 마운트하는 등 재초기화 방법을 문서화한다.
- 외부 입력 객체를 직접 수정하지 않는다. 잘못된 수치·없어진 아이템 ID는 정의된 기본값·유효 범위로 보정하고 필요한 안내를 표시한다.
- 외형·이름 단계 사이 이동, 성별별 초안, 되돌리기 이력은 화면 내부 상태다. 페이지를 벗어난 뒤의 저장·복구는 부모가 `onDraftChange`와 `initialValue`로 맡는다.
- 계정 ID, 인증 토큰, 서버 프로필, 오프닝 시청 여부, 튜토리얼 진행 상태는 이 컴포넌트가 관리하지 않는다. 전역 localStorage에 계정 데이터를 저장하지 않는다.
- 미연결 콜백을 실제 성공으로 취급하지 않는다. 부모가 작업 중이어도 별도 개발 미리보기에서 가짜 함수를 주입해 모든 UI 상태를 확인할 수 있게 한다.

### 9. 독립 미리보기와 전달물

다른 프론트의 회원가입·오프닝 작업이 끝나지 않아도 생성 화면 자체를 열어 볼 수 있어야 한다.

- 별도 개발용 미리보기 진입점 또는 저장소의 기존 컴포넌트 미리보기 방식을 사용한다. 이를 위해 실제 가입 이후 라우트나 본편 진입 흐름을 변경하지 않는다.
- 미리보기에서 남녀 모델·옷·체형을 직접 조작할 수 있게 한다.
- 이름 확인의 사용 가능·중복·확인 실패·느린 응답과 완료의 성공·실패·이름 충돌을 가짜 함수로 재현할 수 있게 한다. 개발 미리보기임을 표시하고 이런 제어 도구를 실제 생성 화면 UI에 섞지 않는다.
- 완료 시 반환되는 데이터는 개발용 결과 패널 등에서 확인하게 한다. 성공한 척 오프닝 페이지나 튜토리얼로 보내지 않는다.
- 전달물은 **생성 화면 컴포넌트, 스타일, 프리뷰용 렌더러 어댑터, 외형 데이터 정의, 개발 미리보기, props·콜백 사용 예시**다.
- 사용 예시는 부모가 초기값을 전달하고 이름 확인·완료·취소 함수를 주입하는 정도면 충분하다. 실제 회원가입·저장 API·영상 플레이어·튜토리얼 코드를 함께 만들지 않는다.
- 신발의 발 크기 대응 등 현재 화면에서 필요한 보정은 최소 범위로 구현한다. 기존 에셋 전체 재제작이나 본편 시스템 개편으로 확장하지 않는다. 해결되지 않은 시각적 제약은 인수인계에 남긴다.

### 10. 접근성과 화면 완료 검증

키보드만으로 성별·카테고리·아이템·슬라이더·이름·완료 버튼을 조작할 수 있게 한다. 가능하면 네이티브 range input을 사용하고 각 슬라이더에 라벨과 현재 값을 연결한다. 방향키로 한 단계, Home/End로 범위 끝을 조절할 수 있어야 한다. 포커스 표시, 색상 이외의 상태 표시, 이름 검사 결과 알림을 제공한다. 동작 줄이기 설정에서는 자동 카메라 이동을 줄인다.

독립 미리보기에서 아래를 확인하고 실제 결과를 보고하라.

1. 다른 서비스 화면 없이 생성 화면을 직접 열 수 있고, 외형→이름→완료 요청이 화면 내부에서 동작한다.
2. 신규 기본값은 속옷·맨발이며 남녀 전환 후 이전 초안이 복원된다. 전달받은 초기값도 정확히 표시된다.
3. 키·머리·손·발과 추가 지원 슬라이더가 실제 모델을 바꾸고 초기화가 정확하다.
4. 남녀 × 속옷/상의/하의/전체 착장 × 신발 유무에서 조절값이 유지된다. 특히 발·신발 호환성을 확인한다.
5. 체형의 기본·끝값·대표 극단 조합을 정면·측면·후면과 제공한 미리보기 모션에서 확인한다. 확인한 범위와 남은 제약을 기록한다.
6. 의상 전환 중 연속 클릭·느린 로딩·실패에도 최신 선택과 프리뷰가 일치한다.
7. 가짜 이름 확인 함수로 중복·형식 오류·입력 변경·한글 조합·늦은 응답·확인 실패를 확인한다.
8. 완료 데이터에 화면의 실제 외형과 이름이 정확히 포함된다. 완료 연속 클릭, 외부 함수 실패·이름 충돌에도 초안이 유지된다. 완료가 자동 페이지 이동을 일으키지 않는다.
9. `onDraftChange`로 받은 값을 다시 `initialValue`로 넣어 재마운트하면 외형·이름이 복원된다. 다른 초기값을 가진 인스턴스끼리 상태·재질을 오염시키지 않는다. 복원된 이름은 다시 확인해야 한다.
10. 1280×720, 1920×1080 및 작은 화면에서 레이아웃을 확인하고 키보드 조작을 검증한다. 성능은 측정한 기기·해상도와 함께 보고한다.

변경한 화면에 해당하는 빌드·검사 명령을 실행한다. 이름 확인 응답 순서, 초안 보존, 완료 데이터 전달처럼 중요한 동작을 필요한 테스트로 검증한다. 기본 화면·체형 조절·의상 선택·이름 확인 화면의 스크린샷을 남긴다. 회원가입부터 튜토리얼까지의 통합 테스트는 이번 완료 조건에 넣지 않는다.

최종 보고는 **실행 방법 / 컴포넌트와 바뀐 파일 / 실제 지원 외형·의상 / props·콜백과 전달 데이터 / 화면 검증 결과와 남은 에셋 제약**으로 정리한다. 이번 완료 기준은 다른 프론트 담당자가 가져다 연결할 수 있는 캐릭터 생성 화면이다.

## 조사 메모 — 이 구조를 선택한 이유

캐릭터 생성에 모든 게임이 따라야 하는 단일 규격은 없다. 아래는 공식 사례·기술 문서에서 확인한 방식과 현재 프로젝트에 대한 설계 판단을 구분한 것이다.

### 공식 사례에서 참고한 것

- **FINAL FANTASY XIV**: 캐릭터 생성 중 카메라 회전·확대, 자세 변경, 속옷과 장비 미리보기, 외형 설정 뒤 이름 입력과 최종 확정을 제공한다. 이 순서를 참고해 ‘외형 → 이름·확정’으로 구성했다. 직업·종족·서버 선택은 우리 요구에 없어 가져오지 않았다. [공식 게임 매뉴얼](https://na.finalfantasyxiv.com/game_manual/start/)
- **검은사막**: 머리·얼굴·몸 등의 부위별 편집, 높이·너비 조절, 편집 이력 되돌리기, 임시 저장·기본값 복원을 안내한다. 부위별 패널과 안전하게 되돌릴 수 있는 편집 구조를 참고했다. 검은사막 수준의 모든 얼굴 기능을 현재 모델이 지원한다는 뜻은 아니다. [공식 커스터마이징 가이드](https://www.sa.playblackdesert.com/es-MX/Wiki?wikiNo=384)
- **Ready Player Me 기술 문서**: 아이템 목록을 종류·호환 대상별로 구성하고, 초안에 아이템을 적용해 미리 본 뒤 최종 저장하는 흐름을 설명한다. 이 데이터 구조만 참고했다. 해당 서비스를 도입하라는 제안은 아니다. [Custom Avatar Creator](https://docs.readyplayer.me/ready-player-me/integration-guides/api-integration/custom-avatar-creator)
- **Epic Games**: 모듈형 캐릭터는 호환되는 스켈레탈 메시와 포즈 연결이 필요하며, 결합 방식에 따라 모프 지원과 처리 비용이 다르다. 따라서 ‘의상 추가 버튼’만으로 새 옷이 기존 체형에 자동 호환된다고 가정하지 않았다. Unreal 전용 API를 현재 웹 프로젝트에 이식하라는 뜻은 아니다. [Working with Modular Characters](https://dev.epicgames.com/documentation/en-us/unreal-engine/working-with-modular-characters-in-unreal-engine)
- **Three.js**: `SkeletonUtils.clone`은 SkinnedMesh와 뼈의 연결을 유지해서 복제하며 형상·재질은 참조로 재사용한다. 프리뷰 편집이 다른 캐릭터까지 바꾸지 않도록 인스턴스별 상태와 변경 자원을 분리해야 한다. [SkeletonUtils 문서](https://threejs.org/docs/pages/module-SkeletonUtils.html)
- **W3C**: 슬라이더의 방향키·Home/End 조작, 라벨, 최소·최대·현재 값 제공을 설명한다. 웹 화면의 조작 규칙은 이 기준을 따른다. [Slider Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)

### 현재 저장소에서 확인한 중요한 차이

1. **외형 기능이 이미 있다.** `메시외형옵션.js`와 `치비게임아바타.jsx`에 선택지·모프·뼈 보정이 있으므로 새 시스템을 중복 제작하기보다 생성 화면의 어댑터에서 재사용하는 방향이다. 코드 존재가 모든 극단 조합의 시각적 품질 검증 완료를 뜻하지는 않는다.
2. **의상은 전신 착장 교체 방식이다.** UI와 카탈로그는 확장 가능하게 하되, 현재 에셋 구조에 맞춰 구현해야 한다.
   - 실제 몸체 8개와 대응 신발 8개가 존재한다. 몸체에는 손·발의 실제 정점 변형 데이터가 있고, 신발에는 모프 타깃이 없다. 따라서 신발 착용 시 발 크기 연동 보완이 필요하다.
   - 몸체는 파일당 약 10~15.4MB다. 최초 진입에서 모든 조합을 동시에 로드하기보다 선택한 모델부터 표시하는 구성이 적합하다.
3. **서비스 연결은 다른 프론트 담당 영역이다.** 시작페이지와 본편의 연결, 회원가입 이후 이동, 오프닝→튜토리얼 순서와 복귀 처리는 이번 화면 구현에서 제외했다.
4. **중복확인은 외부 함수로 받는다.** 현재 모의 API는 이름 길이만 확인하므로 생성 화면은 해당 API에 직접 의존하지 않고, 확인 버튼·결과 UI와 콜백 계약만 제공한다.

이 파일은 구현을 위한 프롬프트와 조사 결과다. 게임 코드, 에셋, 기존 PRD 원본을 수정하거나 화면 구현을 완료한 결과물은 아니다.
