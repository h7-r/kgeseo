03 · 에셋AI가 에셋과 어떻게 상호작용하나

퍼즐은 「무엇을 하는 물건」만 정하고, 실제 물건은 라이브러리에서 찾아 붙인다. 그래서 라이브러리가 바뀌어도 퍼즐은 그대로다.

04 · 에셋시대 고증은 어떻게 하나

한 겹에 기대지 않는다. 정보 → 검색 → AI 판단 → 코드 검사 → 사람, 다섯 겹으로 거른다.

05 · 서버 × 에셋무거운 에셋을 CDN으로 빼는 이유

1인 100~250MB처음 접속할 때 받는 3D · 영상(추정). 100명이면 10~25GB
Vercel 무료 월 100GB화면 호스팅 한도를 에셋이 다 쓰지 않게 뺌
CloudFront 월 1TB 무료 사용종량제 요금의 무료 구간(정액형 Free 플랜과 다름) — 베타 규모면 전송비 0원
파일 전송 분리몰림의 대부분인 첫 다운로드를 앱 서버가 지지 않음(API · DB · 로비 부담은 남음, 기기 로딩 시간은 별도 과제)

06 · 서버 × 에셋CDN으로 빼도 새 맵을 만들 때 에셋을 가져올 수 있는 이유

CDN은 플레이어에게 보내는 복사본이다. AI는 원본을 읽는다. 둘을 잇는 건 「파일 경로」 하나다.

09 · 서버장기 설계인가, 임시방편인가

장기 — 그대로 간다

  • 3D는 브라우저, 서버는 판정 · 저장만
  • 무거운 파일은 CDN
  • 진행 상태는 DB에(서버를 늘려도 안 갈라짐)
  • 로비 = 10명 방들의 모음, 게임과 분리
  • 도메인 · 화면 · 서버 · 파일을 각각 다른 곳에

임시 — 커지면 바꾼다

  • EC2 1대 · 손 설치
  • RDS 단일 영역
  • Vercel 개인 무료 계정
  • 라이브러리 원본이 맥 한 대(백업 권장)

지금 제대로 — 안 하면 재설계

  • 인증 · 세션 소유권(지금 없음)
  • 요청 수 제한(지금 없음)
  • 하위 주소 구조 · 에셋 주소 한 곳
  • 게시 때 라이선스 검사
  • 배포 확인은 실제 케이스로
  • 콘텐츠 · 에셋 버전 함께 고정
  • 제작 단계 기록 형식

10 · 장기 운영지금 정해 둘 연결 규칙 네 가지

서버 한 대 · 손 설치는 나중에 바꾸면 된다. 아래 네 가지를 느슨하게 두면 재작업이 커진다.

① 콘텐츠와 에셋을 한 묶음으로 게시

지금 서버는 콘텐츠 JSON만 버전 고정하고, 에셋 목록은 화면 빌드에 하나만 있다 → 새 판을 게시하면 진행 중인 플레이어도 새 파일을 읽게 된다.

규칙 — 콘텐츠 버전 + 에셋 목록 · 해시 + CDN 경로 + 승인 기록 + 실행부 버전을 한 묶음으로. 세션이 자기 버전 경로를 받는다. 순서: 업로드 → 누락 · 해시 검사 → 서버 로딩 검사 → 신규 세션 공개, 실패 시 보류 · 되돌림.

② 「적혀 있다」와 「실제로 된다」를 구분

「열기」가 적혀 있어도 그 3D가 실제로 열리는 건 아니다.

규칙 — 동작마다 기획상 가능 / 준비된 표현(열린 판 등) / 실행부 지원 / 플레이 검증 네 칸. 퍼즐이 요구하는 동작을 코드로 검사하고, 안 되면 대체 연출이나 생성 요청.

③ 제작 단계 기록 · 라이브러리 백업

제작은 맥에서 계속해도 된다. 다만 모든 실행에 작업 ID · 단계 · 입출력 버전 · 승인 상태 · 재실행 이력을 남겨 두면, 나중에 서버 작업 대기열로 옮길 때 다시 설계하지 않는다. 라이브러리는 원본 · 색인 · 출처 · 검수 기록까지 베타 중 바로 비공개 백업.

④ 인증 · 권한

지금 서버 CORS는 쿠키를 받지 않는 설정이다. 쿠키 세션을 붙일 때 자격 증명 허용 · 만료 · 로그아웃 · CSRF 방어 · 서버가 여러 대여도 같은 세션 확인을 함께 넣는다. 지자체가 직접 관리하는 단계 전에는 기관별 콘텐츠 · 통계 · 게시 권한 경계를 설계.
