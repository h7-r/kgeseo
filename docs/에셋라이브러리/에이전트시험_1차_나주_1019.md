## 2. 에이전트가 라이브러리 에셋을 인지하는 방식
1. **필요 목록**: 04 Scene 구성표의 에셋 요구(REQ)를 쓴다. 요구마다 역할(story_object·dressing), 한글 태그, 장소, 시대, 「왜 거기 있나」가 있다(구체 물건명은 정하지 않음 — 규격).
2. **후보 찾기(코드, 무료)**: 한글 태그마다 라이브러리 검색(글자 유사도 + 로컬 임베딩)으로 요구당 후보 최대 12개.
3. **고르기(LLM)**: 후보마다 「id · 이름 · 분류 · 시대 · 어울리는 장소 · 설명 · 설화 단서 · 맥락 필요 · 쓰면 안 되는 곳 · 실제 크기 · 임시본/설명 추정」 한 줄을 보고 하나를 고르거나 「없음」. 후보 밖 id 는 코드가 버린다.
4. **배치(LLM)**: 공간 구역의 물리 정보(좌표·높이·바닥)와 고른 에셋의 크기로 Scene→구역, 자리·방향을 정한다. 코드가 구역 밖·선정 밖을 거르고 겹침을 경고한다.

→ 메타데이터가 곧 에이전트의 눈이다. 「설명 추정」 185건과 임시본 29건은 사람 확인·교체가 필요하다.
