# 깃 사용법 — 팀원용

여섯 명이 한 저장소를 쓴다. **아래 다섯 상황만** 알면 된다.
외우지 말고 필요할 때 여기서 찾아 쓴다.

| 이럴 때 | 이거 |
|---|---|
| 처음 받을 때 | `git clone` → `npm install` |
| 새 작업 시작 | `git pull` → `git switch -c` |
| 작업 저장 | `git add .` → `git commit` |
| **작업 중에 최신 받기** | `commit` → `pull` → `merge main` |
| 다 됐을 때 | `git push` → GitHub에서 PR |

---

## 1. 처음 한 번만

깃허브에서 온 **초대를 먼저 수락**한다. 안 하면 아래가 안 된다.

```bash
git clone https://github.com/h7-r/kgeseo.git
cd kgeseo
npm install     # 패키지 설치 — 2~3분
npm run dev     # http://localhost:5173
```

> **왜 `npm install` 이 따로 필요한가**
> 저장소에는 `node_modules`(289MB)가 들어 있지 않다.
> 대신 `package.json` 에 "무엇이 필요한지" 목록만 있고, `npm install` 이 그걸 보고 받아온다.

## 2. 새 작업을 시작할 때

**항상 최신 `main` 에서 시작한다.** 옛날 기준으로 작업하면 나중에 합칠 때 충돌이 난다.

```bash
git switch main
git pull                          # 남들이 올린 최신 받기
git switch -c feat/내이름-작업내용   # 새 브랜치를 따서 거기서 작업
```

### 브랜치 이름

| | |
|---|---|
| `feat/세진-기차좌석` | 새 기능·새 화면·새 물건 |
| `fix/문통과안됨` | 버그 수정 |
| `docs/기획서정리` | 문서 |
| `chore/패키지정리` | 설정·정리 |

## 3. 작업하다가 저장할 때

자주, 작게 저장한다. 한 번에 몰아서 하면 나중에 어디서 잘못됐는지 못 찾는다.

```bash
git add .
git commit -m "기차 내부 좌석 7열 배치"
```

메시지는 **"무엇을 했는지"** 한 줄로. `수정`, `ㅇㅇ`, `asdf` 는 나중에 아무도 못 찾는다.

## 4. ★ 작업 중에 최신화 받기

내가 이틀째 작업하는 동안 다른 사람이 `main` 에 여러 개를 합쳤다.
이때 **그냥 두면 나중에 합칠 때 충돌이 산더미**가 된다.
중간중간 가져와 섞어 두면 조금씩만 정리하면 된다.

```bash
# ① 내 작업을 먼저 커밋한다 (이거 안 하면 꼬인다)
git add .
git commit -m "작업 중 저장"

# ② main 최신 받기
git switch main
git pull

# ③ 내 브랜치로 돌아와 섞기
git switch feat/내이름-작업내용
git merge main
```

> ⚠ **섞은 뒤 `package.json` 이 바뀌었으면 `npm install` 을 다시 돌린다.**
> 누군가 새 패키지를 추가했을 수 있다.

**얼마나 자주?** 하루 한 번, 그리고 팀에서 "머지했어요" 소리가 들리면 그때.
작업이 3일 넘어가면 무조건.

## 5. 다 됐으면 올리기

```bash
git push -u origin feat/내이름-작업내용   # 그 브랜치의 첫 push
git push                              # 그다음부터는 이거만
```

올리고 나서 깃허브 저장소에 들어가면 노란 띠에 **Compare & pull request** 버튼이 뜬다.
눌러서 무엇을 했는지 적고 **Create pull request** → 리뷰 → **Merge**.

---

## 충돌이 났을 때

당황하지 않는다. **같은 줄을 두 사람이 고쳤다**는 뜻일 뿐이다.

```bash
git status        # 어떤 파일이 충돌했는지 본다
```

그 파일을 열면 이렇게 생긴 표시가 있다.

```
<<<<<<< HEAD
내가 쓴 코드
=======
남이 쓴 코드
>>>>>>> main
```

**남길 것만 남기고 `<<<` `===` `>>>` 세 줄은 지운다.** 둘 다 필요하면 둘 다 남겨도 된다.
정리한 뒤:

```bash
git add 정리한파일
git commit
```

> ⚠ **3D 씬 코드(`App.jsx`, `scenes/`)에서 충돌이 나면 혼자 판단하지 않는다.**
> 숫자만 봐서는 어느 쪽이 맞는지 알 수 없다. 정리하기 전에 팀에 물어본다.

## 절대 하지 말 것

**1. `main` 에 직접 push** — 반드시 브랜치를 따서 PR로 올린다.

**2. `git push --force`** — 남의 작업이 **영구히 사라진다.**
뭔가 꼬였으면 강제로 밀지 말고 팀에 물어본다.

**3. 한 파일을 두 사람이 동시에 수정** — `src/App.jsx` 는 **1만 줄이 넘는다.**
동시에 손대면 충돌이 확정이고, 3D 코드는 정리가 거의 불가능하다.

### 담당 파일

| 파일 | 담당 |
|---|---|
| `src/App.jsx` | 역(승강장·복도) 씬 — 한 명 |
| `src/scenes/기차내부.jsx` | 기차 안 — 한 명 |
| `src/공용.jsx` | **아무나 손대지 않는다.** 바꿀 일이 생기면 먼저 팀에 말한다 |

새 공간을 만들 때는 **`src/scenes/` 아래 새 파일**로 만든다. `App.jsx` 에 이어 붙이지 않는다.

## 자주 나는 오류 둘

### `Failed to resolve import "..."`

누군가 새 패키지를 추가했는데 내 컴퓨터엔 아직 안 깔린 것.

```bash
npm install
```

### "내 화면에선 되는데 팀원 화면에선 다른데요"

Leva 패널(오른쪽 조절창)에서 바꾼 값은 **내 브라우저에만 저장된다**(localStorage).
커밋해도 남에게 전달되지 않는다.
값을 확정하려면 **코드의 기본값 숫자를 직접 고쳐서 커밋**해야 한다.

```js
배관x비율: { value: 0.62, ... }   // ← 이 숫자를 바꿔 커밋해야 공유된다
```
