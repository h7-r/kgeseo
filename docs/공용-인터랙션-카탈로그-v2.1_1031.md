# 00. 공용 인터랙션 카탈로그 v2.1 (10/31)

> **용도**: 퍼즐 에이전트와 문서가 **실제 구현 가능한 행동만** 사용하도록 제한하는 프로젝트 공용 기준.
> (Case 콘텐츠·SceneInventory·퍼즐 데이터가 참조하는 단일 진실원. 원본: 팀 카탈로그 PDF v2.0 · 2026-09-28)

## 0. 문서 정보
- **Catalog Version**: v2.1 (10/31 — §3 주석 · §4 원칙 1줄 · §6 신설. 원본 v2.0 파일은 그대로 둠)
- **검토 상태**: READY — FE·BE 계약 합의 완료
- **API 연동 계약**: Interaction Contract v0.3.2
- **저장소 반영**: 기존 v0.3.1 파일을 v0.3.2로 갱신 필요
- **FE의 5종별 MVP 실제 구현 상태**: 별도 확인 필요

## 1. Interaction v1 — 계약 5종
| action | 설명 |
|---|---|
| `inspect` | 오브젝트·기록·단서 조사 |
| `navigate` | Zone 또는 조사 지점 이동 |
| `input` | 텍스트·코드 등 입력 |
| `select` | 선택지·대상 선택 |
| `combine_clues` | 획득 단서 2개의 관계 추론·조합 |

**사용하지 않는 옛 ID** (현재 API Interaction ID로 사용 안 함):
`observe` / `collect` / `compare` / `rotate` / `align` / `connect` / `sequence` / `input_code`
- 특히 `collect` 기반 **아이템 인벤토리는 사용하지 않는다.** 획득 정보는 `acquired_clue_ids`로 관리한다.

## 2. Interaction Contract v0.3.2 확정 내용
- `result_type` = `ok | correct | incorrect | already_completed`
- `inspect` / `navigate` 등 비채점 정상 처리 → `ok`
- `message`: `string | null` — BE 콘텐츠 제공, FE는 null일 때 폴백
- `attempt_count` — 채점 요청만 증가, 첫 제출 1
- 동일 `client_event_id` 재전송 → 최초 응답 그대로 반환, attempt 증가 없음
- 새 `client_event_id`로 완료 퍼즐 재제출 → `already_completed`, `state_changes: []`
- `interaction_id` → 서버 UUID
- `state_changes` → 실제 변경분만
- `ui_actions` → 현재 `[]`

## 3. state_changes 닫힌 목록
| type | payload |
|---|---|
| `clue_acquired` | `clue_id` |
| `puzzle_completed` | `puzzle_id` |
| `zone_unlocked` | `zone_id` |
| `hint_level_changed` | `puzzle_id` + `hint_level` |

> [10/31] 위 4종은 **닫힌 목록으로 유지**한다. `hint_level_changed`는 퍼즐별 최대 공개 단계로만 쓴다. 힌트 잔액 · 도움 사용 수 · 별 · 지역 달성률 · 보상은 여기에 끼워 넣지 않는다(§6).

## 4. 등록 원칙
- 계약 5종 중 **실제 구현 가능하고 사용 승인된 것만** FE Interaction / Puzzle Agent가 사용한다.
- Case 문서에서 **새로운 Interaction ID를 임의 생성하지 않는다.**
- SceneInventory의 affordances는 **승인된 5종만** 참조한다.
- **아이템 인벤토리를 새로 도입하지 않는다.**
- **Hint는 Interaction 5종에 추가하지 않고 별도 Hint API로 처리한다.**
- [10/31] **힌트 잔액 · 별 · 보상도 상태 변화(`state_changes`)가 아니라 별도 응답 필드 · 별도 API로 처리한다.** 넣어야 한다면 계약 버전을 올린다.

| 힌트 잔액 · 도움 사용 수 · AI 호출 한도 | Hint API 응답의 `balance` 등 필드 · `GET …/hint-wallet`(API-030) | 회차(잔액) / 계정 · 게스트 + 사건(호출 한도) |
