## 한 줄 요약

계약서 구조는 좋다. 그대로 가되 —

1. **`transform` 은 프론트가 갖는다** (서버는 항상 null). 드로우콜 때문에 메시를 병합해
   둬서, 서버가 위치를 내려주면 그 최적화가 깨진다.
2. **인터랙션 타입을 지금 되는 4개로 좁힌다** — `inspect` / `navigate` / `input` / `select`.
   나중에 늘리는 건 쉽고, 줄이는 건 어렵다.
3. **`GET /api/v1/sessions/{id}` 를 추가한다.** GPU 컨텍스트 손실로 강제 새로고침이 실제로
   일어나는 게임이라, "지금 어디였는지"를 돌려주는 API가 없으면 복귀가 안 된다.

## 용어 충돌 주의

| 우리 코드 | 계약서 | |
|---|---|---|
| 세션 (S0~S9) | — | 화면 단계 (로그인 / 캐릭터생성 / 로비 / 인게임…) |
