# 계약 v0.4.16 — 상황 대사(FE 감지 → BE 판단) · 잡담 위치 (11/6)

> v0.4.7(자동 개입 판단은 BE 일원화) · v0.4.14(일반 팩 정책 검사) 위에 덧붙인다.
> 기준 코드: main `backend/app/schemas/npc_turn.py`(NPC 턴 계약 v0.2) · `npc_content.py`(`npc-pack 0.1`).
> 🟢 결정 · 🟡 운영하며 조정 · 🔴 확인 필요

## 1. 역할 나눔 🟢
| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **FE** | 상황을 **감지**해 auto 턴으로 보낸다. 표시 조건(거리 · 컷신 · 모달 · 대화 중)만 관리하고 표시 · 미표시 · 거절을 보고한다(v0.4.7 §3) | 대사 고르기 · 횟수 세기 · 쿨다운 판단 |
| **BE** | 상황 코드를 받아 **말할지 · 무엇을 말할지** 정한다(횟수 · 쿨다운 · 승인 여부 · 게시 상태). 승인 원문만 돌려준다(LLM 안 씀) | 상황 감지 |

- 지금 FE 초안의 「도움말 횟수 세기 · 대사 고르기」는 BE로 옮긴다. FE에는 감지 코드만 남긴다.

## 2. 요청 — 기존 auto 턴에 `situation` 추가 🟢
`POST /api/v1/play-sessions/{play_session_id}/npc/turns`

```jsonc
{
  "client_event_id": "uuid",
  "client_timestamp": "2026-11-06T10:00:00+09:00",
  "trigger": "auto",
  "focus_object_id": "OBJ_…",          // 기존 필드. 퍼즐은 서버가 이 값으로 찾는다
  "situation": {                        // 새 필드(trigger=auto 일 때만, 없으면 기존 퍼즐 자동 개입)
    "code": "BREATH_LOW",               // 아래 3절 목록만 허용
    "zone_id": "ZONE_…",                // 선택. 플레이어가 있는 Zone
    "value": 12                         // 선택. 수치가 있는 상황(남은 숨 초 등)
  }
}
```

- **P번호는 보내지 않는다.** 기존 계약대로 퍼즐은 서버가 `focus_object_id`(퍼즐 대표 Object)로 찾는다 — 클라이언트가 퍼즐을 지정하지 않게 하기 위함이다.
- `player_message` 턴에는 `situation`을 싣지 않는다(422).

## 3. 상황 코드 목록 🟡
- 해랑 님 초안 「상황 대사 71개」에서 코드를 뽑아 이 표를 채운다. 코드는 `UPPER_SNAKE`, 케이스와 무관한 이름으로 둔다.

| code | 언제 FE가 보내나 | 대사가 할 수 있는 말 |
|---|---|---|
| `BREATH_LOW` | 물속 남은 숨이 기준 아래로 처음 떨어질 때 | 숨이 부족하다 · 거품 자리로 가라 수준 |
| `OFF_OBJECTIVE` | 지금 목표 구역에서 오래 벗어났을 때 | 「이쪽은 아닌 것 같다」 수준. 목적지 이름은 이미 공개된 것만 |
| `ITEM_MISSING` | 필요한 물건 없이 다음 장소에 왔을 때 | 「아직 챙기지 않은 게 있는 것 같다」 수준. **안 찾은 물건의 이름 · 위치 금지** |
| 🔴 나머지 | 해랑 초안 분류 뒤 추가 | — |

- 대사 규칙은 넛지와 같다(v0.2 §5 · v0.4.11): 정답 · 아직 공개되지 않은 단서 · 힌트 문장 금지, 이미 공개된 정보만 다시 짚는다. 게시 때 PUB 정책 검사(NG · 정답 문자열 · 미공개 단서)를 똑같이 돈다.

## 4. 콘텐츠 — `npc.json`(케이스 팩)에 `situations` 추가 🟢
```jsonc
"situations": [
  { "code": "BREATH_LOW",
    "cooldown_seconds": 60,                         // 코드별. 없으면 서버 기본값
    "lines": [ { "line_id": "SIT_BREATH_LOW_01", "text": "…" } ] }
]
```
- `line_id`는 케이스 안에서 유일(기존 중복 검사에 포함). G3 승인 대상이다.
- **횟수 · 쿨다운은 퍼즐 자동 개입(오답 6회 · 무입력 240초, v0.4.7)과 따로 센다.** 상황 코드별 쿨다운만 둔다. 🟡 기본값 60초 — 운영하며 조정.
- 같은 코드에 대사가 여러 개면 BE가 돌아가며 고른다(직전과 같은 것 피함).

## 5. 응답 🟢 (기존 형식 그대로)
- 말함: `reply: { source: "approved_line", line_id, text }`, `suggest_hint: null`.
- 쿨다운 중 · 해당 코드에 승인 대사 없음 · 게시 중단: `reply: null`. 대사 없음은 오류가 아니다.
- 상황 대사는 힌트 버튼을 제안하지 않는다(`suggest_hint`는 퍼즐 자동 개입에서만). `hint_level` · 잔액 · 별은 바꾸지 않는다.
- 기록: 이벤트에 `situation.code`를 남긴다(대사 원문은 남기지 않음 — 기존 규칙).

## 6. 잡담 · 장난 대사 위치 🟢 (11/6 정정)
- **케이스 팩의 기존 `general_nudges`(퍼즐과 무관한 대사)에 둔다.** 나주 고유명(마을 · 아랑사 · 강바람 등)이 들어가도 된다 — 케이스 팩이기 때문이다.

  - 11/6 앞선 답변의 「일반 팩에 `chatter`로」는 이 항목으로 바꾼다.

## 8. 추가 결정 (11/6 BE 질문 7건) 🟢 / 숫자 🟡
1. **판정 없는 걸음 12개:** `situations[].lines[]`에 선택 필드 `focus_object_id`를 둔다. BE는 「코드 + 같은 Object」 대사를 먼저 고르고, 없으면 Object 조건 없는 대사를 고른다.
2. **쿨다운 단위:** `(상황 코드, focus_object_id)`마다 60초. 여기에 🟡 **상황 대사 전체 최소 간격 20초**를 더한다 — Object를 옮겨 다닐 때 동행이 쉬지 않고 말하지 않게.
3. **말투:** 베타는 **해요체 존댓말 한 벌**. 동행 캐릭터라 상점 응대 말투보다 함께 다니는 동료의 존댓말로. 말투 선택은 나중 기능.
4. **QUIET(잡담):** FE가 `QUIET`을 보내면 BE가 `general_nudges`에서 고른다. 우선순위는 가장 낮고, 퍼즐 자동 개입 · 다른 상황 대사의 쿨다운 중에는 내지 않는다. 🟡 회차당 최대 5회 · 코드 쿨다운 180초.
5. **동시 발생 우선순위(FE가 하나만 보냄):** 숨 부족 → 아이템 → 실수 → 목표 이탈 → 진행 없음 → 잡담. BE는 그래도 쿨다운 · 상한으로 거절할 수 있다.
   - **겹침 방지:** 서버 판정 퍼즐의 「연속 오답 6회 · 무입력 240초」는 v0.4.7 퍼즐 자동 개입이 맡는다. 「실수 · 진행 없음」 상황 대사는 **화면 판정 퍼즐과 판정 없는 걸음에서만** 쓴다. 같은 퍼즐에 두 개입이 겹치면 BE는 퍼즐 자동 개입을 우선한다.
6. **멱등 vs 재발화:** 같은 `client_event_id` 재전송 → 처음 응답 그대로(기존 멱등 저장소, `situation`까지 같아야 함 — 다르면 422). 새 `client_event_id`의 같은 상황 → 쿨다운으로 판단. 쿨다운 · 횟수는 서버 상태라 이어하기 뒤에도 유지된다.
7. **대사 변수:** 베타는 `{name}` · `{item}` · `{left}` 같은 치환 없이 **고정 문장만**. 승인 원문 = 화면 문장이 되게.

## 9. 추가 결정 (11/6 오후 — FE 상황 정리 · 해랑 PR #40 반영) 🟢 / 숫자 🟡
> 이 절이 §3 표와 §8-5 순서를 대신한다. 「미승인」으로 남은 다른 문서 표시는 이 절 기준으로 고친다.

1. **말투:** 해요체 존댓말 한 벌(「함께 다니는 동료의 존댓말」). 말투 묻기 · 바꾸기 기능은 베타에서 끈다. 반말 초안은 보관만.
2. **고정 문장:** 이름 · 수 치환 없음(§8-7). 「남은 수」처럼 바뀌는 값은 FE 문구로 보낸다.
3. **NPC 승인 대상에서 빠지는 것:** 퍼즐 설명 · 진행 알림(약 175줄)은 **FE 게임 문구**, 인사 · [F] 보기 · 「더 알려 드릴까요?」 같은 대화 진행 문구는 **FE 고정 문구**. 동행 말투로 보여 줘도 G3 대상이 아니며, 퍼즐 검수(G2)와 게시 검사(NG · 정답 문자열 · 미공개 단서)로 본다.
4. **상황 코드 11개**(§3 표 대체 — 정의 · 감지 근거는 해랑 `docs/naju/NPC_상황분류표_1106.md`):

| code | 뜻 |
|---|---|
| `BREATH_LOW` | 물속 숨이 기준 아래로 처음 떨어짐 |
| `SENT_BACK` | 숨이 다하거나 빠져서 되돌려짐 |
| `ITEM_MISSING` | 필요한 물건 없이 다음 자리에 옴 |
| `ITEM_LEFT_BEHIND` | 가진 물건을 내려놓고 멀어짐 |
| `ITEM_NOT_PICKED` | 보상 물건을 안 줍고 다음 구역으로 감 |
| `REPEATED_MISTAKE` | 같은 실수를 거듭함(화면 판정 퍼즐 · 판정 없는 걸음만) |
| `OFF_OBJECTIVE` | 목표 구역에서 오래 벗어남 |
| `NO_PROGRESS` | 오래 진전이 없음(화면 판정 퍼즐 · 판정 없는 걸음만) |
| `STEP_ARRIVED` | 걸음 자리에 처음 도착(걸음 12개 첫 설명) |
| `STEP_DONE` | 걸음 · 화면 판정 퍼즐이 풀림 — 연출이 끝난 뒤 한 번 |
| `QUIET` | 한동안 조용함(잡담) |

5. **동시 발생 순서**(§8-5 대체): 숨 부족 → 되돌려짐 → 아이템 셋 → 반복 실수 → 목표 이탈 → 진행 없음 → 걸음 도착 · 풀림 → 잡담. 서버 판정 퍼즐과 겹치면 v0.4.7 퍼즐 자동 개입이 우선(§8-5 겹침 방지 유지).
6. **분량** 🟡: 코드당 2줄(직전 대사 피하기 최소), `NO_PROGRESS` · `REPEATED_MISTAKE` · `OFF_OBJECTIVE`만 3줄까지. 걸음 12개는 각 1~2줄 + `focus_object_id`. FE 문구와 같은 말을 되풀이하는 대사부터 뺀다.
7. **잡담 구역:** `general_nudges[].lines[]`에 선택 필드 `zone_id`. FE는 `QUIET`에 `situation.zone_id`를 꼭 싣는다. BE는 같은 구역 대사를 먼저, 없으면 구역 조건 없는 대사를 고른다(§8-1과 같은 방식). 나주 잡담 15개(공통 3 + 구역 12)는 G3 대상.
8. **값 확정 시점:** 걸음의 `focus_object_id` · 잡담의 `zone_id`는 11/9 나주 대응표의 Object · Zone ID로 맞춘다. 그 전까지 FE는 화면 쪽 ID로 짝지어 둔다.
