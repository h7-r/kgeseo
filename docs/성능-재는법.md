# 성능 재는 법

> 눈대중으로 "빨라진 것 같다"를 말하지 않기 위한 문서다.
> 나주 진입이 **25.3초 → 2.7초**로 줄어든 것도 전부 이 방식으로 쟀다.

## 0. 먼저 — 무엇을 재는지 정한다

논쟁이 길어지는 이유는 대개 서로 다른 것을 재고 있어서다. 최소한 이 셋은 다른 값이다.

| 지표 | 무엇 | 재는 법 |
| --- | --- | --- |
| **받은 에셋** | 파일 몇 MB를 내려받았나 | Playwright `response` 가로채기 |
| **총 CPU** | 함수별로 몇 초를 썼나 | CDP `Profiler` |
| **멈춤** | 한 번에 몇 ms씩 얼었나 | `PerformanceObserver` longtask |
| **첫 화면 시각** | 사람 눈에 언제 나왔나 | 화면을 찍어서 판별 (아래) |

파일이 크다고 멈추는 게 아니고, 총 CPU가 크다고 첫 화면이 늦은 게 아니다.
실제로 나주는 **총 CPU는 지형이 먹고 있었는데 첫 화면은 캐릭터가 붙잡고 있었다.**

## 1. 반드시 지킬 세 가지

### ① `headless: false` — 헤드리스는 GPU가 아니다

헤드리스 크롬은 **SwiftShader(소프트웨어 렌더러)**를 쓴다. 야외 씬은 프레임당 수 초가
걸려서 숫자가 통째로 무의미해진다. 창이 떠 있는 게 번거로워도 실제 GPU로 재야 한다.

```js
const 브라우저 = await chromium.launch({ headless: false });
```

### ② 화면 **가운데만** 잘라 찍는다 — 글자에 속지 않게

"화면이 나왔나"를 스크린샷 바이트 수로 판별하는데, 계기판·조작안내 같은 **HTML 글자는
3D보다 먼저 뜬다.** 화면 전체를 찍으면 3D가 아직 비어 있어도 바이트 수가 올라가서,
"2초 만에 나왔다"는 거짓 결론이 나온다. 가장자리를 버리고 가운데만 본다.

```js
const shot = await 페이지.screenshot({ clip: { x: 340, y: 210, width: 600, height: 380 } });
if (shot.length > 12000) { /* 3D가 그려졌다 */ }
```

문턱값(12000)은 **그 화면에서 직접 확인하고 정한다.** 평평한 배경은 몇 KB, 지형·하늘·
풀이 들어오면 수십 KB다. 정했으면 그 시점 스크린샷을 눈으로 한 번 열어 봐야 한다 —
숫자만 믿다가 "까만 화면"을 "그려짐"으로 센 적이 있다.

### ③ 서버를 한 번 예열한다 — Vite 캐시 첫 회가 튄다

개발 서버는 처음 들어온 요청에서 의존성을 변환한다. 예열 없이 재면 첫 회만 몇 초
길게 나와서 중앙값이 오염된다. **한 번 띄워 버리고**, 그다음부터 센다.

```js
await 한번(포트);                 // 예열 — 값은 버린다
for (let i = 0; i < 3; i += 1) 값.push((await 한번(포트)).ms);
값.sort((a, b) => a - b);
const 중앙값 = 값[1];
```

## 2. 전후 비교는 **동시에** 한다

기계 상태(다른 창, 열, 배터리)가 시간대에 따라 변한다. 어제 잰 값과 오늘 잰 값을
비교하면 안 된다. 워크트리 두 벌을 만들어 **서버 두 개를 동시에 띄우고** 번갈아 잰다.

```bash
git worktree add --detach /tmp/새 origin/dev
git worktree add --detach /tmp/옛 <비교할 커밋>
ln -s $(pwd)/node_modules /tmp/새/node_modules     # 설치 다시 안 해도 된다
ln -s $(pwd)/node_modules /tmp/옛/node_modules
(cd /tmp/새/naju01 && npx vite --port 5176 --strictPort &)
(cd /tmp/옛/naju01 && npx vite --port 5177 --strictPort &)
```

끝나면 반드시 정리한다 — 서버를 죽이고, 심볼릭 링크를 지우고, `git worktree remove`.

## 3. 실측 기록 (2026-09-28 · Apple M5 Max · ANGLE Metal)

| | 커밋 | 회차(ms) | 중앙값 |
| --- | --- | --- | --- |
| 최적화 전 | `4db6bdf` | 25055 / 25325 / 25436 | **25.3초** |
| 네 갈래 적용 | `bd6f4d2` | 2428 / 2661 / 4160 | **2.7초** |

갈래별 몫:

- **지형 공간 색인** — `선분에투영`(지형.js) 8.54초 → 0.85초. 결과 지문 동일
- **값소음 비트 마스크** — 격자 조회 3.6배. 결과 지문 동일
- **캐릭터 지연 마운트** — R3F는 Canvas children을 Suspense **하나로** 묶는다.
  1인칭이라 보이지도 않는 15MB 몸체를 다 받을 때까지 첫 프레임이 안 나왔다
- **후처리 버퍼 형식** — 속도가 아니라 "화면이 통째로 까맣던" 건(HalfFloat → UnsignedByte)

## 4. 자주 빠지는 함정

- **모듈 최상위 `useGLTF.preload` 는 모듈을 읽기만 해도 받는다.** 컴포넌트를 안 그려도
  파일이 내려온다. 정적 `import` 를 `lazy()` 로 바꿔야 실제로 미뤄진다.
- **`Box3.setFromObject` 는 스킨드 메시의 뼈 배율을 반영하지 않는다.** 캐릭터 치수를
  잴 때는 뼈 위치나 스키닝된 정점을 직접 봐야 한다([[캐릭터-자세-측정법]] 참고).
- **이 기계는 98fps 상한이다.** 그림자·픽셀 최적화의 이득이 여기서는 측정되지 않는다.
  약한 GPU 몫으로 넘기고, 여기서는 "느려지지 않았다"만 확인한다.

## 5. 회귀가 의심될 때

이 문서대로 `origin/dev` 와 의심되는 커밋을 나란히 재면 된다. 숫자가 위 표와 크게
다르면 기계 상태부터 의심하고(다른 무거운 창을 닫고 다시), 그래도 다르면 그 사이
커밋을 이분 탐색한다.
