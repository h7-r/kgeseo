| 로그인 429 `login_locked` | 실패 누적 잠금(DB 기반, 15분 범위) | 정확한 오류 코드 확인; 임의로 계정·DB 잠금 해제하지 않음 | 운영+BE |
| 이메일·닉네임 429가 '사용 가능'으로 보임 | FE 오류 처리 회귀 | FE에 화면·시간·API 코드 전달 | FE |

| 게임 저장 충돌/진행 덮어쓰기 | 알려진 동시 쓰기 버그 또는 정상 409 | 동일 계정 여러 탭·기기 여부 기록, 중복 실행 중지 | FE+BE |
| NPC 넛지가 안 나옴 | 게시 상태·OFF 정책 가능(상황 대사·정식 힌트는 베타 제외라 정상) | 오답·무입력 넛지 여부와 나주 v1 rev 1 게시 상태 먼저 확인 | PM+콘텐츠 |
| 로비 입장 실패 | 로그인 상태·JWT TTL·설정·429 가능(명단은 `*`) | HTTP 상태(401/403/429/503), 시각, 요청 상황 기록 | 운영+미르님 |
| Google/Naver 로그인 503 | 베타 미제공(준비 중) — 정상 | 이메일 로그인으로 안내, 화면에 '준비 중' 표시 확인 | PM+FE |

### 429 처리의 핵심

- `rate_limited`: 네 API가 각각 60초/IP 버킷을 사용한다. 응답은 HTTP 429, `Retry-After`, `detail.code=rate_limited`.
- `login_locked`: 로그인 실패 잠금. 같은 IP에서 다수가 실패하면 공유 잠금이 발생할 수 있으므로, **가입 제한값을 올려도 로그인 잠금 문제는 해결되지 않는다.**
- 모니터링은 정상 요청 중 실제로 발생한 429를 기준으로 한다. 운영 서버에 31번·61번 요청을 반복해 인위적으로 검증하지 않는다.

## 6. 요청 제한 상향/복구 — 운영 담당자만

현 기본값(환경 변수 미설정 시):

| 설정명 | 기본값 | 기능 |
|---|---:|---|
| `RATE_LIMIT_EMAIL_EXISTS` | 30 | 이메일 중복확인 |
| `RATE_LIMIT_NICKNAME_EXISTS` | 30 | 닉네임 중복확인 |
| `RATE_LIMIT_REGISTER` | 30 | 회원가입 — 베타 종료 후 10으로 조정 |
| `RATE_LIMIT_ANONYMOUS_SESSION_CREATE` | 60 | 새 게스트 세션 발급 |
| `RATE_LIMIT_WINDOW_SEC` | 60초 | 공통 제한 창, 보통 변경하지 않음 |

**중요:** 이 설정은 실행 중 자동 갱신되지 않는다. `.env` 변경 후 `waegok-api` 재시작이 필요하며, 코드 재배포는 필요 없다. 재시작 중 짧은 API 요청 실패가 있을 수 있다. 기존 메모리 카운터는 재시작으로 초기화되고, DB 로그인 잠금은 유지된다.

운영 담당자의 승인된 절차:

1. 현장에서 `rate_limited`가 실제 장애인지 확인하고 PM이 조정할 한도·시점을 결정한다.
2. 운영 변수 중복 여부(systemd `Environment=`/`EnvironmentFile=` 및 앱 `.env`)를 확인한다. **설정은 한 곳에서만 관리**한다.
3. 변경 전 설정값을 안전하게 기록하되 다른 비밀값을 노출하지 않는다.
4. 운영 설정 파일의 지정된 `RATE_LIMIT_*` 행만 수정한다. 0·음수·빈 문자열·문자열 등의 잘못된 값은 **서버 시작 실패**를 유발한다.
5. 운영 담당자가 승인된 방식으로 `waegok-api`만 재시작한다. Caddy와 로비 서비스는 재시작하지 않는다.
6. `systemctl is-active waegok-api`, 내부·외부 `health/ready`를 확인한다. 이상이 있으면 원래 설정으로 되돌린 뒤 다시 재시작하고 BE와 공유한다.
7. 변경 시각, 이유, 변경 항목과 수치, 재시작 여부, 검증 결과를 기록한다.

베타 종료 후에는 PM 확정에 따라 `RATE_LIMIT_REGISTER=10`을 설정하고 `waegok-api`를 재시작한다. 다른 세 API는 기본값 유지.
