# 구글·네이버 로그인 설정

새 PC나 새 팀원이 간편 로그인을 켤 때 따른다. 키 값은 저장소에 올리지 않는다.

## 1. 키 받기

프로젝트 키 관리자에게 아래 값을 안전한 경로로 받는다. 깃·공개 채널에 붙여 넣지 않는다.

| 값 | 넣는 곳 |
| --- | --- |
| 구글 클라이언트 ID | `backend/.env` 의 `GOOGLE_CLIENT_ID`, `website/.env` 의 `VITE_GOOGLE_CLIENT_ID` |
| 네이버 Client ID | `backend/.env` 의 `NAVER_CLIENT_ID`, `website/.env` 의 `VITE_NAVER_CLIENT_ID` |
| 네이버 Client Secret | `backend/.env` 의 `NAVER_CLIENT_SECRET` |

구글 클라이언트 보안 비밀번호는 지금 코드가 쓰지 않으므로 넣지 않는다.

```bash
cp backend/.env.example backend/.env
cp website/.env.example website/.env
```

`backend/.env` 의 `NAVER_REDIRECT_URI` 는 로컬에서 `http://localhost:5175/로그인/콜백` 이다.

## 2. 파일 점검

```bash
npm run check:social
```

값은 출력하지 않고 빠진 키와 어긋난 값만 알려 준다. 콘솔 등록까지 확인하지는 못한다.

## 3. 콘솔 등록 (키 관리자가 주소마다 한 번)

**Google Cloud Console → API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트**

- 승인된 JavaScript 원본에 `http://localhost`, `http://localhost:5175`, 배포 주소를 모두 넣는다. 로컬은 포트 있는 주소와 없는 주소가 둘 다 필요하다.
- OAuth 동의 화면이 테스트 상태면 로그인할 구글 계정을 테스트 사용자에 넣는다.

**네이버 개발자센터 → 내 애플리케이션 → API 설정**

- 네이버 로그인 Callback URL 에 `http://localhost:5175/로그인/콜백` 과 배포 주소의 같은 경로를 넣는다.
- 서비스 URL 에 사이트 주소를 넣는다.
- 애플리케이션이 개발 중 상태면 로그인할 네이버 아이디를 멤버관리의 테스트 ID 에 넣는다.

## 4. 실행과 확인

사이트는 `127.0.0.1` 이 아니라 **`http://localhost:5175`** 로 연다. 콘솔에 등록한 주소와 글자까지 같아야 한다.

`.env` 를 바꾼 뒤에는 백엔드와 웹사이트 개발 서버를 다시 켠다.

| 증상 | 확인할 것 |
| --- | --- |
| 구글 단추가 안 보이고 콘솔에 `origin is not allowed` | 3번의 JavaScript 원본, 클라이언트 ID 일치 |
| 구글 창에 `origin_mismatch` | 3번의 JavaScript 원본 |
| 구글 창에 `access_denied` | 구글 테스트 사용자 |
| 네이버 화면에 Callback URL 오류 | 3번의 Callback URL, `NAVER_REDIRECT_URI` |
| 네이버 로그인 뒤 권한 오류 | 네이버 테스트 ID |
| 사이트에 준비 중 안내 | `.env` 값, 서버 재시작 |
