# 왜곡 캐릭터 생성 화면 — UI·UX 재디자인 프롬프트

작성: 2026-09-24. 현재 생성 화면의 코드·저장된 스크린샷·인수인계 문서와 외부 레퍼런스를 확인해 작성했다.

**사용법:** 아래 「전달용 프롬프트」를 그대로 전달한다. 이번 문서는 이미 동작하는 생성 화면을 시각적으로 재편하는 후속 지시다. 이전 구현 프롬프트의 고정 3열·프리뷰 박스·상하단 바 배치보다 이 문서의 디자인 지시를 우선한다. 실제 기능·입출력 계약은 현재 코드를 기준으로 보존한다.

## 전달용 프롬프트

당신은 3D 게임의 캐릭터 생성 화면을 만드는 UI 아트 디렉터이자 React·Three.js 프론트엔드 개발자다. 현재 「왜곡」의 캐릭터 생성 초안은 기능은 갖추었으나, 테두리로 둘러싼 프리뷰·메뉴·설정 패널 때문에 작은 칸들이 모인 설정 도구처럼 보인다. **캐릭터가 서 있는 하나의 연속된 공간을 화면 전체에 펼치고, 그 위에 조작 도구가 가볍게 떠 있는 게임 화면으로 재디자인하라.**

이번 구현 대상은 **캐릭터 생성 화면의 시각 디자인·상호작용·프리뷰 연출**이다. 회원가입, 실제 서버, 오프닝, 튜토리얼, 전체 라우팅은 다른 프론트 담당자의 범위다. 현재 캐릭터와 편집 기능을 유지하면서 구도·빛·여백·타이포그래피·동작을 다시 설계한다.

### 1. 현재 구현을 읽고 보존할 것

먼저 아래 파일과 기존 화면 캡처를 확인하라.

| 파일 | 이번에 다룰 부분 |
|---|---|
| `naju01/src/캐릭터생성/캐릭터생성화면.jsx` | 고정 열 배치를 전면 무대+오버레이로 변경, 카테고리·설정·이름 화면의 계층 재설계 |
| `naju01/src/캐릭터생성/캐릭터프리뷰.jsx` | 전면 Canvas, 배경·조명·그림자·자세·카메라, 축약한 관찰 도구 |
| `naju01/src/캐릭터생성/스타일.js` | 색·폰트·간격·컨트롤 상태·모션 토큰 재설계 |
| `naju01/src/캐릭터생성/미리보기.jsx` | 개발 도구를 기본 접힘으로 변경, 시각 검토용 진입점 정리 |

| `naju01/src/툰재질.js`, `치비게임아바타.jsx` | 프리뷰의 툰 화풍·기존 리깅·신발 보정 확인 |
| `docs/캐릭터생성-인수인계.md` | 현재 props·콜백·실제 지원 범위·검증 결과 확인 |
| `docs/이미지/캐릭터생성/1-기본.png`부터 `4-이름.png` | 변경 전 비교 기준 |

현재는 대부분 인라인 스타일이며, `머리`, `바닥`, `패널`, `갈래칸`, `카드`, `무대`, `아래줄` 같은 스타일 상수가 있다. 실제 코드를 읽고 변경 위치를 결정한다. 존재하지 않는 CSS 선택자를 가정하지 않는다. 필요하면 생성 화면에 한정한 CSS 파일/모듈로 정리해도 된다.

다음 동작은 유지한다.

- 남녀 선택, 성별별 초안, 최초 속옷·맨발, 실제 헤어·의상, 피부·헤어·의상 색상.
- 현재 11개 체형 조절과 검증된 범위. 어깨 하한 1.00·기본 1.20, 팔 길이 기본 0.88 등 실제 기본값을 디자인 편의로 바꾸지 않는다.
- 이미 구현된 신발 착용 시 발 크기 보정. 이전 조사 문서의 ‘신발 크기 조절 미구현’을 이번에 다시 적용하지 않는다.
- 의상은 전신 GLB 교체 방식이다. 모델 예열과 최신 선택 우선 동작을 보존한다.
- 속옷 미리보기와 실제 착장 선택의 분리, 되돌리기·다시 실행·초기화, 한 번의 슬라이더 드래그를 하나의 이력으로 처리하는 방식.
- 이름 입력·중복확인·IME·늦은 응답 무시·오류·완료 중 중복 제출 방지.
- `initialValue`, `catalog`, `nameRules`, `checkName`, `onDraftChange`, `onComplete`, `onCancel` 계약.
- 초안의 `appearance.colors`와 완료 payload의 `supportedColorValues`처럼 현재 구분된 필드를 유지한다. 이름·콜백·payload를 새 디자인에 맞춘다는 이유로 바꾸지 않는다.

### 2. 하나의 명확한 아트 방향

**콘셉트: ‘왜곡 조사관을 맞이하는, 고요하고 깊은 스튜디오’.**

캐릭터 뒤에 넓게 번지는 청회색 빛, 가장자리의 짙은 먹색, 부드럽게 이어지는 바닥, 머리와 어깨를 배경에서 분리하는 은은한 윤곽광으로 공간을 만든다. 뒤쪽 먼 공간에는 약한 빛의 어긋남을 한 곳만 배치해 ‘왜곡’의 분위기를 암시한다. 얼굴과 옷의 색은 정확히 보이고, 시선은 캐릭터 → 현재 편집 항목 → 다음 버튼 순서로 흐르게 한다.

현재 스타일라이즈드 캐릭터의 형태를 살린다. 사실적인 인물로 교체하거나 금속·유리 재질로 바꾸지 않는다. 세계관 장식은 배경의 보조 요소이며, 캐릭터보다 밝거나 선명하지 않게 한다.

디자인 판단 순서는 **구도 → 캐릭터 자세 → 조명과 깊이 → 조작부 계층 → 전환 동작 → 필요한 효과**다. 각 단계가 좋아진 뒤 다음을 얹는다.

### 3. 화면 전체를 연속된 무대로 만들기

기존 `200px / minmax(0,1fr) / 360px` 3열 레이아웃을 그대로 두고 테두리 색만 지우는 방식으로 끝내지 않는다. Canvas와 배경이 컴포넌트의 전체 면적을 차지하고, HUD가 그 위에 놓이는 구조로 바꾼다. 헤더·푸터 뒤에도 같은 배경이 이어져야 한다.

권장 레이어:

```text
캐릭터 생성 루트 — 부모가 준 전체 크기
  배경층: 연속된 그라데이션·아주 약한 공간 연출
  3D층: 캐릭터·접지 그림자·필요한 배경 오브젝트
  대비층: 글자가 놓이는 가장자리에만 옅은 명암
  UI층: 제목 / 좌측 카테고리 / 우측 조절부 / 소형 보기 도크 / CTA
  일시 UI층: 툴팁·팝오버·오류 알림
```

- 중앙 프리뷰에 테두리, 둥근 카드, 별도 불투명 사각 배경을 두지 않는다.
- 화면 전체를 가르는 헤더 하단 선·푸터 상단 선을 제거한다. 상하단은 작고 독립된 요소만 배치한다.
- 왼쪽 카테고리와 오른쪽 도구 뒤로 배경이 이어져 보이게 한다. 큰 상자 세 개의 구조가 인지되지 않아야 한다.
- 오른쪽 도구의 가독성은 화면 가장자리의 부드러운 명암층과 제한된 반투명 표면으로 확보한다. 명암층은 안쪽으로 자연스럽게 사라지게 하고 닫힌 사각 윤곽을 만들지 않는다.
- 입력 필드·선택 썸네일·포커스 표시처럼 조작 의미가 있는 부분에는 경계선을 사용할 수 있다. 화면 영역 전체를 둘러싸는 선과 모든 버튼에 동일하게 반복되는 선을 제거한다.
- 글과 버튼이 없는 빈 공간에서는 캐릭터를 자유롭게 관찰할 수 있어야 한다.

1920×1080 기준의 시작 구도는 아래와 같다. 수치는 시각 검토 후 조절할 설계값이며 외부 게임의 규격을 뜻하지 않는다.

| 요소 | 시작 배치 |
|---|---|
| 가장자리 여백 | 좌우 40~56px, 상하 28~40px |
| 제목 | 좌상단, 28~34px 한글 제목 + 짧은 1줄 설명 |
| 진행 표시 | 상단에 작은 `01 외형 · 02 이름` 텍스트. 큰 단계 카드 제거 |
| 왼쪽 카테고리 | 폭 80~112px, 중간 높이에 아이콘+짧은 한글 라벨 4개 |
| 오른쪽 조절부 | 폭 300~340px, 선택한 내용만 높이에 맞춰 펼침 |
| 캐릭터 중심 | 전체 폭의 약 43~47%. 실제 좌우 UI 점유 면적을 고려해 계산 |
| 전신 크기 | 머리부터 발끝까지 화면 높이 약 70~78%, UI와 겹치지 않게 |
| 관찰 도크 | 캐릭터 아래 안전 영역의 작은 가로 도크 |
| 주요 CTA | 우하단, 화면마다 하나의 가장 강한 행동 |
| 되돌리기 등 | 좌하단의 낮은 강조, 반복 테두리 없이 작은 조작 묶음 |

배경은 UI까지 관통해 이어지지만, 캐릭터 실루엣은 조절부에 가려지지 않게 한다. 이름 단계로 전환할 때에도 같은 무대와 캐릭터 인스턴스를 유지한다.

### 4. 배경·조명·바닥으로 깊이를 만들기

**배경**

- 순수 검정 한 장을 피하고, 어두운 남청색 가장자리→캐릭터 뒤 청회색 빛→바닥의 낮은 밝기로 이어지는 큰 명암 덩어리를 만든다.
- 출발 팔레트: 가장자리 `#080D15`, 중간 `#142432`, 캐릭터 뒤 `#2B4755`, 주 글자 `#F2F4F5`, 보조 글자 `#AAB8C4`, 선택 강조 `#9AD8E8`. 실제 대비·피부색을 보고 조정한다.
- 그라데이션 중심은 화면 정중앙이 아니라 캐릭터의 등·어깨 뒤에 놓는다. 얼굴과 밝은 피부가 배경에 묻히지 않게 밝기를 제한한다.
- 배경을 너무 균일하게 만들지 않도록 큰 반경의 빛 2~3개를 겹치고, 밴딩이 실제 보일 때만 아주 약한 정적 디더/노이즈를 사용한다. 움직이는 필름 그레인을 필수로 넣지 않는다.
- ‘왜곡’ 포인트는 뒤쪽에 어긋난 얇은 빛의 면 또는 희미한 곡면 하나로 제한한다. 캐릭터를 둘러싼 큰 네온 고리, 바닥 격자, 무수한 입자, HUD 숫자는 넣지 않는다.

**바닥과 접지**

- 바닥의 사각형 끝·검은 경계·지평선 꺾임이 화면에 드러나지 않게 한다. 무한 스튜디오처럼 배경과 자연스럽게 이어진다.
- 발 바로 아래의 선명도가 조금 높은 접지 그림자와 주변으로 넓고 흐리게 퍼지는 음영으로 무게를 만든다. 검은 원 하나를 붙인 것처럼 만들지 않는다.
- 낮음 품질에서도 값싼 부드러운 접지 음영은 유지한다. 고급 효과를 꺼도 캐릭터가 떠 보이면 안 된다.
- 실제 모션·체형·신발 변화에 그림자가 맞아야 한다. 움직이는 캐릭터에 정지 그림자를 영구 캐시하지 않는다.

**캐릭터 조명**

- 얼굴과 몸의 형태를 드러내는 중성 주광, 그림자를 조금만 채우는 약한 보조광, 머리·어깨·팔을 배경에서 분리하는 은은한 윤곽광을 구성한다.
- 현재 높은 ambient와 카메라 추종 주광이 만드는 평평한 밝기를 재조정한다. 피부를 하얗게 날리지 않고 얼굴·손·옷의 굴곡이 남도록 한다.
- 회전해도 관찰 가능한 밝기를 유지하되 조명이 모두 카메라에 붙어 완전히 평평해지지 않게 한다. 고정된 공간의 빛 방향과 관찰용 보조광을 구분해 검토한다.
- 어두운 피부·밝은 피부, 검은 머리·밝은 옷 모두에서 실루엣과 색상 차이를 확인한다. 색 선택 시 배경색이 달라져 피부가 다른 색처럼 보이지 않게 한다.
- 기본 편집 조명은 안정적으로 유지한다. 필요하면 관찰 메뉴 안에 ‘연출 조명 / 중성 조명’ 두 모드만 둔다. 둘은 미리보기 설정이며 저장 외형값을 바꾸지 않는다.

### 5. 첫인상과 카메라 연출

- 첫 화면과 이름 확인 화면의 기본 자세를 현재 T에 가까운 `A_TPose`에서 자연스러운 서 있는 자세로 바꾼다. 양팔이 몸통을 가리지 않고 손과 발도 관찰되는 자세를 택한다.
- 기존 대기 클립을 먼저 확인한다. 팔짱·허리에 손을 얹는 자세는 해당 신체 부위를 가릴 수 있으므로 무조건 기본값으로 사용하지 않는다. 적절한 클립이 없으면 프리뷰 전용으로 검증한 편안한 정지 포즈를 만들고, 전체 애니메이션 제작으로 범위를 확대하지 않는다.
- 체형 세부 편집에서는 부위를 보기 쉬운 편집 자세를 사용할 수 있다. 팔·손 편집 시 팔을 조금 벌리는 정도로 시작하고 자세 전환은 부드럽게 처리한다.
- 약한 호흡·무게중심 변화가 실제 지원되면 활용하되, 슬라이더 드래그 중에는 부위가 흔들리지 않게 안정시킨다. 입력을 방해하는 자동 회전은 사용하지 않는다.
- 첫 진입은 500~700ms 정도의 짧은 밝기·구도 정돈으로 끝낸다. 로딩이 끝나기 전에 진행된 카메라 애니메이션 때문에 캐릭터가 튀어나오지 않게 한다. 입력은 연출 종료를 기다리지 않아도 가능해야 한다.
- 기본 렌즈는 현재 30도 FOV 근처의 인물 관찰 구도를 출발점으로 한다. 과도한 광각으로 머리·손·발의 크기가 왜곡되지 않게 한다.
- 헤어 선택은 머리 근처, 손 크기 선택은 손, 의상 선택은 적절한 전신으로 초점을 부드럽게 전환한다. 같은 슬라이더를 움직이는 동안 반복해서 카메라를 당기지 않는다.
- 카메라 자동 이동은 사용자가 회전·확대 조작을 시작하면 중단한다. 일반적인 카테고리 선택만으로 사용자가 잡은 방향을 매번 정면으로 초기화하지 않는다.
- 오른쪽 패널·상단 제목·하단 도크의 실제 크기를 제외한 **관찰 안전 영역**을 계산한다. 현재 카메라의 하단 가림 높이만 고려하는 방식은 전면 오버레이에 맞춰 확장한다. 조절부 폭이 바뀌어도 머리·손·발이 그 뒤에 숨지 않아야 한다.

### 6. UI를 가볍게 만들면서 조작을 분명하게 하기

**좌측 카테고리**

- 기본·체형·헤어·의상의 4개 카테고리를 아이콘+짧은 한글 라벨로 배치한다. 세로 여백과 정렬로 묶고 외곽 박스는 없앤다.
- 현재 항목만 밝은 텍스트, 작은 선택 표시, 부드러운 국소 배경으로 강조한다. 다른 항목은 배경 없이 낮은 대비로 둔다.
- 아이콘은 한 스타일의 단순한 선·형태로 맞춘다. 이모지·잡다한 기호를 섞지 않는다. 라벨을 모두 숨겨 의미를 추측하게 만들지 않는다.

**우측 조절부**

- 상단에 현재 항목명과 1줄 설명, 아래에 필요한 컨트롤만 둔다. 화면 높이를 채우기 위해 빈 패널을 늘리지 않는다.
- 체형은 ‘기본 크기(키·머리·손·발) / 신체 비율 / 체격’으로 나누고 기본 크기를 먼저 펼친다. 접힌 항목은 명확히 열 수 있게 하고 해당 항목의 편집 상태를 유지한다.
- 현재의 모든 슬라이더 옆 `− / + / 초기화` 상자를 같은 강도로 반복하지 않는다. 라벨·값·슬라이더를 기본으로 두고, 미세 조절·초기화는 작고 통일된 보조 조작으로 제공한다. 마우스 hover뿐 아니라 키보드 focus와 터치에서도 접근 가능해야 한다.
- 슬라이더는 얇은 레일과 분명한 핸들, 기본값 표시, 정렬된 현재 값으로 구성한다. 정밀한 클릭 영역과 기존 키보드 조작은 유지한다. 숫자는 흔들리지 않는 폭으로 정렬한다.
- 성별은 하나의 간결한 선택 묶음으로, 피부·헤어색은 깔끔한 색상칩으로 정리한다. 선택은 색 차이만이 아니라 체크·모양·텍스트로도 드러낸다.
- 길게 반복되는 설명은 도움말로 옮기되 실제 오류·사용 제한은 바로 읽을 수 있게 표시한다. ‘뼈·모프·기본 배율’ 같은 내부 용어를 제품 설명에 노출하지 않는다.

**헤어·의상 목록**

- 실제 헤어·옷 썸네일이 먼저 보이고 이름은 아래에 작게 놓인다. 일반 카드는 바탕과 자연스럽게 섞이고 선택한 항목에만 얇은 강조·체크를 준다.
- 현재 한 벌인 의상을 여러 빈 카드로 채우지 않는다. 슬롯 구분과 실제 선택지만 적절한 밀도로 보여 준다.
- 썸네일을 감싸는 중첩 프레임을 없애고 배경·카메라 방향·크기를 통일한다. 필요한 경우 기존 썸네일 도구로 다시 굽되 실제 에셋을 쓰고, 사진이나 생성 이미지로 대체하지 않는다.
- 속옷 미리보기는 옷 선택값을 지우지 않는 토글이다. 이 기능을 유지하면서 설명을 간결하게 정리한다.

**관찰 도구·주요 버튼**

- 전신/머리/손/발 보기와 ‘관찰 옵션’을 작은 도크에 묶는다. 화질·자세·세부 회전·줌 버튼을 지금처럼 15개 가까이 한꺼번에 나열하지 않는다. 보조 메뉴에 옮겨도 기존 기능은 남긴다.
- ‘이름 입력으로’와 ‘캐릭터 생성 완료’는 각각 해당 단계의 유일한 강한 CTA로 만든다. 넓은 호흡, 선명한 대비, 절제된 표면 강조를 사용한다. 지속적인 발광·맥박 효과는 넣지 않는다.
- 되돌리기·다시 실행·초기화는 덜 강조된 보조 조작으로 배치한다. 화면 이동·확정과 같은 강도로 경쟁하지 않게 한다.
- 개발용 가짜 서버 패널은 기본 접힘으로 바꾸고, 열었을 때만 확인 도구로 나타나게 한다. 기본 시각 검토 화면을 개발 패널이 밀어내지 않게 한다.

### 7. 타이포그래피·표면·모션을 하나의 체계로 정리

다음은 시작 토큰이며 실제 화면에서 조정한다.

| 항목 | 방향 |
|---|---|
| 한글 글꼴 | 현재 Pretendard 계열 유지, 일반 UI는 비례폭 글꼴 |
| 제목 | 28~34px, 중간~굵은 두께, 넓은 여백 |
| 항목 제목 | 18~22px |
| 라벨·조작 | 14~16px, 설명은 12~13px 이상 |
| 숫자 | tabular 숫자, 소수점·퍼센트 정렬 |
| 간격 | 4/8/12/16/24/32/48px 계열, 그룹 간 간격을 내부보다 크게 |
| 반투명 표면 | 필요한 툴박스에만 적용, 어두운 틴트+약한 블러 |
| 코너 | 작은 도구 8~12px 정도, 화면 전체를 둥근 카드로 만들지 않음 |
| hover·pressed | 100~160ms, 국소 명도·위치 변화. 확대 폭은 작게 |
| 카테고리 전환 | 180~240ms, 짧은 페이드와 6~10px 이동 |
| 부위 카메라 이동 | 300~450ms, 감속하며 정지 |
| 이름 단계 전환 | 300~450ms, 같은 공간에서 구도·도구만 전환 |

- UI 모션은 `transform`·`opacity` 중심으로 처리한다. 레이아웃 폭을 계속 흔들거나 매 프레임 React 전체 상태를 갱신하지 않는다.
- 큰 배경을 연속해서 blur 애니메이션하지 않는다. `backdrop-filter`는 작은 표면에만 사용하고 지원하지 않는 환경에는 반투명 단색을 제공한다.
- 반투명 효과가 있어도 글자는 선명하게 유지한다. 부모 전체에 opacity를 적용해 글자까지 희미해지게 하지 않는다.
- 사용자 동작 직후 선택 상태는 즉시 바뀌고 시각적 전환만 부드럽게 이어진다. 애니메이션 때문에 클릭 결과가 늦어지면 안 된다.
- 동작 줄이기 설정에서는 카메라 이동·배경 움직임·입장 연출을 줄이거나 생략한다. 상태 변경과 키보드 포커스는 그대로 전달한다.

### 8. 이름 입력도 같은 장면 안에서

- 외형 완료 후 Canvas를 재마운트하거나 전체 화면 모달로 덮지 않는다. 캐릭터가 같은 공간에 남아 있고, 우측 조절 도구만 이름·확인 UI로 전환한다.
- 캐릭터는 자연스러운 자세와 적절한 상반신/무릎 위 구도로 정돈할 수 있다. 외형·착장·선택 시점이 이유 없이 초기화되지 않게 한다.
- ‘당신의 이름을 알려 주세요’와 같은 짧은 제목, 이름 입력, 중복확인, 결과 안내, 완료 CTA만 명확하게 배치한다. 이미 본 외형값을 긴 표로 다시 나열하지 않는다.
- 이름 검사 결과가 나와도 입력칸·CTA가 위아래로 튀지 않게 메시지 자리를 확보한다. 실패 메시지는 읽을 수 있는 대비를 준다.
- 기존 `checkName`·`onComplete`의 로딩·오류·충돌·중복 제출 방지를 그대로 유지한다. 완료 성공은 부모에게 전달하고 이후 페이지 이동은 구현하지 않는다.

### 9. 이 프로젝트에 맞는 렌더링 기법 선택

현재 스택은 React Three Fiber·Drei·Three.js이며 `@react-three/postprocessing`도 설치돼 있다. 사용할 수 있는 효과 중 목표에 도움이 되는 것만 적용한다. 아래 우선순위로 구현하고 효과를 켜기 전·후를 비교한다.

**필수 기반**

1. 전체 화면에 이어지는 배경과 Canvas 합성.
2. 자연스러운 자세와 UI를 고려한 카메라 구도.
3. 툰 모델의 형태를 살리는 주광·보조광·윤곽광.
4. 부드러운 접지와 배경의 큰 명암.
5. 명확한 글자·컨트롤 상태와 짧은 전환.

**필요할 때 선택**

- 저비용 배경 그라데이션 셰이더 또는 CSS 다중 radial gradient.
- 먼 배경 오브젝트에만 아주 느리고 작은 이동. 편집 중에는 눈에 띄지 않게 한다.
- 빛나는 배경 요소에 한정한 약한 bloom. 얼굴·흰 옷·UI까지 번지면 끈다.
- 국소 UI blur, 아주 약한 가장자리 명암, 필요한 수준의 안티앨리어싱.
- 측정 결과에 따른 DPR·그림자 해상도·장식 효과 단계 조절.

**현재 구현에 반드시 반영할 기술 제약**

- `캐릭터프리뷰.jsx`의 `gl.setClearColor(..., 1)`은 불투명해서 아래 CSS 그라데이션을 가린다. 기본안은 투명 Canvas+하부 배경+투명한 접지 표현이다. 이 방식을 택하면 WebGL 알파와 clear alpha, scene background, 그림자 재질을 함께 맞춘다. 공간 오브젝트상 전체 WebGL 배경이 더 적합하면 그 안에서 배경을 일관되게 구현한다. 서로 다른 배경을 겹쳐 색 경계가 드러나는 상태로 두지 않는다.
- 후처리를 넣을 경우 알파가 유지되는지 검증한다. 효과를 켰더니 검은 사각형이 생기거나 하부 그라데이션이 사라지면 합성부터 고친다.
- 현재 아바타는 `MeshToonMaterial`과 자체 툰 셰이더를 사용한다. `툰재질.js`는 원본 PBR의 normal·roughness·metalness·env를 의도적으로 사용하지 않는다. 따라서 HDRI·Lightformer를 추가했다고 현재 피부와 옷에 PBR 반사가 자동으로 생긴다고 가정하지 않는다. 생성 화면 전용 툰·윤곽 설정과 실제 조명으로 형태를 조정한다.
- 피부색·흰 옷의 색이 망가지지 않도록 sRGB 입력·출력과 톤매핑을 점검한다. 기존 렌더러와 composer에 톤매핑·감마 변환을 중복 적용하지 않는다. Three 기본 후처리와 pmndrs 후처리의 처리 방식을 혼용하지 않는다.
- 편집 캐릭터에는 강한 피사계심도, 모션 블러, 색수차, 왜곡 렌즈를 기본으로 적용하지 않는다. 세부 형태를 보기 어렵게 만드는 효과는 이 화면의 목적과 맞지 않는다.
- ray tracing, path tracing, 실시간 SSR, WebGPU 이전을 이번 디자인의 선행 조건으로 삼지 않는다. 현재 브라우저 스택에서 충분한 구도·조명·레이어 품질을 만든다.
- `ContactShadows` 등은 움직임·모프·모델 교체 후에도 맞아야 한다. 정지 때 캐시한다면 변경 시 갱신 경로를 함께 구현한다. 모션이 재생 중인데 `frames=1`만 사용하면 안 된다.
- 전체 화면이 되어 픽셀 수가 늘어나는 점을 고려한다. 기존 `preserveDrawingBuffer`가 운영 프리뷰에도 필요한지 확인하고, 캡처 도구 때문에만 필요하면 캡처 경로로 한정한다.

### 10. 조작 충돌·반응형·성능

- Canvas는 생성 화면 루트의 `absolute/inset:0` 레이어로 배치한다. 다른 프론트에 삽입할 때 전체 문서의 레이아웃을 강제로 점유하는 전역 fixed UI를 만들지 않는다.
- UI 오버레이의 빈 공간은 관찰 조작을 가로막지 않게 한다. 실제 버튼·패널·슬라이더에서는 포인터와 휠을 정확히 처리해 카메라까지 전달되지 않게 한다. 전체 wrapper에서 모든 이벤트를 잡는 현 구조를 함께 점검한다.
- 슬라이더 드래그, 우측 목록 스크롤, 색상 선택 중에는 캐릭터가 회전·확대되지 않아야 한다. 팝오버를 닫은 뒤 포커스가 호출 버튼으로 돌아오게 한다.
- 1280×720에서는 여백·좌측 내비 폭·우측 도구 폭을 조절한다. 화면 전체를 축소해 글자를 작게 만들지 않는다. 조절 목록만 필요할 때 스크롤된다.
- 작은 화면에서는 카테고리를 가로 도크, 조절부를 높이가 제한된 하단 시트로 옮긴다. 캐릭터는 시트 위 관찰 영역에 다시 구도 잡는다. 이름 입력 시 화면 키보드도 고려한다.
- 클릭 표적은 시각적으로 작은 아이콘보다 넓게 확보한다. 키보드 포커스 링, 라벨, 방향키/Home/End 슬라이더 조작을 유지한다. 주 조작을 hover에서만 발견할 수 있게 하지 않는다.
- 평균적인 테스트 환경에서 부드러운 조작을 목표로 하되 측정 없이 프레임 수를 보장하지 않는다. 저사양에서는 장식·blur·bloom·그림자 해상도부터 줄이고 외형 조절 반응·글자·접지는 유지한다.
- demand 렌더링은 장면이 정지했을 때만 적용하고, 모션·카메라 보간·모프가 움직일 때는 필요한 프레임을 요청한다. 비활성 탭에서 렌더링을 멈추는 기존 동작을 보존한다.

### 11. 실제 작업 순서와 완료 기준

먼저 현재 화면을 동일한 해상도로 캡처한다. 그리고 다음 순서로 진행한다.

1. **전면 무대와 오버레이:** 큰 프리뷰 프레임·전폭 구분선·3열 박스 구조를 제거한다.
2. **캐릭터의 첫인상:** 자연스러운 포즈, 크기와 위치, 피부·헤어·옷의 조명, 발 접지를 맞춘다.
3. **조작부 재구성:** 카테고리, 접히는 세부 항목, 썸네일, 소형 도크, 단계별 CTA를 다듬는다.
4. **배경 깊이와 전환:** 기본 구도가 완성된 뒤 필요한 효과를 얹는다.
5. **기능 회귀·시각 검토:** 아래 기준을 확인하고 실제 화면에서 반복 수정한다.

필수 시각 검토 장면:

- 1920×1080과 1280×720의 기본 전신 화면.
- 체형 조절, 손·발·헤어 근접 보기, 의상 선택.
- 밝은 피부/어두운 피부, 밝은 옷/어두운 옷, 남성/여성.
- 이름 입력, 검사 실패, 완료 중 상태.
- 작은 화면과 효과를 줄인 품질 설정.

디자인 합격 기준:

- 첫 화면에서 캐릭터와 하나의 공간이 먼저 보인다. 캐릭터를 둘러싼 큰 사각 프레임이 없다.
- 상하·좌우 배경이 이어지고 바닥 끝·Canvas 검은 사각형·패널 경계가 공간을 자르지 않는다.
- 오른쪽 도구를 읽을 수 있으면서도 캐릭터 실루엣과 부위 편집을 가리지 않는다.
- 카테고리·선택값·주요 CTA의 강약이 분명하다. 모든 버튼이 같은 모양과 강조를 갖지 않는다.
- 첫 화면에서 T자 자세가 기본 인상으로 남지 않는다. 체형 편집 자세는 관찰 목적에 맞는다.
- 화면 전환 후 같은 캐릭터가 같은 공간에 이어진다. 모델·카메라·사용자 초안이 불필요하게 초기화되지 않는다.
- 고급 효과를 꺼도 구도·가독성·깊이가 유지된다. 눈에 띄는 효과가 부족한 디자인을 대신하지 않는다.

기능 검증은 기존 `naju01/도구/캐릭터생성검사.mjs`와 관련 빌드·검사를 활용한다. 버튼 위치나 DOM 구조가 바뀌면 테스트를 의미 있는 역할·라벨 기준으로 갱신하고, 기존 기능 검사를 삭제해서 통과시키지 않는다. 새 입력 레이어 때문에 생길 수 있는 **UI 드래그→카메라 오작동**, **팝오버 키보드 포커스**, **카메라 안전 영역**을 특히 확인한다.

최종 결과는 실행되는 화면과 함께 **동일 조건의 변경 전·후 캡처, 적용한 디자인 원칙, 유지된 기능·콜백, 측정한 성능·품질 조건, 남은 제약**으로 보고한다. 코드가 빌드된 것만으로 디자인 완료라고 판단하지 말고, 실제 화면을 열어 위 기준에 맞는지 확인하라.
