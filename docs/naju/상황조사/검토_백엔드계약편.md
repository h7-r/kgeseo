# 검토 — 백엔드 계약 편 (2026-11-06)

「상황을 잘게 다 살리자」는 플레이어 편에 맞서, 계약 v0.4.16 으로 **실을 수 있고 · 승인할 수 있고 · 운영할 수 있는** 분류로 깎은 안이다. 코드는 읽기만 했다. 퍼즐 정답 값은 적지 않았다.

- 항목 표기: `1:` 1스테이지 · `2:` 2스테이지 · `굴:` 물굴 · `3:` 능선 · `대:` 대화_끊김_오류 보고서. 예) `2:C01` · `굴:문-11` · `3:C-16` · `대:H4`.
- 코드 근거는 `파일:줄`. `dialogue/…` = `naju01/src/dialogue/…`, `be/…` = `backend/app/…`. `dialogue/*` 는 조사 중에도 바뀌어 줄이 1~2 밀릴 수 있다.
- 「변경안」이라고 적은 것만 계약 · 스키마에 지금 없는 것이다. 그 밖의 필드는 전부 지금 있는 것이다.

## 6. 반대편에 보내는 반박 5줄

1. **잘게 가를수록 틀린 대사가 나간다.** FE 는 버린 것과 안 주운 것(3 §13 ⑤), 너무 이른 것과 줄이 틀린 것(1 §9-10)을 지금도 못 가른다. 못 가르는 것을 코드로 가르면 「두고 가네요」가 한 번도 안 주운 열쇠에 붙는다.
2. **가르는 일은 코드가 아니라 `focus_object_id` 가 한다.** P11 의 다섯 걸음은 코드 다섯이 아니라 `NO_PROGRESS` 하나에 초점 Object 다섯이다(3-1 · 3-8). 코드는 10개로 두고 문장은 걸음마다 다르게 낼 수 있다.
3. **플레이어를 가장 많이 살리는 것은 대사가 아니라 침묵이다.** 듣는 중 · 세는 중 · 연출 중 오판이 네 보고서에 다 있다(1 §9-3, 2 겹침 1 · 2 · 7, 굴 §12-5 · 7, 3 §13 ③). 표시 조건으로 「안 보내기」를 넣는 데는 계약도 승인도 필요 없다.
4. **게임이 이미 말한 것을 동행이 또 말할 필요가 없다.** 「먼저 …부터」 · 「소지품이 가득 찼다」 · 「가시에 찔렸다」는 알림이 하고 동행이 제 말투로 읽는다. 여기에 코드를 붙이면 같은 말이 두 번 나온다(대:M8). 빈 곳은 알림이 없는 13항목이고 그건 게임 코드로 메운다(2-(c)).
5. **급한 정도는 코드를 늘리지 않고 「같은 코드를 다시 보내기」로 살린다.** 숨은 코드 둘이 아니라 `BREATH_LOW` 를 20초 · 10초에 두 번 보내고(쿨다운 8초) 서버가 돌아가며 다른 문장을 준다. `value`(남은 숨 · 누적 횟수)는 기록에 남아 기준을 고칠 근거가 된다 — `value` 로 문장을 고르는 것은 지금 계약에 없으니 기대하지 않는다. 코드 40개는 코드마다 3줄만 잡아도 한 벌 120줄(어림)과 쿨다운 40벌이다.
