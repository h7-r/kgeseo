# 나주(앙암바위) 퍼즐 대응표 — 2026-11-05

11/4 확정 규칙(P번호가 공식 ID · 값 판정 = 서버 · 손맛 판정 = 화면)에 FE 상호작용 ID 를 붙인 것.
FE 상호작용 ID 는 `naju01/src/puzzles/*` 가 `registerInteractable` 에 넣는 **로컬 id** 다(idmap 초안의 `OBJ_…` 런타임 ID 는 BE 쪽 대응표가 맡는다).
정답 값은 여기에 없다(따로 전달).

## 분리·단일 기준
- **P02 → P02 + P02-2.** 통발 고르기(어느 통발을 넣을지 = 값)는 서버, 줄 당기기 게이지 3판은 화면.
- **P13 → P13 + P13-2.** 걸상 밟는 차례(5 순서 = 값)는 서버, 돌새 둘을 45° 씩 돌려 마주 보게 하는 건 화면.
- **P09 는 단일.** 서버는 고리 셋의 숫자만 판정한다. 물레 돌리기(E 꾹)는 입력 수단일 뿐이고, 뜬 돌 4 · 톱니돌 3 이 다 꽂혀야 돌릴 수 있게 FE 가 막는다. 별도 P09-2 없음.
- 판정이 없는 것은 퍼즐로 등록하지 않는다(아래 「퍼즐 아님」).

## 세진 님과 맞춘 것(11/5)
1. **물굴 Zone** — 별도 Zone 으로 나눈다. 제안 ID 는 `ZONE_RIVER_CAVE_HALL`(P07 · P08 · P09), `ZONE_RIVER_CAVE_INNER`(P10). 최종 ID 는 PM 확인 대기.
2. **P08** — 화면 판정(`client_skill`). FE 가 성공을 확인하면 `complete` 를 보낸다.
3. **Item 표시 이름** — 톱니돌 · 푸른 눈물. 내부 ID 는 기존 서버 Item 과 호환을 보고 세진 님이 정한다.

## 아직 정할 것: P13 제출
- **대표 Object** — `ridge-platform-story` 를 쓴다. 평상 글이 다 드러나야 걸상을 밟을 수 있어서, 제출 시점에는 항상 활성 상태다. 플레이어가 이 Object 에 E 를 누르지 않아도 FE 가 이 ID 로 제출한다.
- **값 형식** — 걸상 번호 0…4 는 z 가 작은 쪽(남)에서 북으로 매긴 차례라, 걸상 배치가 바뀌면 번호도 바뀐다. 기호(해 · 달 · 물결 · 새 · 불) 5개를 제출하는 안을 제안한다.
- **판정 시점** — 지금 FE 는 정답을 코드에 들고 한 발마다 판정해서, 틀리면 바로 전부 꺼진다. 서버로 옮기려면 5개를 모아 한 번에 제출하고, 틀리면 5개째에 꺼지게 바꾸는 안을 제안한다. 이 경우 한 발마다 오는 반응이 사라진다.
