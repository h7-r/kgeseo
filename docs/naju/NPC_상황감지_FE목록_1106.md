# 나주 동행 NPC — FE 가 감지하는 상황 목록 (2026-11-06)

계약 v0.4.16(상황 감지는 FE · 대사 선택과 횟수 · 쿨다운은 BE)에 맞춰, **지금 FE 감지 코드가 실제로 내는 상황**을 정리한 문서다.
1~3절의 「FE 이름」은 코드 안에서 쓰는 이름이다. 서버에 보낼 상황 코드는 5절에 적었다 — **2026-11-06 계약 v0.4.16 §9 로 11개가 확정됐다**(쿨다운 · 분량 같은 숫자만 🟡 조정 중).

- 감지 코드: `naju01/src/dialogue/situations.ts`(판정 규칙) · `naju01/src/dialogue/gameObserver.ts`(게임 상태 읽기)
- 0.5초마다 게임 상태를 읽기만 한다. 걷는 중(마우스 잠금)이 아니거나 연출 · 종이 읽기 · 힌트함이 떠 있으면 시간을 세지 않는다.
- 검사: `node --test naju01/tests/dialogue.test.ts`

## 1. 상황

| FE 이름 | 뜻 | 조건(지금 값) | 대상 |
| --- | --- | --- | --- |
| `arrive` | 그 목표 앞에 처음 섰다 | 목표가 처음 「지금 목표」가 됐을 때 1회 | 목표 |

| `astray` | 목표에서 멀어진다 | 목표 반경 밖에서 다가오지 않고 18초 · 45초(2회까지). 3m 넘게 다가오면 다시 셈 | 목표 |

| `idle` | 한참 아무것도 하지 않는다 | 움직임(0.6m) · 진전 없이 150 · 330초(2회까지) | 목표(없을 수 있음) |
| `breath` | 물속에서 숨이 얼마 안 남았다 | 남은 숨이 20초 아래로 처음 떨어질 때 1회. 40초 위로 찬 뒤 또 떨어져야 다시 | 목표(없을 수 있음) |
| `sentBack` | 숨이 다해 되돌려졌다 | 「숨이 다했다」 알림이 뜰 때마다 1회(연출 중이면 끝난 뒤) | 목표(없을 수 있음) |
| `solved` | 풀었다 | 끝낸 목표가 새로 생김(이어 하기로 이미 풀려 있던 것은 제외). 연출 중이면 끝난 뒤 | 목표 |
| `chatter` | 한동안 아무 말도 없었다 | 동행이 90초 말이 없었고 곧 `stuck` 을 물을 참이 아닐 때 | 없음 |
| `missing` | 필요한 물건 없이 그 자리에 왔다 | 목표 자리 안에 6초 머물렀는데 가져와야 할 물건이 소지품 · 손에 없음, 물건마다 1회 | 목표 |

화면 쪽에서 따로 알아채는 것(위 판정 밖):

| FE 이름 | 뜻 | 조건 |
| --- | --- | --- |
| 진행 수 | 하나씩 채우는 퍼즐에서 하나 더 해냈다 | 안내판의 「n / m」이 오름(m ≤ 6 쯤, 빠르게 오르내리는 줄은 제외) |
| 게 물림 | 조개 구멍에서 게한테 물렸다 | 조개 캐기 안내판의 「꼬집힘」 수가 오름 |
| 말 걸기 | 플레이어가 [F] 로 말을 걸고 보기를 골랐다 | 여기서 뭘 해야 해요 / 힌트를 주세요 / 괜찮아요(말투 바꾸기는 베타에서 끈다 — §9) |

급하지 않은 상황(`stuck` · `wrong` · `overtime` · `astray` · `idle` · `chatter`)은 지금 FE 에서 35초 간격을 둔다.
횟수 · 간격을 BE 가 맡게 되면 이 FE 쪽 제한(위 표의 「n회까지」 · 35초)은 빼거나 「보내는 빈도 상한」으로만 남긴다.

## 3. 틀림 · 풀림을 알아채는 법(한계)

퍼즐 쪽에 「틀렸다 / 풀렸다」를 알리는 장치가 없어, 이미 화면에 뜨는 알림 문장의 첫머리와 안내판 숫자로 알아챈다(`gameObserver.ts` 의 `NOTICE_SIGNS`).
퍼즐 문장을 고치면 이 표가 어긋난다. 세진 님 PR 이 들어가 퍼즐 파일을 고칠 수 있게 되면 퍼즐이 직접 알리게 바꾼다.

- 실수를 세는 목표: P01 · P02 · P05 · P08 · P09 · P10 · P11 · P13 · P13-2
- 실수를 못 세는 목표(진전 없음 · 시간 초과로만 본다): P02-2(게이지) · P03(항아리) · P07(빛 잇기) · P12(장승 고리)
- 물굴 퍼즐(P07 · P08 · P09 · P10)의 풀림은 알림 문장으로만 안다.

## 4. 지금 구현과 계약 v0.4.16 의 차이(바꿀 것)

지금은 FE 가 대사까지 고른다(`director.ts` — 도움말 칸 · 풀림 · 끝 횟수를 세고 `lines.ts` 에서 고름). 계약 §1 과 맞지 않는다.
`director.ts` 를 「상황을 auto 턴으로 보내고, 받은 reply 를 띄우기만」으로 바꾸고 아래를 FE 에서 뺀다.

- 도움말 사다리 칸 세기, 풀림 · 끝 횟수 세기
- `pickLine` · `pickGeneral` · `ownLines` 로 대사 고르기
- 상황별 횟수 제한과 간격(표의 「n회까지」 · 35초)

지금 할 수 없는 까닭과 순서:

1. 보낼 창구(세션 · NPC 턴 호출)가 세진 님 통합 PR(`naju01/src/companion/`)에 있다. main 에 들어온 뒤 그 위에 붙인다.
2. `focus_object_id` · `zone_id` 는 대응표(11/9 확정 예정)가 있어야 채운다.
3. 그때까지 `lines.ts` 의 대사는 개발용 미리보기이자 npc.json 초안이다. 감지한 상황을 계약 코드로 바꾸는 곳은 `naju01/src/dialogue/situationCodes.ts` 한 곳으로 모아 뒀다.

## 6. §9 로 정해진 것과 아직 열린 것

### 확정(§9)

1. **걸음 대사의 자리** — `situations[].lines[]` 에 `focus_object_id` 를 붙여 싣는다. 코드는 `STEP_ARRIVED`, 걸음 12개에 각 1~2줄.
2. **글 속의 바뀌는 자리** — 고정 문장이다. 이름 · 수 치환이 없다. 「남은 수」처럼 바뀌는 값은 FE 문구가 맡는다(`lines.ts` 의 대사에 `{…}` 가 없는지 검사가 본다).
3. **말투** — 해요체 존댓말 한 벌(「함께 다니는 동료의 존댓말」). 말투 묻기 · 바꾸기는 베타에서 끈다. 반말 초안은 보관만 한다.
4. **대화 진행 문구** — 인사 · [F] 보기 · 「더 알려 드릴까요?」 · 「알겠어요」는 FE 고정 문구이고 G3 대상이 아니다. 「여기서 뭘 해야 해요?」의 답도 여기 든다: 안내판 설명 → 걸음 첫 설명 대사 → 둘 다 없는 목표 일곱은 「무엇을 하는 곳인가」 한 줄(`lines.ts` 의 `WHAT_TO_DO`).
5. **퍼즐 설명과 진행 알림** — FE 문구다(약 175줄). 동행 말투로 보여 줘도 G3 가 아니라 퍼즐 검수(G2)와 게시 검사로 본다.
6. **`QUIET`** — 코드다. 잡담은 `general_nudges[].lines[]` 에 두고 줄마다 선택 필드 `zone_id` 를 단다. FE 는 `QUIET` 에 `situation.zone_id` 를 꼭 싣는다. 나주 잡담 15개(공통 3 + 구역 12)는 G3 대상이다.

### 아직 열린 것

1. **`focus_object_id` · `zone_id` 의 값** — 11/9 나주 대응표의 Object · Zone ID 를 기다린다. 그 전까지 FE 는 화면 쪽 ID(`focusLocalId` · `zone`)로 짝지어 둔다. 겨눌 대상이 없는 걸음 다섯(`S1_FIRE` · `S1_SMOKE` · `S2_ENTER` · `S3_GO` · `S3_RIFT`)은 화면 쪽 ID 도 없어, 대응표에서 대표 Object 를 받아야 서버가 가를 수 있다.
2. **숫자 🟡** — 코드별 쿨다운과 분량, 쿨다운을 코드로만 셀지 코드 + `focus_object_id` 로 셀지(분류표 C4).
3. **걸음의 도움말 줄** — 걸음 대사 18줄 가운데 15줄은 [F] 로 청할 때 주던 도움말이고, 도착 때 하던 첫 설명은 3줄뿐이다. `STEP_ARRIVED` 아래 함께 실으면 서버가 도착 때 돌려 고르면서 도움말이 먼저 나올 수 있다. 도착 때는 첫 설명만 나가게 할 길(줄의 차례 고정 등)이 필요한지.
4. **물 밖 세 구역의 나주 잡담 3줄** — 한 구역에 묶이지 않아 `zone_id` 를 비워 뒀다. 비운 줄을 서버가 「어디서나」로 읽으면 물굴에서 강바람 이야기가 나온다. 구역마다 따로 실을지 정해야 한다.
5. **퍼즐 앞에 처음 섰을 때** — FE 판정은 퍼즐에도 `arrive` 를 내고 지금은 같은 `STEP_ARRIVED` 로 옮긴다. §9 의 뜻은 걸음이라, 보낼 때 걸음만 남길지 정한다(퍼즐의 첫 설명 5줄은 퍼즐 넛지로 분류돼 있다).
6. **갇힘 · 넘어감으로 끝나는 걸음의 `STEP_DONE`** — 능선에 갇히는 순간(`S3_GO`)과 틈을 넘는 순간(`S3_RIFT`)에도 풀림이 나간다. 뺄지는 §9 에 없다.
7. **빠져서 되돌려짐** — `SENT_BACK` 의 뜻에 들지만 게임이 알림도 값도 내지 않아 못 본다. 퍼즐 · 이동 파일 동결이 풀린 뒤에 신호를 받는다.
8. **플레이어가 고른 보기** — 「힌트를 주세요」를 `player_message` 로 보낼지(문구 고정)는 §9 에 없다.
9. **보내기 자체** — FE 는 아직 대사를 직접 고른다(4절). auto 턴으로 바꾸는 일은 세진 님 통합 PR 뒤다.
