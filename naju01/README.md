# NAJU-01 그레이박스 — 작업 공간

「NAJU-01 공간 설계 통합본 v3」의 **A-01 마스터 블록 평면을 그대로 세워, 1인칭으로 걸어보는** 작업 공간입니다.
문서 §7 「할 일」의 5번 — *그레이박스 → 박스만 놓고 1인칭으로 걸어보기* — 에 해당합니다.

## 실행

```bash
npm install          # 저장소 뿌리에서 한 번 (본편과 같은 패키지를 같이 씁니다)
npx vite naju01      # http://localhost:5174
```

본편(`npm run dev`, 5173)과 **동시에** 띄워 놓고 번갈아 볼 수 있습니다. 본편 기차의 텔레포트도 5173 안의 `/naju01/` 로 넘어옵니다.
빌드는 `npx vite build naju01` (결과는 `naju01/dist-naju01/`, 깃 무시됨), 빌드본 보기는 `npx vite preview naju01`. 타입 검사는 `npx tsc -p naju01`.
빌드본에는 `/__naju-edit` 가 없어서 빌드할 때 `assets/edits.json` 을 `naju-edit.json` 으로 같이 내보내고, 빌드본은 그 파일로 손 배치를 읽습니다.
발표는 빌드본이 가볍습니다(HMR·미압축 모듈·개발용 검사가 빠짐).

첫 진입 때는 손 배치·구운 모형 다섯을 **먼저 받고**(로딩 덮개) 씬을 세웁니다(`src/app/prefetch.ts`). 구운 지형은 일부러 늦게 켭니다 — 손 배치가 「해석 지형으로 선 뒤 구운 땅이 도착하는」 순서의 생성 번호로 남아 있어서입니다.
naju01 의 `main.tsx` 는 StrictMode 를 씌우지 않습니다 — 개발 모드에서 씬의 memo·effect 가 두 번 돌아 첫 진입이 두 배로 무거워집니다.

### 발표 프리셋 (주소 스위치)

Leva 저장값 위에 얹히므로 어느 브라우저에서든 같은 화면이 나오고, 떼면 원래 화면입니다. 값은 `src/app/presentation.ts`.

| 주소 | 하는 일 |
|---|---|
| `?present` | 꾸미기 패널·계기판·이름표·격자·조사점 표식·단면선 끔 |
| `?present=light` | 위 + 원경·수풀 밀도와 그림자 범위 줄임, 물 그림자 수신 끔, 해상도 상한 1.5·MSAA 2 |
| `?present=minimal` | 위 + 바닥결·물잔결까지 끔(비상용 — 땅이 단색이 됨) |
| `&mood=evening` · `&mood=night` | 로비처럼 어두운 바탕 + 낮은 해 하나(하늘돔 끔·안개 당김). 따로 써도 됨 |

## 조작

`T` 시작 · `WASD` 이동 · `Shift` 달리기 · `Space` 점프 · `C` 앉기 · `V` 1·3인칭 전환 · `E` 편집 모드 · `ESC` 나가기
3인칭에서는 마우스를 돌려 캐릭터의 앞·뒤·옆을 자유롭게 볼 수 있습니다.
`1` `2` `3` → **V1·V2·V3 시점으로 이동** (개발용 검증 장치입니다. 게임 기능이 아닙니다 — §0.4 텔레포트 금지와 무관)
`H` 계기판 숨기기 · `?stage=16x9` 본편과 같은 16:9 무대 · 절벽에서 떨어지면 마지막 안전 지점으로 복귀

화면 왼쪽에는 **캐릭터 꾸미기 패널**(동작·체형·헤어·의상·색·애니풍·외곽선)이 뜨고, 그 오른쪽에 **도면 계기판**(좌표·고도·구간 거리·fps·§9 미결값)이
`H` 로 열립니다(처음엔 접혀 있고 「[H] 누르면 계기판이 열립니다」 안내가 뜹니다). 맵 위에는 구역·통로·씬 요소 **이름표**가 뜹니다. 발표 프리셋(`?present`)에서는 셋 다 숨깁니다.
조작 안내 문구와 시점 V1~V3 표식은 `?dev` 일 때만 뜹니다.
나주맵은 Leva 패널을 띄우지 않습니다. 아래 §9 미결값은 `plan/sitePlan.ts` 의 `TUNABLE_RANGES` 기본값으로 정합니다.

## 도면 → 좌표 (검산 완료)

| | 실측(좌표에서 다시 계산) | 도면 |
|---|---|---|
| T1 `Z1→Z2` 바위틈 | 9.50 m · 0° | 9.5 m · 수평 |
| T2 `Z2→Z4` 강변 우회 비탈 | 15.14 m · 27.9° | 15.1 m · 27.9° |
| T3 `Z4→Z3` 북측 스위치백 | 22.50 m · **14.9°** | 22.5 m · **15.5°** ← 도면 쪽이 어긋남(아래) |
| T4 `Z3→Z1` 서측 하강로 | 28.41 m · 26.2° | 28.0 m · 26.6° |
| 고리 1바퀴(수평) | **75.5 m** | 75.1 m |
| 고리 1바퀴(경사 포함 실보행) | **81.6 m** · 1.8 m/s 로 45초 | — |

- 네 통로의 시작·끝이 모두 **맞는 구역·맞는 고도**에 붙습니다.
- 최대 경사 **27.9°** — 0단계 규칙 `≤ 30°` 충족.
- 차단물(B1·B1b·B2·수목대·B3)이 통로를 막지 않습니다.
- 계기판이 이 값을 실시간으로 다시 계산해 도면 값과 나란히 보여줍니다. 어긋나면 빨갛게 뜹니다.

좌표는 도면(1 m = 12 px)에서 읽었습니다. X 0→80, Z 0→50(도면 아래쪽 = 강 쪽), Y = 고도.
**1 유닛 ≈ 0.30 m** — 본편 규약 그대로입니다(`src/engine` 의 조작 상수가 이 축척 기준).

### T3 각도는 도면 표가 스스로 어긋나 있습니다

`연장` 을 무엇으로 보느냐가 통로마다 다릅니다.

| | 낙차 | 연장 | 도면 각 | atan(낙차/연장) | asin(낙차/연장) |
|---|---|---|---|---|---|
| T2 | 8 m | 15.1 m | 27.9° | **27.9°** ✔ | 32.0° |
| T4 | 14 m | 28.0 m | 26.6° | **26.6°** ✔ | 30.0° |
| T3 | 6 m | 22.5 m | 15.5° | 14.9° | **15.5°** ✔ |

T2·T4 는 `연장` 이 **수평 거리**인데 T3 만 **빗변**입니다. 좌표(22.50 m)는 도면과 정확히
맞으므로 **좌표는 건드리지 않았고**, 계기판은 다른 통로와 같은 규칙인 14.9° 를 띄웁니다.
→ **§7 0단계에서 도면 표 쪽을 고치는 것**이 맞다고 봅니다. `≤ 30°` 규칙에는 영향이 없습니다.

## §9 미결값 조절 장치

문서 §9 가 「가정」·「검증용」이라고 적어 둔 값들을 **걸으면서 그 자리에서 돌려 볼 수 있게**
했습니다. §7 0단계(눈높이·걷기 속도·FOV·통로 최소폭 확정)를 이 화면 안에서 끝내자는 것입니다.

| Leva 손잡이 | 범위 | 무엇을 정하나 |
|---|---|---|
| `절벽높이` | 6~22 m | §3 — 「아래 사람이 사람으로 보이는 높이」 |
| `차단물높이` | 0.4~2.5 배 | §4 — 도면에 없는 값. 시야가 끊기는 최소치 |
| `눈높이` | 1.2~2.2 m | §9 — 문서 1.6 / 본편 1.95 중 무엇으로 갈지 |
| `FOV` | 45~90° | §9 |
| `걷기속도` | 1.0~3.5 m/s | §9 — 문서 가정 2.5 / 본편 1.8 |

계기판 아래쪽에 「§9 미결값」 칸이 생겼고, **도면 기본값과 다른 값은 노란색**으로 뜹니다.
지금 보고 있는 게 도면대로인지 돌려 본 상태인지 헷갈리지 않게 하려는 것입니다.

### 절벽 높이는 혼자 움직이지 않습니다

`절벽높이` 는 곧 **Z3 의 고도**입니다. 그래서 손잡이를 돌리면 이것들이 **같이** 따라 움직입니다.

```
절벽높이  →  Z3 고도  →  T3 끝 고도 (Z4 +8 → Z3)   → T3 경사
                     →  T4 시작 고도 (Z3 → Z1 0)  → T4 경사
                     →  Z3 위에 선 B2·수목대의 바닥
                     →  절벽면 실각 (배터 띠 4 m 는 그대로라 높이만큼 서진다)
```

이 연동 덕분에 **「높이를 올리면 무엇을 잃는가」가 그 자리에서 보입니다.**

| 절벽 높이 | T3 경사 | T4 경사 | 절벽 실각 | 0단계 규칙 `≤ 30°` |
|---|---|---|---|---|
| 10 m | 5.1° | 19.4° | 68° | OK |
| 12 m | 10.1° | 22.9° | 72° | OK |
| **14 m (도면)** | 14.9° | 26.2° | 74° | OK · 여유 2.4 m |
| 16 m | 19.6° | 29.4° | 76° | OK (아슬아슬) |
| **16.4 m** | 20.6° | **30.0°** | 76° | **여기가 천장** |
| 18 m | 24.0° | 32.4° | 78° | ✗ T4 위반 |

> **찾은 것 — 절벽을 16.4 m 보다 높일 수 없습니다.**
> T4(서측 하강로)가 절벽 높이를 그대로 28.41 m 안에서 내려와야 해서, 16.4 m 를 넘는 순간
> 0단계 규칙 `≤ 30°` 를 어깁니다. 즉 §3 의 「절벽 높이는 아직 미정」은 사실
> **6~16.4 m 안에서만 미정**이고, 그 위로 가려면 T4 를 더 길게 돌리는 **도면 수정이 먼저**입니다.
> 계기판의 T4 줄이 빨갛게 변하는 지점이 바로 이 천장입니다.

> **Leva 로 돌린 값은 내 브라우저에만 저장됩니다**(팀 규칙 §6). 팀에 전달하려면
> `plan/sitePlan.ts` 의 `TUNABLE_RANGES` 기본값을 고쳐서 커밋합니다. 본편 공용 모듈(`src/engine`)은 고치지 않고,
> 걷기 속도는 인자로만 덮어씁니다.

## 손 배치 — 요소별 편집기

나무·덤불·돌·소품은 모양 한 종류당 `InstancedMesh` 하나로 그립니다. 드로우콜은 싸게 유지하면서
광선이 `instanceId` 를 돌려주므로 「몇 번째 물건」을 집어 옮기고 지울 수 있습니다.
표본은 **지름 1 · 밑동 원점** 규약이라 자리의 `키`(m)가 그대로 배율이 되고, `y` 가 곧 땅에 닿는 점입니다.
무리를 만드는 곳은 `src/scene/buildInstanceGroups.ts`, 편집을 얹는 곳은 `src/placement/instanceGroups.ts` 입니다.

### 편집은 파일에 남는다

배치는 시드 기반이라 **어디서 열어도 같은 결과**가 나온다. 편집만 사람마다
다르면 그 전제가 깨진다. 그래서 「무엇을 지웠고 무엇을 옮겼는가」만
`assets/edits.json` 에 적고 생성 결과 위에 덧씌운다.
**생성은 그대로 결정적이고, 편집만 얹힌다.** 편집은 무리 안의 **생성 순서 번호**로 물건을 가리키므로,
생성기의 반복 순서·난수 소비·개수가 바뀌면 같은 번호가 다른 물건을 가리킨다. 새 물건은 기존 무리 뒤에
새 무리로 더하고, 생성기를 고친 뒤에는 아래 「손 배치 확인」을 돌린다.

```json
{ "지움": { "언덕수풀.나무": [0,1,2] },
  "고침": { "언덕수풀.나무": { "10": { "x": 40, "z": 20, "키": 9 } } } }
```

저장은 개발 서버가 받는다(`vite/editFilePlugin.ts` 의 `editFileServerPlugin` · `/__naju-edit`).
본편 서버(5173)는 같은 플러그인을 읽기 전용으로 붙이고, 쓰기는 naju01 서버(5174)만 한다.
덮어쓰기 전 내용은 `assets/edits-backup/` 에 최근 40개까지 남는다.

### 손 배치 확인

편집이 걸린 생성 번호마다 그 자리의 좌표를 `assets/edit-anchors.json` 에 적어 두고, 생성기를 고친 뒤 다시 재서 비교한다.

```bash
npx vite naju01                                   # 개발 서버
node naju01/tools/check-edit-anchors.mjs          # 비교 — ✖ 가 나오면 손 편집이 다른 물건에 붙었다
node naju01/tools/check-edit-anchors.mjs --write  # 손 배치가 맞는 것을 확인한 뒤(또는 편집기로 새로 저장한 뒤) 기준 갱신
```

주소를 앞에 주면 다른 포트의 서버를 잰다(`… check-edit-anchors.mjs http://localhost:5329/`). 도구는 편집 파일을 읽기만 한다.
