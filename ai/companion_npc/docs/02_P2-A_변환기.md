# P2-A — 기존 Case 파일 → ScenarioPack 변환기

> 작성 2026-10-24 · 상태 **초안** · 코드 `src/companion_npc/adapters/` · 테스트 `tests/test_adapter.py`

## 1. 입력과 출력

| | |
|---|---|
| 입력 | `<case_id>.client.json` (CaseClientContent) · `<case_id>.server.json` (PuzzleRuntimeDefinition) — **읽기 전용** |
| 출력 | `ScenarioPack` (항상 `publication.status = "draft"`) + `ConversionReport` |
| 실패 | 입력 오류 · 계약 오류 → 예외. 정답 누설 → `AnswerLeakError` (팩을 돌려주지 않음) |

GameSpec / PuzzleSpec 은 확정 전이라 다루지 않는다. 확정되면 같은 출력을 내는 변환기를 하나 더 둔다.

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m companion_npc.adapters case_001                 # 보고서만 출력
.\.venv\Scripts\python.exe -m companion_npc.adapters case_001 --out-dir runs\packs --alias 밸브
```

종료 코드는 0 성공 · 1 입력/계약 오류 · 2 정답 누설이다. 누설이면 파일을 쓰지 않는다.

## 2. 구조

| 파일 | 역할 |
|---|---|
| `adapters/source_models.py` | backend 입력 스키마를 그대로 옮긴 것. backend 와 같은지 `test_backend_compat.py` 가 필드·검증 결과로 검사 |
| `adapters/loader.py` | 파일 읽기. 경로 규칙(case_id 패턴, cases 폴더 밖 차단)은 backend 와 같다 |

## 3. 변환 규칙

| ScenarioPack | 원본 | 규칙 |
|---|---|---|
| `case_id` · `entry_zone_id` | client | 그대로 |
| `pack_id` | client.case_id | `pack_<case_id>` (64자 넘으면 해시) |
| `zones[]` + `navigation[]` | client.zones[] | 그대로 |
| `objects[]` | client.zones[].objects[] | 그대로 + `initially_visible·enabled`. `interaction.type` 이 5종 밖이면 비우고 경고 |
| `objects[].puzzle_id` | `interaction.target_id` | **type == "input" 일 때만**. 다른 type 의 target 의미는 계약이 없다 |
| `puzzles[]` | server.puzzles[] → 효과에서만 이름이 나오는 퍼즐 | 순서: 정의된 순서 → 처음 나온 순서. 이름만 있는 퍼즐은 경고 |
| `puzzles[].host_object_ids · zone_id` | input 오브젝트 역참조 | zone 이 하나일 때만 zone_id |
| `puzzles[].grants_clue_ids · completes_puzzle_ids · sets_flags` | server.puzzles[].on_correct | 그대로 |
| `clues[]` | on_correct.grant_clue_ids · 조합 clue_ids · on_success.grant_clue_ids | **ID 만, 짝·결과와 잇지 않음** |
| `knowledge[]` (zone) | zone.description | 등급 0, **그 zone 에 있을 때만** |
| `knowledge[]` (object) | object_name | 등급 0, 그 zone 에 있을 때만. **처음에 숨은 물건은 만들지 않음** |
| `source.*_sha256` | client · server 전체 | 정규화 JSON 해시 (CRLF·들여쓰기·key 순서 무관) |
| premise · persona · locale · hints · lore · title · puzzle_type | — | **비움** (지어내지 않음) + 보고서 `missing` |

## 4. 공개 여부와 NPC 참조 가능 여부 (`FIELD_POLICY`)

| 원본 필드 | FE 공개 | NPC 참조 | 처리 |
|---|:-:|:-:|---|
| zone · navigation · object 이름/종류/visible/enabled · interaction.type | ○ | ○ | 복사 |
| interaction.target_id | × (Bundle 이 숨김) | ○ | input 이면 puzzle_id |
| asset_key · metadata | ○ | × | 제외 (FE 표현 전용) |
| puzzles[].puzzle_id · on_correct.* | × | ○ | 복사 |
| **puzzles[].accepted_answers** | × | **×** | 제외. 누설 검사에만 사용 |
| **clue_combinations[].clue_ids (짝)** | × | **×** | 제외. 조합 퍼즐의 정답이다 |
| **clue_combinations[].on_success** | × | **×** | 제외. 나오는 ID 만 따로 등록 |
| server 의 모르는 key | × | × | 제외. 값은 읽지 않고 위치만 보고 |

## 5. 누설 검사

1. 팩 전체 + 보고서의 모든 문자열을 본다. 값뿐 아니라 dict key(flag 이름 등)도 포함한다.
2. 금지어는 `accepted_answers` + `--alias` 로 준 별칭이다. 별칭은 어디에도 남기지 않는다.
3. 정규화는 대소문자·공백·문장부호를 지운다. 그래서 `north-east` 는 `NORTHEAST` 로 잡힌다.
4. **영문·숫자 3자 미만** 정답(예: `"1"`)은 낱말 단위로만 비교한다. `case_001` 같은 ID 에 걸리는 오탐을 막기 위해서다. 한글은 짧아도 부분 문자열로 찾는다.
5. 변환기가 스스로 만든 칸(버전, 해시, source_refs)은 검사에서 뺀다. 원본 콘텐츠가 아니고 숫자 정답과 우연히 겹친다.
6. 걸린 위치는 **순번 경로**로만 적는다. flag 이름에 정답이 들어 있어도 보고서가 그 이름을 다시 쓰지 않는다. 누설이면 ID 가 든 칸(warnings 등)을 비운 보고서만 내보낸다.
7. 금지 key(`accepted_answers`, `on_correct`, `on_success`, `clue_combinations`, `combination_id`)도 따로 찾는다.

**한계**: 글자 비교다. 번역(VALVE ↔ 밸브)은 별칭을 줘야 잡는다. 돌려 말하기("손잡이 달린 그 부품")는 못 잡는다. ID 이름 자체가 이야기 스포일러인 경우(`CLUE_KEEPER_TRUTH`)도 정답이 아니면 통과한다. 그래서 발화층은 ID 를 문장에 쓰지 않고 knowledge 의 text 만 쓴다(P4 규칙으로 고정 예정).

## 6. 현재 Case 파일로는 채울 수 없는 칸

보고서 `missing` 과 같다.

| 칸 | 채울 주체 |
|---|---|
| premise · persona · locale · knowledge(등급 ≥1, 설화) · puzzles[].title | 사람 작성 |
| hints[] · safety_audit | 사람 승인 |
| puzzles[].puzzle_type · required_clue_ids · required_discovery_ref | 생성 에이전트 산출물 (스키마 미정) |
| case_version · puzzles[].prerequisite_puzzle_ids · 물건 드러남 조건 · clues[] 이름/설명 | backend 계약 (Contract Gap) |

## 7. 검사 통과의 의미와 공개 조건

§5 의 한계에서 나오는 운영 규칙이다.

1. **`leak_check: passed` 는 "안전하다"가 아니라 "주어진 금지어가 글자로는 없다"는 뜻이다.** 문자열 검사만으로 의미 수준의 정답 누설을 완전히 막을 수는 없다. 의미 검사기(파이프라인 설계요청 §8 H3)와 사람 검수가 따로 필요하다.
2. **별칭 목록이 불완전하면 검사를 통과해도 공개 안전성을 보장할 수 없다.** 보고서의 `terms_checked` 는 "검사에 쓴 금지어 수"일 뿐, 별칭이 빠짐없다는 증거가 아니다. 별칭 목록의 완전성은 사람이 확인한다.
3. **승인되지 않은 콘텐츠는 draft 로 남는다.** 변환기와 이후 자동 단계는 draft 를 approved·published 로 올리지 않는다. 올릴 때는 사람이 premise·승인 힌트를 채우고, 별칭을 포함해 다시 검사한 뒤 `publication`·`safety_audit` 를 기록한다.
4. **"NPC 가 참조할 수 있다" ≠ "LLM 프롬프트에 넣어도 된다".** `FIELD_POLICY.npc_referable` 은 NPC 서비스 내부(판단층 피처·검색 필터)에서 쓸 수 있다는 뜻이다. 프롬프트로 보낼 수 있는 범위는 더 좁고, 별도 정책으로 정한다. 현재 제안은 **gate 를 통과한 knowledge.text 와 승인 힌트 text 만** 보내는 것이다. ID·flag 이름·`grants_clue_ids` 같은 구조 정보는 보내지 않는다. 외부 API(GPT)와 로컬 모델(Qwen) 사이에 범위 차이를 둘지도 이 정책에서 정한다 [미정].
5. **ID 에 담긴 사건 정보가 발화로 새지 않는지는 후속 단계에서 검증한다.** 입력 쪽 규칙(§5, 프롬프트에 ID 를 넣지 않음)만으로는 충분하지 않다. P4 에서 출력 쪽 검사를 더한다. 생성된 발화에서 팩의 ID·flag 이름과 그 조각(예: `KEEPER_TRUTH`, `keeper truth`)을 찾아, 걸리면 발화를 버린다.
