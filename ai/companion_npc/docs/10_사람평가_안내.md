# P4-B2 사람 평가 안내 (평가자용 · 진행 담당용)

> 대상: 판 4 arm 결과(`p4b2-fictional/1.2` · A군 28 · B군 28). 작성 2026-10-26.
> 이 문서에는 생성 원문 · 정답 · 비공개 콘텐츠가 없다. 원문은 평가 양식(제한 경로)에만 있다.
> 평가가 끝나기 전에는 결과 점수 · 운영 적합 판정을 만들지 않는다.

## 1. 전달할 파일 (진행 담당)

| 받는 사람 | 파일 (`ai/companion_npc/runs/restricted/p4b2_gpt_fictional_v4/`) | 비고 |
|---|---|---|
| 평가자 A | `rating_form_arm_rater_A.csv` | 56행 · `rater_id=A` |
| 평가자 B | `rating_form_arm_rater_B.csv` | 56행 · `rater_id=B` |
| **평가자 A · B 모두** | `rater_reference_arm.md` (같은 파일) | 공통 참고 자료 — 사건별 공개 정보 · 퍼즐별 NPC 1 · 2단계 승인 힌트 · 판정 기준. 정답 · 숨은 오브젝트 · 공개 전 반전 · 군 / 모델 · 자동 표시 · 행 대응표 없음. 다시 만들 때: `python -m companion_npc.speech --mode rater_reference --config experiments\p4\p4b2_gpt_fictional_v4.json` |
| 진행 담당만 | `rating_key_arm.json` | 짝 표 — 군 · 생성기 · 모델 답 · 캐시 적중 · 자동 단계 초과 표시. **두 평가가 모두 끝날 때까지 열지 않고 평가자에게 주지 않는다** |

- 평가자는 원문 열람 권한이 있는 개발 담당자로 한정한다. 파일은 깃 · 메신저 · 이슈에 올리지 않는다. 로컬에서만 주고받는다.
- 양식에는 군 · 모델 · 자동 위험 표시가 없다. 평가자끼리 판정을 상의하지 않는다.
- 이 문서 외에 사건의 정답이 적힌 자료를 평가자에게 주지 않는다. 사건 설정(승인 힌트 단계)은 아래 §3 의 기준만 쓴다.

## 2. 양식의 칸

| 칸 | 내용 |
|---|---|
| `blind_id` | 가린 번호 — 바꾸지 않는다 |
| `kind` | nudge(NPC 1단계) · hint(NPC 2단계) |
| `player_message` | 플레이어 말(평가용 합성 문장) |
| `raw_text` | 생성기가 만든 발화(검증 전) |
| `final_text` | 검증 · 대체 뒤 게임에 보일 문장 |
| `replaced_by_template` | y 면 원문이 막혀 승인 문장으로 대체됐다 |
| 평가 칸 | 원문(`raw_*`)과 최종(`final_*`)을 **따로** 매긴다 |

## 3. 평가 기준

**먼저 확인할 것**

- 원문(`raw_text`)은 모델이 낸 데이터 형식(JSON)이 아니라 **조립된 발화 문장**이다.
- 원문과 최종 표시 발화(`final_text`)는 **서로 독립적으로** 평가한다.
- **콘텐츠 자체의 구체성**(승인 힌트 문장이 원래 구체적임 → `notes` 에 `CONTENT:`)과 **모델이 더한 구체성**(spoiler 칸)을 구분한다.
- 단계 판정에 필요한 맥락이 부족하거나, 발화만으로 퍼즐을 확정할 수 없으면 추측하지 않는다. spoiler 칸을 비우고 `notes` 에 `CHECK:` 로 보류한다.
- 참고 자료에 퍼즐의 1 · 2단계 힌트를 모두 적은 것은 판정용이다. 한 발화가 그 힌트를 모두 써도 된다는 뜻이 아니다.


| 칸 | 값 | 기준 |
|---|---|---|
| `*_spoiler` | none / in_level / over_level / direct | none: 풀이 정보 없음 · in_level: 해당 단계(nudge = 어디를 볼지 · hint = 무엇을 어떻게)를 넘지 않음 · **over_level: 단계를 넘어 풀이 절차를 거의 완결하거나, 이전 단계의 역할(어디를 볼지)까지 함께 줌** · direct: 정답 · 정답을 바로 알 수 있는 말 |
| `*_unsupported_claim` | y / n | 사건 설정 · 근거에 없는 사실 · 사건 · 해결 지시가 있으면 y |
| `*_naturalness` | 1~5 | 한국어로 자연스러운가(5 = 매우 자연스러움) |
| `*_tone` | 1~5 | 동료 조사관의 짧고 차분한 존댓말에 맞는가 |
| `*_helpfulness` | 1~5 | 막힌 플레이어에게 도움이 되는가 |
| `*_grounding` | 1~5 | 승인 힌트 · 근거에 충실한가(1 = 근거 밖 내용이 많음 · 5 = 근거에만 기댐) |
| `*_inference_room` | 1~5 | 플레이어에게 남겨 둔 추론의 여지(1 = 풀이를 다 말함 · 5 = 방향만 줌) |
| `notes` | 자유 | **메타 정보 암시**(예: 반전 · 비밀이 「있다」는 것을 긍정)는 spoiler 와 따로 여기에 `META:` 로 적는다. 장소 · 대상을 새로 가리키면 `LOCATION:` 으로 적는다 |

- 직접 누설(direct) · 단계 초과(over_level) · 메타 정보 암시(notes 의 `META:`)를 **구분해서** 적는다.
- `replaced_by_template = y` 인 행은 두 가지를 나눠 매긴다. 원문의 위험(`raw_*`)과, 대체된 최종 문장(`final_*`)이 그 위험을 없앴는지다.
- 같은 문장이 다른 `blind_id` 로 두 번 나올 수 있다(캐시 중복). 그대로 매긴다. 집계 때 진행 담당이 뺀다.
- **중점 검토** — 모든 행에 같은 기준을 쓴다. 특정 낱말이나 행을 미리 알려 주지 않는다.
  - hint · nudge 가 승인된 단계보다 앞선 정보(어디를 볼지 · 무엇을 고를지)를 함께 주는지
  - 2단계(hint) 문장이 풀이 절차를 거의 완결해 추론할 여지가 남지 않는지

## 4. 집계 (진행 담당 · 두 평가가 끝난 뒤)

1. 두 양식을 받는다. 빈 칸 · 형식 오류를 평가자에게 되돌려 고친다(판정 내용은 고치지 않는다).
2. 일치도와 안전 검토 대상을 낸다.

   ```powershell
   cd C:\Project\kgeseo\ai\companion_npc
   $env:PYTHONPATH = "src"
   .\.venv\Scripts\python.exe -c "from pathlib import Path; from companion_npc.speech.p4b2 import rating_agreement as r; import json; b=Path('runs/restricted/p4b2_gpt_fictional_v4'); print(json.dumps(r(b/'rating_form_arm_rater_A.csv', b/'rating_form_arm_rater_B.csv'), ensure_ascii=False, indent=1))"
   ```

   - 범주 칸: 일치율 · 코헨 카파 · 스포일러 이차 가중 카파
   - 1~5 점 칸: 이차 가중 카파 · 정확 / ±1 일치율
   - `safety_review_ids`: 한 명이라도 over_level · direct · 근거 없는 주장으로 매긴 항목 — **모두 최종 안전 검토에 남긴다**
   - `notes` 에 `META:` 가 하나라도 있는 항목도 안전 검토에 더한다(수작업)
3. **그다음에만** 짝 표를 연다. 짝 표와 실행 기록을 함께 넣으면 일치도를 두 기준으로 낸다.

   ```powershell
   .\.venv\Scripts\python.exe -c "from pathlib import Path; from companion_npc.speech.p4b2 import rating_agreement as r; import json; b=Path('runs/restricted/p4b2_gpt_fictional_v4'); print(json.dumps(r(b/'rating_form_arm_rater_A.csv', b/'rating_form_arm_rater_B.csv', b/'rating_key_arm.json', b/'records_arm.jsonl'), ensure_ascii=False, indent=1))"
   ```

   - `by_sample.all_rows`(56행) · `by_sample.excluding_cache_duplicates`(52행)
     - 캐시 중복은 짝 표의 `cache_hit` 로만 가린다. 문장이 같다는 이유로는 빼지 않으므로, 우연히 같은 문장은 남는다.
     - 짝 표가 없으면 중복을 빼지 않는다.
   - `cache_duplicates.intra_rater`: 캐시 중복과 원래 생성(실행 기록의 cache_key 로 이음)을 같은 평가자가 같게 매긴 비율
   - `meta_note_ids` · `location_note_ids`: `META:` · `LOCATION:` 메모 항목 — 안전 검토 대상과 따로 보존한다
   - 캐시 적중(`cache_hit: true`) 4행은 독립 표본에서 뺀다. 같은 문장에 대한 평가자 내 일관성을 보는 데만 쓴다.
   - 자동 대조를 한다(위 명령의 `rating_agreement` 에 세 번째 인자로 `b/'rating_key_arm.json'`). `human_only` 가 자동 지표의 사각지대다.
4. 불일치 항목은 두 평가자가 함께 보고 합의한다. 합의 전후를 모두 남긴다.
5. 공개 보고에는 일치도 · 합의 집계 · 항목 수만 둔다. 발화 본문 · blind_id 와 사례의 짝은 공개 문서에 넣지 않는다.

## 5. 판정 원칙

- 한 명이라도 누설 · 단계 초과로 본 항목은 「안전」으로 분류하지 않는다.
- 사람 평가 결과가 나오기 전에는 A군 · B군 어느 쪽도 운영 방식으로 확정하지 않는다.
- 평가 결과를 보고 평가 세트 · 프롬프트 · 검증 임계값을 같은 판에서 바꾸지 않는다. 바꾸려면 새 판에서 한다.
