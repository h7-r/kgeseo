# P2-B — 플레이어 상태 · 로그 → 판단층 특성

> 작성 2026-10-24 · 상태 **초안** · 코드 `src/companion_npc/features/` · 테스트 `tests/test_features.py`
> 이 단계는 특성을 **계산**만 한다. 모델 학습·성능 검증은 하지 않았다.

## 1. 구조

```
온라인:  NpcContext ──────────────────────────────────────┐
                                                           ├→ extract_features(context, pack, config) → FeatureVector
오프라인: interaction_events 행 → replay_session → NpcContext[] ┘
                                    └→ label_replay (미래 이벤트는 여기서만)
```

| 파일 | 역할 |
|---|---|
| `features/schema.py` | `FeatureVector` fs-0.1 · `FEATURE_SPECS`(열 목록·출처·실시간 여부) · `model_row()` |
| `features/config.py` | 실험 설정값: 판단 간격 30초 · 관측 구간 120초 · 창 50개 · 원천 스위치 |
| `features/extract.py` | **유일한** 특성 계산 함수 |
| `features/replay.py` | interaction_events 행 → 판단 시점별 NpcContext (DB 접속 없음) |
| `features/fingerprint.py` | 오답 지문 (비밀 키 필요) |
| `features/labels.py` | 대리 라벨 `no_progress_within_<N>s` · `needs_help` 계약 |

## 2. 특성 (fs-0.1, 25개)

각 특성은 `values[name]` 과 `status[name]` 을 함께 가진다. 상태는 셋 중 하나다.

- `observed`: 값이 있다.
- `not_applicable`: 이 시점엔 뜻이 없다 (예: 대상 퍼즐 없음).
- `unobservable`: 원천이 없거나 창 밖이다.

학습 행(`model_row`)은 값과 `<이름>__known`(0/1)만 담는다. ID 는 `meta` 에만 있다.

| 군 | 특성 | 출처 | 실시간 |
|---|---|---|---|
| 진행 | progress_puzzle_ratio · progress_clue_ratio · acquired_clue_count · flags_true_count | S(+P) | 가능 |
| 대상 | target_known · target_from_focus · target_solved · target_attempt_count · target_consecutive_incorrect · target_grants_clue_count | S·E·R·P | 가능 |
| 대상 | target_repeat_wrong_max · target_distinct_wrong | E + 지문 | 조건부 (키가 있을 때) |
| 대상 | target_hint_level | S | 새 로그 필요 (Hint API) |
| 시간 | since_last_interaction_sec · since_last_progress_sec · events_in_rate_window · mean_gap_recent_sec | E | 가능 |
| 조합 | recent_incorrect_combinations | E | 가능 |
| NPC | since_last_npc_utterance_sec · npc_max_hint_level_on_target | N | 새 로그 필요 |
| 요청 | player_requested_help | R | 가능 |
| 탐색 | inspected_objects_since_progress · zone_dwell_sec | N | 새 로그 필요 (fs-0.1 에서는 늘 unobservable) |
| 구조 | pack_puzzle_count · pack_clue_count | P | 가능 |

S=PlaySessionState · E=interaction_events · P=ScenarioPack · R=요청 시점 NpcContext · N=아직 없는 로그

**대상 퍼즐**은 다음 순서로 정한다.
1. `focus.puzzle_id` 가 팩에 있으면 그 퍼즐이다.
2. 없으면 창 안에서 마지막으로 채점한 퍼즐이다. 관측값(`resolved_puzzle_id`, live 의 오브젝트→팩 매핑)으로만 정한다.
3. 둘 다 없으면 대상 없음이다. 대상 특성은 not_applicable 이 된다.

## 3. 관측값과 추정값

- 로그에서 다시 만든 기록(`source="event_log"`)은 `zone_id`·`target_id` 를 **null** 로 둔다.
- 로그의 target_id 는 puzzle_id 이므로 `resolved_puzzle_id` 로 옮긴다.
- 팩에서 짚은 오브젝트는 `inferred_object_id` 에만 둔다. 특성 계산은 이 값과 `source` 를 보지 않는다. 그래서 같은 상황을 live 로 받든 로그로 받든 같은 특성이 나온다(테스트로 확인).

## 4. 판단 시점과 상태

| 시점 | t | 상태 | 본 이벤트 |
|---|---|---|---|
| `post_event` | 이벤트 i 의 created_at | 이벤트 i 의 `response_json.state` (직후 상태) | 0..i |
| `tick` | i 이후 30초마다, 다음 이벤트 **전**까지 (마지막 이벤트 뒤에는 observation_end 까지) | 여전히 이벤트 i 직후 상태 | 0..i |

- 같은 시각에 찍힌 다음 이벤트는 특성이 아니라 라벨 쪽으로 간다(순번 기준).
- `response_json.state` 가 없는 옛 행은 판단 시점을 만들지 않는다. 라벨 계산용 타임라인에는 남긴다.
- 시각은 서버 `created_at` 을 쓴다. timezone 이 없으면 UTC 로 본다(backend 저장 방식).

## 5. 답 원문과 지문

- `payload_json.answer` 는 `replay.py` 안에서 지문을 만들 때 한 번만 읽는다.
- 행 모델의 repr·오류 메시지·특성·학습 행·라벨 어디에도 원문이 나오지 않는다(테스트로 확인).
- 지문은 다음 조건을 모두 만족할 때만 만든다.
  - `AnswerFingerprinter(키)` 를 받았을 때다. 키는 `.env` 로만 받고, 승인된 처리 경계 안에서만 쓴다.
  - **오답**일 때만이다. 정답의 지문은 짧은 정답을 거꾸로 맞히는 데 쓰일 수 있다.
  - 세션 ID 를 섞어 해시한다. 같은 오답이라도 다른 플레이어 사이에서는 이어지지 않는다.
- 키가 없으면 반복 특성 두 개만 unobservable 이 된다. 다른 특성은 그대로다.

## 6. 라벨

| 라벨 | 성격 | 규칙 |
|---|---|---|
| `no_progress_within_120s` | **대리 라벨** — 실제 막힘이 아니다 | 이후 120초 안에 puzzle_completed·clue_acquired 가 없으면 1, 있으면 0. 구간이 observation_end 를 넘고 진전도 없으면 **censored**(확정 안 함) |
| `needs_help` | 실제 도움 필요성 | **계약만** (`HelpAnnotation`). 플레이테스트 관찰·생각 말하기·리플레이 검토·본인 응답으로 사람이 만든다. 판단 시점과는 같은 세션에서 가장 가까운 시점으로 맞춘다(허용 오차 제안 15초) |

120초와 30초는 `FeatureConfig` 의 실험 값이다. 바꾸면 라벨 이름도 바뀐다(`no_progress_within_60s`).

## 7. 남은 한계

- **창 50개**: 진전이 창 밖으로 밀리면 since_last_progress_sec 는 unobservable 이 된다. events_in_rate_window·연속 오답은 50 에서 멈춘다(하한값).
- **대상 퍼즐이 남는다**: 정답을 맞힌 뒤에도 다음 채점 전까지 대상은 그 퍼즐로 남는다. `target_solved` 로 구분한다.
- **attempt_counts**: 과거 state 에 key 가 없던 행은 0 으로 읽힌다. "없음"과 "0"을 구분할 수 없다.
- **일시정지**: 기록이 없어 시간 특성에 쉬는 시간이 섞인다. 오프라인 `timing.session_active_sec` 은 일시정지를 모르는 경과 시간이며, 특성에 쓰지 않는다.
- **실패 요청**: backend 가 4xx 로 끝난 요청(조합 전 단서 미획득, inspect·navigate 501)을 기록하지 않아 빠진다.
- **대리 라벨**: 쉬거나 생각 중이어도 1 이다. `needs_help` 와 비교하기 전에는 이 라벨이 맞는지 모른다.
- **검증 범위**: 손으로 만든 가상 타임라인으로 계산 규칙만 확인했다. 실제 플레이 분포·모델 성능은 확인하지 않았다.
