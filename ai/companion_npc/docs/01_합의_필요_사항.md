## P2-B 검증 범위 (2026-10-24 기준 사실 기록)

질문이 아니라 현재 상태다. 결과를 인용할 때 함께 적는다.

- **테스트 139개(P2-B 커밋 기준)는 기능 검증이다.** 계약·변환·특성 계산 규칙이 의도대로 동작하는지를 본다. **모델 예측 성능은 검증하지 않았다.** 학습한 모델이 아직 없다.
- **온라인·오프라인 일치 테스트는 모의 데이터 기준이다.** 손으로 만든 가상 사건 타임라인(5개 이벤트)으로 수행했다. 실제 NPC 서비스가 만든 NpcContext 와는 비교하지 않았다. 그 서비스는 아직 없다.
- **실제 운영 DB 로그로 통합 검증하지 않았다.** `replay_session` 은 interaction_events 행 형식을 받도록 만들었지만 실제 행을 넣어 본 적은 없다. 반출 범위(#10)가 정해진 뒤 수행한다.
- **오프라인 tick 이 실제 플레이 중이었는지 확정할 수 없다.** 일시정지·세션 종료 기록이 없다(#19). 이벤트 사이 30초마다 만든 판단 시점에 플레이어가 자리를 비웠거나 이미 나갔을 수 있다. 그런 시점의 대리 라벨 1 은 "막힘"이 아니다.
- **`needs_help` 는 실제 플레이테스트로 라벨을 모아야 한다(#20).** 그 전에는 `no_progress_within_120s` 가 도움 필요성을 얼마나 잘 나타내는지 알 수 없다.

## P2-C 검증 범위 (2026-10-25 기준 사실 기록)

자세한 수치와 근거는 `docs/04_P2-C_시뮬레이터.md` 에 있다. 여기에는 인용할 때 함께 적을 요지만 둔다.

- **합성 데이터는 실제 플레이어 분포를 대표하지 않는다.** 유형·매개변수는 관찰 근거가 없는 가정이다(#24).
- **합성 데이터에서 "무진전" 대리 라벨은 탐색과 막힘을 잘 가르지 못했다**(exploring 0.73 · stuck 0.90). 이것은 가정한 세계에서의 관찰이며, 실제 플레이어에서도 그렇다는 근거가 아니다.
- `synthetic_needs_help`(시뮬레이터 정답)와 `needs_help`(사람 판단)는 다른 라벨이다.

## P3-A 검증 범위 (2026-10-25 기준 사실 기록)

수치는 `docs/05_P3_학습평가_설계.md` §12 에 있다.

- 테스트 통과(P3-A 기준 186개, 재현 정보 테스트 포함 188개)는 **기능 검증**이다. 모델 예측 성능 검증이 아니다.
- 기준선 결과는 모두 **합성 데이터**에 대한 평가다. 실제 플레이어 성능이 아니다.
- 관측 가능 평가에서 규칙 기준선 개입의 **74~95% 가 세션 종료 후**에 일어났다. 종료·일시정지 이벤트가 없는 운영 로그에서도 같은 위험이 있다(#19). **Oracle 없이 이를 완전히 막을 수 있다고 가정하지 않는다.**
- 탐색 중 오개입 지표만으로는 종료 후 개입 위험을 파악할 수 없다(#26).
- 현재 규칙 기준선은 설정한 오개입 예산을 충족하지 못했다.
- `generator_reference` 는 Oracle 정보를 쓰는 참고 기준선이다. 운영에 적용할 수 없다.
- 실제 세션 종료·일시정지 이벤트는 **backend 팀과 협의할 별도 계약 변경**이다(#19). 이 실험 환경에서는 만들지 않는다.

## P3-B 검증 범위 (2026-10-26 기준 사실 기록)

수치는 `docs/06_P3-B_모델비교.md` 에 있다.

- 테스트 203개 통과는 기능 검증이다. 모델 비교 결과는 모두 **합성 데이터 평가값**이며 실제 플레이어 성능이 아니다.
- **운영 모델은 정하지 않았다.** LightGBM 은 분류 지표가 가장 좋았고, 로지스틱 회귀는 개입 빈도가 낮고 진단 목표를 더 자주 맞췄다. 둘 다 후속 후보다.
- **어떤 차단(2·5·10분)·상한 조합도 종료 후 개입을 0 으로 만들지 못했다.** 2분 차단은 정상적인 장시간 탐색형의 활동 시점을 36~48% 막았다.
- 합성 평가의 모든 개입은 `check_in` 이었다. 퍼즐 힌트 경로는 검증되지 않았다(#28).

## P4-B1 검증 범위 (2026-10-26 기준 사실 기록)

수치는 `docs/08_P4-B1_실험준비.md` §3 에 있다.

- 실제 GPT 요청 · Qwen 다운로드 · 설치를 하지 않았다. LLM 생성기는 골격과 오프라인 전송으로만 시험했다.
- 검증기 평가 세트(212 항목)는 테스트 견본이다. 오탐 · 미탐 수치는 **지금 검증기의 성질**이며 일반화된 성능이 아니다.
- 임계값은 P4-A 값 그대로다. dev · locked 어느 쪽을 보고도 고치지 않았다.
- 돌려 말한 정답은 `answer_leak` 으로 한 번도 잡히지 않았다(0/24). 막힌 것은 근거 검사와 check_in 템플릿 정책 덕이다. **문자열 검증만으로 의미적 안전성이 보장되지 않는다.**
- check_in 보완 전(p4b1/0.1) 오탐 21 · 미탐 15 → 보완 후(p4b1/0.2) 오탐 25 · 미탐 2. 늘어난 오탐 4건은 미승인 일반 인사(의도된 차단)이고, 남은 미탐 2건은 hint 문장 안 끼워 넣기다.
