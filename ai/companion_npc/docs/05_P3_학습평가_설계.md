## 1. 단계

## 3. Oracle 정보와 관측 가능 정보

| 정보 | 예 | 쓸 수 있는 곳 | 쓸 수 없는 곳 |
|---|---|---|---|
| 관측 가능 | 특성(`X`) · 세션 ID · 사건 ID · 판단 시각 | 모델 입력 · 실시간 개입 판단 · 운영 가능 평가 · 표본 가중치 · tick 솎아 내기 | — |
| **Oracle** (시뮬레이터 정답) | 잠재 상태 · 유형 · 종료 시각 · 결과 · 최종 상태 | 라벨 · 진단 · 참조 평가 | **모델 특성 · 실시간 개입 판단 · 운영 가능 평가의 필터** |

코드로는 다음처럼 막는다.
- `ExampleSet` 은 `X`(특성 열)와 `oracle`(정답 묶음)을 다른 칸에 둔다.
- 관측 가능 기준선의 `score(X, columns)` 는 Oracle 을 인자로 받지 않는다(테스트로 서명 검사).
- Oracle 을 쓰는 것은 `GeneratorReference.score_with_oracle` 하나뿐이고, `uses_oracle=True` 로 표시한다.
- 특성 열 이름에 Oracle 이름이 섞이면 오류가 난다. Oracle 을 섞어도 관측 가능 점수가 바뀌지 않는지 테스트한다.

### 정책 평가의 두 가지 실행

| 실행 | 정책을 돌리는 시점 | 뜻 |
|---|---|---|
| `observable` | 테스트 사건의 **모든** 판단 시점 | 운영과 같은 조건 (자리 비움·종료를 모름) |
| `oracle_filtered` | working · exploring · stuck 시점만 | 자리 비움·종료를 안다고 가정한 이상 조건 |

둘의 차이가 **종료·자리 비움을 관측하지 못해 생기는 위험**이다. away·종료 후 오개입 수는 `observable` 에서 별도 지표로 보고한다. 이 수를 셀 때만 Oracle 을 쓰고, 필터로는 쓰지 않는다.

### generator_reference

- 시뮬레이터가 stuck 을 일으키는 조건(유형별 `stuck_after_fails` · `stuck_prob > 0`)을 그대로 쓰는 참고 기준선이다.
- **성능 상한선이 아니다.** 관측 가능 모델이 생성 규칙을 얼마나 다시 배웠는지(규칙 재학습)를 보는 비교점이다.
- 유형을 쓰므로 운영 가능 평가와 섞지 않는다.

## 4. 데이터

- **원천**: P2-C 시뮬레이터 → P2-B 파이프라인(`replay_session → extract_features → label_replay`) → `ExampleSet`.
- **로더**: P2-C 출력 폴더도 읽을 수 있다(`load_synthetic_dir`). manifest 의 `representative: false` 와 파일 해시를 확인한다.
- **라벨 결합 검사**(`check_label_join`):
  - 잠재 구간이 세션 시작부터 빈틈·겹침 없이 이어지는지 본다.
  - 라벨이 잠재 상태와 맞는지 본다: stuck=1, working·exploring=0, away·종료 후=NaN.
- **학습 가능 행과 제외 사유**(`dataset_stats`): 사유는 상호 배타이고 합이 전체와 같다.
  - `usable_for_synthetic_needs_help` · `excluded_post_termination` · `excluded_away` · `excluded_other`
  - 대리 라벨이 censored 인 종료 전 행은 주 라벨 학습에는 쓴다. 대리 라벨 비교에서만 뺀다.

## 5. 분할과 누수 방지

- **바깥 분할**: 사건 하나를 통째로 테스트로 둔다. 바깥 테스트 사건은 설정·임계값 선택에 쓰지 않는다.
- **안쪽 분할**: 학습 사건 안에서 세션 단위로 나눈다. 규칙의 (a, b), P3-B 의 하이퍼파라미터·임계값은 여기서만 고른다.
- **`check_fold` 가 확인하는 것**:
  - 바깥 학습과 테스트에 같은 세션이 없다.
  - 테스트 사건이 학습 행에 없다.
  - 안쪽 폴드가 바깥 테스트 행에 닿지 않는다.
  - 안쪽 학습과 검증에 같은 세션이 없다.
  - 안쪽 검증 폴드를 합치면 바깥 학습과 정확히 같다.
- **전처리**(`fit_preprocessor`): 학습 행으로만 적합한다.
  - 늘 NaN 이거나 값이 하나뿐인 열은 빼고, 뺀 목록을 남긴다.
  - NaN 은 학습 행의 중앙값으로 채운다. 0 으로 채우지 않는다.
  - 표준화도 학습 행으로만 잰다.
  - 테스트 행을 망가뜨려도 적합 결과가 같은지 테스트한다.
- **결과 보고**: seed 별·사건별로 따로 보고한다.

## 6. 지표

### 분류 지표 (판단 시점 단위 · cooldown 없음)

라벨 있는 테스트 행에 세션 가중치를 적용해 계산한다. 양성은 `synthetic_needs_help = 1` 이다.

- 계산하는 지표: Precision · Recall · F1 · Average Precision · **False Discovery Rate**(= 1 − Precision) · **False Positive Rate**(음성 중 개입 비율)
- 함께 적는 값: 행 수, 양성 수, 가중 양성 비율

### 정책 지표 (cooldown · 세션당 상한 적용)

| 지표 | 정의 |
|---|---|
| 탐색 10분당 불필요 개입 | exploring 중 개입 ÷ exploring 시간(분) × 10. **예산 지표** |
| 활동 10분당 불필요 개입 | (working + exploring) 중 개입 ÷ 그 시간 × 10 |
| 막힘 에피소드 발견율 | 관측 종료 전에 시작한 stuck 구간 중, 그 안에서 개입한 비율 |
| 막힘 시작부터 첫 개입까지 | 중앙값 · 90 백분위 (초) |
| 세션당 개입 수 | |
| away · 종료 후 오개입 수 | `observable` 실행에서만 생긴다 |
| 판단 시점이 있는 막힘 에피소드 수 | 30초보다 짧아 판단 시점이 없는 구간은 원리상 발견할 수 없다 |

분류 성능과 정책 성능은 따로 보고한다.

## 7. 기준선 (P3-A)

| 기준선 | 입력 | 조정 |
|---|---|---|
| `always_intervene` · `never_intervene` | 없음 | 없음 |
| `rule[session · thin60 · thin90]` | 도움 요청 · 대상 연속 오답 ≥ a · (대상 있음 AND 마지막 상호작용 뒤 ≥ b초) | a ∈ {2..6}, b ∈ {60, 90, 120, 180, 240}. 안쪽 검증에서 「예산을 지키는 조합 중 가중 F1 최대」. 지키는 조합이 없으면 예산 초과가 가장 작은 것 (`feasible: false` 로 표시) |
| `generator_reference` | 특성 + **유형(Oracle)** | 없음 · 참고용 |

- 가중치 전략은 규칙에서는 **선택 목적함수**에만 영향을 준다(규칙 자체는 학습하지 않는다).
- 매개변수 이동: seed 1 기본 데이터에서 고른 규칙을 이동 설정 데이터의 같은 테스트 사건에 적용한다.

## 8. 관측 불가능한 특성 (P3-B 모델용)

- 학습 폴드에서 늘 관측되지 않는 열(fs-0.1 의 힌트 1 · NPC 2 · 탐색 2개와 그 `__known`)은 뺀다.
- 로지스틱 회귀: 학습 폴드 중앙값으로 채움 + `__known` 열.
- LightGBM: NaN 을 그대로 넣음 + `__known` 열.
- 한계: 학습 행에는 「해당 없음」과 「관측 불가」의 구분이 없다. 필요하면 fs-0.2 에서 다룬다.

## 12. P3-A 결과 (합성 평가값 — 실제 플레이어 성능 아님)

- 실행: `python -m companion_npc.training --config experiments/p3/p3a_baselines.json --publish`
- 커밋된 요약: `experiments/results/p3a_baselines/` 의 `report.md` · `metrics.json`. metrics.json 에는 핵심 지표와 재현 정보가 들어 있다. 재현 정보는 다음과 같다.
  - 설정 해시 · 소스 해시 · 패키지 버전 · git 커밋
  - seed 별 데이터 해시
  - 원본 results.json 의 sha256
- 원본: `runs/p3/p3a_baselines/results.json` (깃 제외). 사건·seed·기준선·cooldown·실행 방식별 세부 지표가 모두 들어 있다.

**인용할 때 함께 적을 사실**

- 테스트 186개 통과(P3-A 기준, 재현 정보 테스트를 더해 188개)는 **기능 검증**이다. 모델 예측 성능 검증이 아니다.
- 아래 기준선 결과는 모두 **합성 데이터**에 대한 평가다. 실제 플레이어 성능이 아니다.
- 관측 가능 평가에서 규칙 기준선 개입의 **74~95% 가 세션 종료 후**에 일어났다(§12.4-3).
- 탐색 중 오개입 지표만으로는 종료 후 개입 위험을 파악할 수 없다(§12.4-4).
- 현재 규칙 기준선은 설정한 오개입 예산(탐색 10분당 1회)을 **어느 폴드에서도 충족하지 못했다**(§12.4-1).
- `generator_reference` 는 Oracle(플레이어 유형)을 쓴다. **운영에 적용할 수 없다**(§3).

### 12.1 학습 가능 행 (seed 별 · 제외 사유는 상호 배타)

| seed | 판단 시점 | 학습 가능 | 제외: 종료 후 | 제외: away | 기타 | 양성(stuck) |
|---|---|---|---|---|---|---|
| 20261025 | 161,569 | 43,015 (26.6%) | 105,681 | 12,873 | 0 | 8,909 |
| 20261026 | 162,383 | 43,642 | 106,504 | 12,237 | 0 | 9,819 |
| 20261027 | 163,116 | 43,501 | 106,296 | 13,319 | 0 | 9,211 |

P2-C 의 `eligible`(53,878)과 다른 기준이다. P2-C 는 **대리 라벨** 기준이라 away 를 넣고 censored 를 뺐다. 여기서는 **주 라벨** 기준이라 away 를 빼고, 대리 라벨이 censored 인 종료 전 행(seed 1: 1,571)은 넣는다.

### 12.2 분할·누수

- 3 seed × 3 폴드 모두 `check_fold` 를 통과했다. 바깥 테스트는 995~1,000 세션, 학습은 1,992~1,999 세션이다.
- 안쪽 5 폴드는 바깥 학습을 정확히 나눈다.

### 12.4 관찰

1. **규칙의 선택이 격자 끝(a=6, b=240)에 붙고, 모든 폴드에서 예산을 못 지켰다**(`feasible: false`). 안쪽 검증의 탐색 10분당 불필요 개입은 1.8~2.2 였다. 격자가 좁거나, 이 규칙 형태로는 예산을 지킬 수 없다.
2. **세 가중치 전략이 같은 규칙을 골랐다.** 그래서 테스트 결과도 같다. 규칙은 학습하지 않아서, 가중치가 바꾸는 것이 선택 목적함수의 F1 값뿐이기 때문이다. 가중치의 효과는 P3-B 의 학습 모델에서 봐야 한다.
3. **관측 가능 조건과 Oracle 조건의 차이가 매우 크다.** 규칙의 세션당 개입은 관측 14~21회, Oracle 0.8~2.6회다. 관측 조건 개입의 **74~95% 가 종료 후**에 일어났다. 「마지막 상호작용 뒤 ≥ b초」 조건이 세션이 끝난 뒤 계속 참이 되기 때문이다.
4. **예산 지표(탐색 10분당)는 이 위험을 가린다.** 이 지표는 exploring 중 개입만 센다. 그래서 관측·Oracle 값이 거의 같다(1.16 대 1.18). 운영 판단에는 종료 후·away 개입을 함께 보는 지표가 필요하다.
5. **매개변수 이동에서 나빠졌다**(seed 1, rule). F1 0.25→0.23 · 0.21→0.17 · 0.24→0.22, 탐색 10분당 불필요 1.16→1.85 · 2.27→3.19 · 2.20→3.02.
6. **cooldown 30초는 불필요 개입을 약 2배로 늘렸다**(1.16→2.12). 발견율은 거의 그대로였다(0.40→0.40).
7. **generator_reference 와 관측 가능 규칙의 격차가 크다**(F1 약 0.65 대 0.23). 유형을 아는 이점이 크다는 뜻이다. 관측 가능 모델이 이 격차를 좁히면, 그것은 생성 규칙을 다시 배운 결과일 수 있다.
8. **첫 개입까지 시간이 30초에 몰린다.** tick 간격이 30초라 생기는 하한이다. 막힘 에피소드는 거의 모두(368 중 367) 판단 시점을 하나 이상 포함한다.
